Bitset — tysiące bitów w jednej zmiennej

W poprzedniej lekcji liczba int była rzędem 32 żarówek, a long long — rzędem 64. To wystarcza, żeby zapamiętać, które z kilkudziesięciu rzeczy zostały wybrane. Ale co, jeśli rzeczy jest tysiąc albo dziesięć milionów? Do tego służy bitset: jedna zmienna, w której mieści się dowolnie długi rząd zer i jedynek. Zajmuje osiem razy mniej pamięci niż tablica bool, liczy jedynki jednym poleceniem, a działania & | ^ ~ << >> wykonuje na całym ciągu naraz — po 64 bity w jednym kroku. Poznasz go bardzo powoli, od pierwszego bitu, a potem użyjesz w trzech słynnych pomysłach: sicie Eratostenesa, które znajduje wszystkie liczby pierwsze do stu milionów, sumach podzbiorów, które zamiast pętli robią jedno przesunięcie, i przyspieszaniu algorytmów na grafach. Po każdej części czekają ćwiczenia ze sprawdzarką.

01 — Pierwszy bitset

Rząd przełączników w jednej zmiennej

W lekcji Liczby dwójkowe nauczyłeś się patrzeć na liczbę jak na rząd żarówek: int to 32 żarówki, long long — 64. Każda żarówka to jedna informacja „tak / nie”: czy element został wybrany, czy uczeń był obecny, czy lampka świeci. Jedna liczba zapamiętywała w ten sposób cały zestaw takich informacji, a operatory &, | i ^ działały na wszystkich żarówkach naraz.

Kłopot w tym, że 64 żarówki to mało. Często trzeba zapamiętać „tak / nie” dla tysiąca rzeczy, dla miliona albo dla stu milionów — na przykład: „czy liczba x pojawiła się już w danych?” albo „czy liczba x jest pierwsza?”. Do tego służy bitset — zmienna, która jest po prostu bardzo długim rzędem bitów. Ty wybierasz, ile ma ich być.

Po co nowe narzędzie, skoro jest tablica bool?

Na pytanie „czy liczba x już była?” umiesz już odpowiadać tablicą: bool byla[1000001]; i potem byla[x] = true;. To działa, ale jest rozrzutne. Komputer nie potrafi zaadresować pojedynczego bitu pamięci, więc każdy bool zajmuje cały bajt — osiem bitów — choć potrzebny jest tylko jeden. Siedem bitów z każdych ośmiu się marnuje.

Bitset upycha bity ciasno, jeden obok drugiego, i sam wyciąga ten, o który prosisz. Sprawdziliśmy to na kompilatorze, którego używa sprawdzarka:

Oszczędność pamięci to dopiero początek. Bitset ma też gotowe polecenia — na przykład policzenie wszystkich jedynek jednym wywołaniem — i potrafi wykonywać działania &, |, ^, ~, <<, >> na całym ciągu bitów naraz, kilkadziesiąt razy szybciej niż pętla po tablicy. Ale po kolei — najpierw nauczmy się go tworzyć i czytać.

Pierwszy bitset

pierwszy_bitset.cpp
int main() {
    bitset<8> b;
    cout << b << "\n";
    b[3] = 1;
    b[0] = 1;
    cout << b << "\n";
    cout << b[3] << " " << b[1] << " " << b.size() << "\n";
    return 0;
}
▶ Wyjście

bitset<8> b; tworzy bitset z ośmioma bitami. Liczba w ostrych nawiasach to rozmiar — tak jak w vector<int> w nawiasach stał typ elementów. Bitset potrzebuje biblioteki <bitset>, ale <bits/stdc++.h> już ją zawiera.

Na start wszystkie bity są zerami — w przeciwieństwie do zwykłej zmiennej int w main, w której siedzą śmieci. b[3] = 1; zapala bit numer 3, a b[3] odczytuje go: daje 1 albo 0. b.size() to liczba bitów.

Najciekawsze jest cout << b: wypisuje od razu cały bitset, wszystkie osiem cyfr. Spójrz, gdzie wylądowały jedynki — o tym za chwilę.

bitset<8> b po zapaleniu bitów 0 i 3. Pod każdą kratką numer bitu. Numery rosną od prawej do lewej — dokładnie tak, jak w liczbach dwójkowych.

Bity numerujemy od prawej

W wypisanym bitsecie 00001001 bit numer 0 jest na samym końcu, a bit numer 7 — na początku. To ta sama umowa co w lekcji Liczby dwójkowe: najmłodszy bit stoi z prawej strony. Dzięki temu bitset wypisuje się dokładnie jak liczba dwójkowa — 00001001 to 2³ + 2⁰ = 9 — a bit numer k ma wagę 2ᵏ.

Przy pisaniu i czytaniu przez b[i] numeracja jest za to zwyczajna: b[0] to bit 0, b[1] to bit 1. Myli się tylko kierunek wypisywania: cout << b pisze od najwyższego numeru do najniższego. Jeśli chcesz zobaczyć bity w kolejności numerów, napisz zwykłą pętlę — porównaj oba wiersze:

dwa_kierunki.cpp
int main() {
    bitset<10> b;
    b[0] = 1;
    b[1] = 1;
    b[7] = 1;
    for (int i = 0; i < 10; i++) cout << b[i];
    cout << "\n";
    cout << b << "\n";
    return 0;
}
▶ Wyjście

Pierwszy wiersz wypisała pętla: najpierw b[0], potem b[1], …, na końcu b[9]. Bity 0 i 1 są na początku, bit 7 — na ósmym miejscu.

Drugi wiersz to cout << b — ten sam bitset czytany od końca. Zapamiętaj: cout pisze od bitu N − 1, pętla od bitu 0. W zadaniach uważnie czytaj, której kolejności chce treść.

Rozmiar musi być stałą

Jest jedno ważne ograniczenie: rozmiar bitsetu trzeba znać już w chwili pisania programu. Nie da się wczytać n i zrobić bitsetu o n bitach — kompilator musi z góry wiedzieć, ile pamięci zarezerwować:

rozmiar_z_cin.cpp
int main() {
    int n;
    cin >> n;
    bitset<n> b;
    cout << b;
    return 0;
}

Rozmiarem może być liczba wpisana wprost albo stała — zmienna z const, której wartość jest znana od początku i nigdy się nie zmienia. Wolno też liczyć na stałych: N + 1 to też stała.

Co więc robić, gdy w zadaniu n jest dopiero w danych? To samo, co z tablicami: zrób bitset z zapasem, tak duży, jak największe n z ograniczeń. Jeśli liczby są od 0 do 1 000 000, potrzebujesz bitów o numerach 0, 1, …, 1 000 000 — czyli bitset<1000001>, o jeden więcej niż największa liczba.

Zaznaczanie liczb

Najczęstsze użycie bitsetu: zaznaczasz, które liczby się pojawiły. Bit numer x zapalasz, gdy wczytasz liczbę x. Powtórki niczego nie psują — zapalenie bitu, który już świeci, nic nie zmienia. A gdy potem przejdziesz pętlą po numerach od najmniejszego, wypiszesz różne liczby od razu rosnąco, bez żadnego sortowania — to ten sam pomysł co sortowanie przez zliczanie z lekcji Sortowanie.

zaznaczanie.cpp
int main() {
    int n;
    cin >> n;
    bitset<100> byla;
    for (int i = 0; i < n; i++) {
        int x;
        cin >> x;
        byla[x] = 1;
    }
    for (int x = 0; x < 100; x++) {
        if (byla[x]) cout << x << " ";
    }
    cout << "\n";
    return 0;
}
▶ Wejście
7 42 7 42 99 0 7 13
▶ Wyjście

Liczby są od 0 do 99, więc wystarcza bitset<100>. Liczby 42 i 7 przyszły dwa razy, ale każda zapaliła ten sam bit.

W drugiej pętli warunek if (byla[x]) działa tak samo jak przy tablicy bool: jedynka to prawda, zero — fałsz. Pętla idzie po wszystkich stu numerach, ale wypisuje tylko te, które świecą: 0, 7, 13, 42 i 99.

Tu liczy się kolejność dwóch linijek. Najpierw pytamy byla[x] — bit opowiada o liczbach, które przyszły wcześniej. Dopiero potem zapalamy bit, żeby następne liczby wiedziały, że x już był.

Gdybyś zamienił te linijki miejscami, każda liczba „byłaby już wcześniej” — bo sam przed chwilą zapaliłeś jej bit. Taki sam schemat posłuży do liczenia różnych liczb: if (!byla[x]) { byla[x] = 1; ile++; } — licznik rośnie tylko przy pierwszym spotkaniu.

Duże bitsety — przed main

Zmienne zadeklarowane wewnątrz main trafiają do niewielkiego obszaru pamięci zwanego stosem — na sprawdzarce ma on 8 MB. Pamiętasz z lekcji Tablice, że wielka tablica w main wywraca program? Z bitsetem jest tak samo. Sprawdziliśmy: bitset na 50 milionów bitów (6,25 MB) w main jeszcze działa, ale na 100 milionów (12,5 MB) — program się wysypuje:

za_duzy_w_main.cpp
int main() {
    bitset<100000000> b;   // 12,5 MB na stosie
    b[12345] = 1;
    cout << b[12345] << "\n";
    return 0;
}
▶ Wyjście programu

duzy_przed_main.cpp
bitset<100000000> b;   // przed main: OK
int main() {
    b[99999999] = 1;
    b[12345] = 1;
    cout << b[99999999] << b[12345] << b[7] << "\n";
    return 0;

▶ Wyjście
110

Zasada jest prosta: bitset większy niż kilka milionów bitów deklaruj przed main, jako zmienną globalną. Globalny bitset też ma na start same zera. Sprawdzarka ma 256 MB pamięci, więc globalny bitset na sto milionów bitów (12,5 MB) mieści się z dużym zapasem.

Zapamiętaj bitset<N> b; to N bitów o numerach od 0 do N − 1, na start same zera. Zapis i odczyt: b[i] = 1; i if (b[i]). cout << b wypisuje wszystkie bity od numeru N − 1 do 0 — bit 0 jest na końcu, jak w liczbie dwójkowej. N musi być stałą (liczba albo const int), więc deklaruj bitset z zapasem: dla liczb do M — bitset<M + 1>. Duże bitsety stawiaj przed main. Bitset zajmuje 8 razy mniej pamięci niż tablica bool.

02 — Wbudowane polecenia

set, reset, flip, count i reszta

Na razie umiesz bity zapalać (b[i] = 1) i czytać (b[i]). Bitset ma jeszcze kilka gotowych poleceń — wywołuje się je przez kropkę, tak jak s.size() przy napisach albo v.push_back(x) przy vectorze. Jest ich niewiele i wszystkie mają proste angielskie nazwy: set — ustaw, reset — wyzeruj, flip — przewróć, count — policz, any — jakikolwiek, none — żaden, all — wszystkie, test — sprawdź.

Jeden bit: set, reset, flip

jeden_bit.cpp
int main() {
    bitset<8> b;
    b.set(1);
    b.set(4);
    b.set(6);
    cout << b << "\n";
    b.reset(4);
    b.flip(0);
    cout << b << "\n";
    b.flip(0);
    b.set(7, 1);
    b.set(1, 0);
    cout << b << "\n";
    return 0;
}
▶ Wyjście
01010010 01000011 11000000

b.set(i) zapala bit i — to samo co b[i] = 1. b.reset(i) gasi bit i, czyli b[i] = 0. b.flip(i) przełącza bit: zero zamienia na jedynkę, a jedynkę na zero — jak włącznik światła. Dwa przełączenia z rzędu wracają do stanu sprzed.

Prześledź: po trzech set świecą bity 1, 4 i 6. Potem bit 4 gaśnie, a bit 0 się zapala (był zgaszony). Na końcu bit 0 znowu gaśnie, b.set(7, 1) ustawia bit 7 na 1, a b.set(1, 0) — bit 1 na 0. Wersja z dwoma argumentami ustawia bit na podaną wartość.

Bitset jako zbiór liczb

        

            
Najważniejszy sposób patrzenia na bitset: to zbiór liczb od 0 do N − 1. Liczba x należy do zbioru, gdy świeci bit numer x. Bitset 00101100 to zbiór {2, 3, 5}. Liczba pierwsza to liczba większa od 1, która dzieli się tylko przez 1 i przez samą siebie: 2, 3, 5, 7, 11, 13, … Liczba 1 nie jest pierwsza, a 9 = 3 · 3 nie jest, bo ma dodatkowy dzielnik 3. bool czyPierwsza(int x) {
    if (x < 2) return false;
    for (int d = 2; d * d <= x; d++) {
        if (x % d == 0) return false;
    }
    return true;
}
int main() {
    int ile = 0;
    for (int x = 1; x <= 100; x++) {
        if (czyPierwsza(x)) ile++;
    }
    cout << ile << "\n";
    return 0;
}

Ponad dwa tysiące lat temu grecki uczony Eratostenes wymyślił sposób, który zamiast sprawdzać liczby po kolei, skreśla wszystkie złożone naraz. Ten sam pomysł działa dzisiaj w komputerach — z bitsetem jako kartką.

Wypisz na kartce liczby od 2 do N. Teraz powtarzaj:

            
    
                
  1. Weź najmniejszą liczbę, która nie jest skreślona i jeszcze jej nie brałeś. Ona jest pierwsza — gdyby miała mniejszy dzielnik, zostałaby skreślona wcześniej.
    2. 
                
  2. Skreśl wszystkie jej wielokrotności: dla 2 to 4, 6, 8, 10, …; dla 3 to 6, 9, 12, …. Wielokrotności na pewno są złożone, bo dzielą się przez tę liczbę.
    3. 
            

            
Na początku bierzesz 2 i skreślasz liczby parzyste. Najmniejsza nieskreślona to 3 — skreślasz jej wielokrotności. Czwórka jest już skreślona, więc następna jest 5, potem 7… Liczby, które na końcu zostaną nieskreślone, to dokładnie liczby pierwsze. To jest sito: liczby złożone „przelatują przez sito”, zostają pierwsze. Prześledź to w ramce — każdy krok bierze kolejną liczbę pierwszą i skreśla jej wielokrotności.

        if (!zlozona[i]) {
            cout << i << " ";
            ile++;
        }
    }
    cout << "\n" << ile << "\n";
    return 0;
}

Kartką jest bitset zlozona: bit x zapalony znaczy „x jest skreślona, nie jest pierwsza”. Ma rozmiar N + 1, bo potrzebujemy bitu numer N. Liczby 0 i 1 nie są pierwsze, więc skreślamy je od razu.

                    
Zewnętrzna pętla przechodzi kolejne liczby i. Jeśli i nie jest skreślona — jest pierwsza — i wewnętrzna pętla skreśla jej wielokrotności, idąc co i: j += i. Na końcu nieskreślone bity od 2 do N to liczby pierwsze.

                    
Dwa szczegóły różnią ten kod od opisu na kartce: wewnętrzna pętla zaczyna od i * i, a zewnętrzna kończy się, gdy i * i > N. Dlaczego wolno tak zrobić — poniżej.

                

            

        


        
Dlaczego od i · i i tylko do pierwiastka

        

            
Weź i = 7. Jego mniejsze wielokrotności to 14, 21, 28, 35 i 42. Każda z nich ma dzielnik mniejszy niż 7 (14 = 2 · 7, 21 = 3 · 7, 35 = 5 · 7), więc skreśliliśmy ją już wcześniej — przy dwójce, trójce albo piątce. Pierwsza wielokrotność 7, której nikt jeszcze nie skreślił, to 7 · 7 = 49. Ogólnie: wszystkie wielokrotności i mniejsze od i · i są już skreślone, więc wewnętrzna pętla może zacząć od i · i.

            
Stąd od razu druga obserwacja: gdy i · i > N, wewnętrzna pętla nie skreśli już niczego — zaczynałaby za końcem kartki. Zewnętrzną pętlę można więc skończyć przy pierwiastku z N. Liczby pierwsze większe od pierwiastka i tak zostaną nieskreślone. Dla N = 10⁶ oszczędność jest wyraźna: wersja „od 2 · i, aż do N” wykonuje 2 775 210 skreśleń, a wersja „od i · i” — 2 122 048. Zwróć też uwagę na if (!zlozona[i]): skreślamy tylko wielokrotności liczb pierwszych. Bez tego warunku (gdybyśmy skreślali też wielokrotności 4, 6, 8, …) skreśleń byłoby 5 985 517.

Mniej pamięci to często także szybszy program.

        07 — Sumy podzbiorów
        
Jakie sumy da się ułożyć — przesunięcie zamiast pętli

        

            
W portfelu masz monety 3 zł, 5 zł i 4 zł. Jakie kwoty możesz zapłacić bez reszty, jeśli każdą monetę dajesz najwyżej raz? To jedno z najczęstszych pytań w zadaniach olimpijskich — w różnych przebraniach: odważniki na wadze, prezenty do podziału, ciężary w plecaku. W tej części zobaczysz, jak bitset odpowiada na nie jednym zapisem S |= S << x.

        


        
Najpierw na piechotę

        

            
Z lekcji Liczby dwójkowe umiesz przejrzeć wszystkie wybory monet maskami: trzy monety to 2³ = 8 wyborów. Dają one sumy 0 (nic nie dajesz), 3, 5, 4, 3 + 5 = 8, 3 + 4 = 7, 5 + 4 = 9 i 3 + 5 + 4 = 12. Działa — ale przy 100 monetach wyborów jest 2¹⁰⁰, czyli więcej, niż komputer zdąży sprawdzić do końca świata. Potrzebny jest inny pomysł.

        


        
Zbiór sum rośnie z każdą monetą

        

            
Zamiast wszystkich wyborów pamiętajmy tylko zbiór kwot, które da się już ułożyć. Na początku, bez żadnej monety, umiemy zapłacić tylko 0: S = {0}. Teraz dochodzi moneta x. Każdą kwotę, którą umieliśmy ułożyć, możemy zapłacić bez tej monety albo z nią — wtedy kwota rośnie o x. Nowy zbiór to stare sumy plus stare sumy powiększone o x:

Wyszło dokładnie to samo co przy maskach, ale bez przeglądania wyborów. A teraz najważniejsze: w części 5 widziałeś, że przesunięcie bitsetu S << x to zbiór, w którym do każdej liczby dodano x. „Stare sumy + moneta” to więc S << x, a „stare sumy razem z nowymi” to OR: S | (S << x).     cout << "\n";
    return 0;

Dlaczego moneta nie liczy się dwa razy?

        

            
W zapisie S |= S << x przesunięcie liczy się ze starego S — z kwot ułożonych bez monety x — i dopiero potem dokładamy je do S. Każda nowa kwota używa więc monety x dokładnie raz. Liczby ujemne? Przesuń zero na środek

        

            
Bity mają tylko numery od zera w górę, więc w bitsecie nie zapiszesz sumy ujemnej. Gdy w zadaniu mogą się pojawić — na przykład odważniki kładzie się na obie szalki wagi, więc jeden odważnik może dodać albo odjąć swoją masę — przesuń wszystko o stałą T. Sumę d trzymaj w bicie T + d. Na start zapalasz bit T (suma 0), a odważnik w daje S | (S << w) | (S >> w): zostaje, dodaje się albo odejmuje. T wystarczy równe sumie wszystkich odważników — wtedy żadna suma nie zejdzie poniżej bitu 0.

        


        

            Zapamiętaj
            Zbiór kwot, które da się ułożyć z elementów (każdy najwyżej raz), to bitset S: na start S[0] = 1, a dla każdego elementu S |= S << x;. Bitset musi mieć co najmniej tyle bitów, ile wynosi suma wszystkich elementów + 1. S[k] — czy da się ułożyć k, S.count() - 1 — ile jest różnych sum dodatnich, największe s ≤ razem / 2 z S[s] — najlepszy podział na dwie grupy. Gdy z każdej grupy bierzesz dokładnie jedno: N |= S << v dla każdej możliwości, potem S = N. Sumy ujemne trzymaj w bicie T + d. Pętla na tablicy bool musi iść od góry w dół.

Co jest w środku bitsetu

        

            
Procesor nie umie działać na pojedynczych bitach — pracuje na całych słowach po 64 bity, takich jak jeden long long. Jedno a & b na dwóch liczbach long long to jeden krok procesora, który od razu wykonuje AND na 64 parach bitów.

            
Bitset jest w środku po prostu tablicą takich słów. bitset<1000> to 16 słów po 64 bity (1024 bity, z czego 24 nie są używane). Widać to w rozmiarach, które zmierzyliśmy:

Baza zadań: bitset w praktyce

        

            
Znasz już cały warsztat: bitset i numery bitów od prawej, polecenia set, reset, flip, count, any, none i all, zamianę z liczby i z napisu i z powrotem, działania na zbiorach, przesunięcia, sito Eratostenesa, sumy podzbiorów i tablice bitsetów w grafach. Czas na zadania, w których to wszystko się łączy.

            
Zadania są ułożone od najłatwiejszego do najtrudniejszego: najpierw bitset w prostych przebraniach (skarpetki, sudoku, bingo, kalendarz urlopów, kod kreskowy), potem zbiory, sita i przesunięcia w trudniejszych zadaniach (ankiety, alergie, linijka, plakaty bez pętli po polach, sito na przedziale do 10¹²), a na końcu poważne algorytmy — dokładnie k monet, wyszukiwanie wzorca z dżokerami, automat komórkowy, skoczek na wielkiej szachownicy — oraz wielki finał: wyszukiwarka dokumentów z AND, OR, NOT i nawiasami.             Jak rozwiązywać zadania z bitsetem
            1) Zapytaj, czy w zadaniu są długie ciągi informacji „tak / nie” — obecności, zbiory, możliwe sumy, odwiedzone pola. To kandydaci na bitset. 2) Ustal rozmiar z ograniczeń i dodaj zapas: liczby do M — bitset<M + 1>, a przy dużych rozmiarach deklaruj przed main. 3) Szukaj działań na całym ciągu: część wspólna to &, „dodaj x do każdego” to <<, „ile” to count(). 4) Gdy używasz tylko n z N bitów, pilnuj, żeby ~, << i all() nie popsuły wyniku bitami spoza n — przytnij maską. 5) Policz, czy zdążysz: działanie na bitsecie to N / 64 kroków. 6) Zanim wyślesz: zero, puste zbiory, największe dane z treści, nawiasy przy operatorach i kolejność bitów w napisie.

        10 — Częste błędy
        
Częste błędy i dobre praktyki

        

            

                
↔️

                
Kolejność wypisywania

                
cout << b pisze od bitu N − 1 do bitu 0 — bit 0 jest na końcu. Pętla for (i = 0; i < N; i++) cout << b[i]; pisze w odwrotnej kolejności. Sprawdź, której chce treść.

            

            

                
📏

                
Rozmiar to stała

                
bitset<n> z n wczytanym z wejścia się nie kompiluje („not usable in a constant expression”). Deklaruj z zapasem: dla liczb do M — bitset<M + 1>.

            

            

                
🌍

                
Duże bitsety przed main

                
bitset<100000000> w main wysypał program (SIGSEGV), a przed main działał bez problemu. Duże bitsety i tablice bitsetów deklaruj globalnie.

            

            

                
✅

                
all() i n mniejsze od N

                
all() patrzy na wszystkie N bitów. Gdy używasz tylko n z nich, pisz (int)b.count() == n — rzutowanie ucisza ostrzeżenie o porównaniu liczby bez znaku z int.

            

            

                
🎭

                
~ i << wychodzą poza n

                
~a zapala też bity od n do N − 1, a b << 1 wynosi jedynki za pozycję n − 1. Przytnij wynik maską n jedynek: maska.set(); maska >>= N - n;.

            

            

                
🙈

                
[] nie sprawdza numeru

                
b[20] = 1 w bitsecie o 16 bitach popsuło pamięć po cichu: cout pokazał zera, a count() — 1. test(i) i set(i) zatrzymują program z komunikatem o złym numerze.

            

            

                
🔤

                
Napis czytany od końca

                
W bitset<8>(s) ostatni znak napisu to bit 0. Z za długiego napisu zostaje N pierwszych znaków, a z liczby — N ostatnich bitów. Inny znak niż 0 i 1 (nawet spacja) zatrzymuje program.

            

            

                
0️⃣

                
Zero i npos

                
Przy usuwaniu zer z przodu to_string().find('1') dla zera zwraca string::npos (18446744073709551615). Sprawdź to przed substr i wypisz wtedy „0”.

            

            

                
🧮

                
Nawiasy przy działaniach

                
cout << a & b się nie kompiluje, a a & b.count() to coś innego niż (a & b).count(). Zawsze bierz działanie w nawias, zanim je wypiszesz albo policzysz.

            

            

                
🚫

                
Bitset to nie liczba

                
Nie ma a + b, a < b, b[i]++ ani if (a). Bitsetu nie da się posortować ani wstawić do map jako klucza — użyj to_ulong() albo to_string(). Różne rozmiary się nie łączą.

            

            

                
🧺

                
Sito: N + 1 i start od i · i

                
Bitset sita ma N + 1 bitów, bo potrzebny jest bit N. Pamiętaj o z[0] = z[1] = 1. Skreślaj od i * i i tylko dla nieskreślonych i — przy N blisko 2 · 10⁹ licz w long long.

            

            

                
💰

                
Sumy: rozmiar i zero

                
Bitset sum musi pomieścić sumę wszystkich elementów. Zacznij od S[0] = 1, a odpowiadając „ile sum dodatnich”, odejmij zero. W tablicy bool pętla idzie od góry w dół.
