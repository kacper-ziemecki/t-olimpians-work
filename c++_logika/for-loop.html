Pętla for w C++

Pętlę while już znasz. Teraz poznasz jej najczęściej używaną siostrę: pętlę for, w której start, warunek i zmiana licznika stoją razem w jednej linijce. Po każdej części czekają ćwiczenia ze sprawdzarką.

00 — Zanim zaczniesz

Co już umiesz i czego się nauczysz

Ta lekcja zakłada, że przerobiłeś lekcje Typy zmiennych, Input / Output, If / Else i — przede wszystkim — While loop. Z lekcji o while pamiętasz, że każda pętla ma trzy elementy: start (zmienna z wartością początkową przed pętlą), warunek (kiedy pętla ma się jeszcze kręcić) i zmianę (coś w ciele, co przybliża warunek do fałszu). Znasz też liczniki, sumy, rekordy, break, continue i pętlę w pętli.

Pętla for nie umie niczego, czego nie umiałby while. Ale zbiera te trzy elementy w jednym miejscu, na samej górze pętli. Dzięki temu jednym spojrzeniem widać, skąd licznik startuje, dokąd dojdzie i jak szybko — a to sprawia, że pętle z licznikiem pisze się szybciej i myli rzadziej. W programach olimpijskich for pojawia się kilka razy częściej niż while.

Uczymy się tak samo jak poprzednio: przepisuj przykłady do swojego edytora i uruchamiaj je, przy pytaniach „Co wypisze program?” najpierw śledź program w głowie albo na kartce, a dopiero potem sprawdzaj odpowiedź, i po każdej części rób ćwiczenia w sprawdzarce. Nie przerabiaj wszystkiego za jednym razem — rób przerwy po kolejnych częściach.

01 — Pierwsza pętla for

for — while w jednej linijce

Przypomnij sobie najprostszą pętlę z lekcji o while: wypisanie liczb od 1 do 5. Trzy elementy pętli są tam porozrzucane po trzech różnych miejscach: start nad pętlą, warunek w nawiasie, a zmiana — na samym dole ciała. W krótkim programie to nie problem, ale gdy ciało pętli ma dwadzieścia linijek, zmiana ginie gdzieś na dole i łatwo o niej zapomnieć.

Pętla for (po angielsku „dla”, czytaj: „for”) robi dokładnie to samo, tylko wszystkie trzy elementy zapisuje w jednym nawiasie, oddzielone średnikami. Porównaj:

while.cpp
int i = 1;              // start
while (i <= 5) {        // warunek
    cout << i << " ";
    i++;                // zmiana
}
▶ Wyjście
1 2 3 4 5
for.cpp
// start; warunek; zmiana — wszystko w jednym miejscu
for (int i = 1; i <= 5; i++) {
    cout << i << " ";
}
▶ Wyjście
1 2 3 4 5

Oba programy wypisują to samo i działają tak samo. Wersja z for jest krótsza, ale ważniejsze jest co innego: z samej pierwszej linijki od razu wiesz, że licznik i zacznie od 1, skończy na 5 i będzie rósł o 1. Nie trzeba szukać zmiany na dole ciała.

Przepisywanie while na for

Każdą pętlę while z licznikiem przepiszesz na for w trzech ruchach: start znad pętli przenosisz na początek nawiasu, warunek zostaje w środku, a zmianę z dołu ciała przenosisz na koniec nawiasu. Ciało pętli robi się o jedną linijkę krótsze.

co_trzy_while.cpp
int n;
cin >> n;
int i = 2;
while (i <= n) {
    cout << i << " ";
    i += 3;
}
co_trzy_for.cpp
int n;
cin >> n;
for (int i = 2; i <= n; i += 3) {
    cout << i << " ";
}

Ten drugi ma w C++ swoją „kanoniczną” postać, którą zobaczysz w tysiącach programów: for (int i = 0; i < n; i++).

Suma w pętli for — także z ułamkami

Akumulatory z lekcji o while działają w for bez żadnych zmian: zmienna przed pętlą, dokładanie w ciele, wypisanie po pętli. Policzmy sumę 1 + 1/2 + 1/3 + … + 1/n. Tu czai się pułapka z lekcji o typach:

#include <iostream>

    for (int i = 1; i <= 4; i++) {
        suma += 1 / i;      // dzielenie całkowite!
    }
    cout << fixed << setprecision(4) << suma << "\n";
    return 0;
}

02 — Zakresy i kroki

Skąd, dokąd i co ile

Nagłówek pętli for to w praktyce opis zakresu: skąd licznik startuje, do jakiej wartości dojdzie i o ile zmienia się w każdym kroku. Kto umie szybko czytać i pisać takie nagłówki, ten pisze pętle bez błędów. Oto najczęstsze z nich — z wartościami licznika i liczbą obrotów:

nagłówekwartości licznikaobrotów
for (int i = 0; i < n; i++)0, 1, …, n − 1n
for (int i = 1; i <= n; i++)1, 2, …, nn
for (int i = n; i >= 1; i--)n, n − 1, …, 1n
for (int i = n - 1; i >= 0; i--)n − 1, …, 1, 0n
for (int i = a; i <= b; i++)a, a + 1, …, bb − a + 1
for (int i = a; i <= b; i += k)a, a + k, a + 2k, …(b − a) / k + 1
for (int p = 1; p <= n; p *= 2)1, 2, 4, 8, …ok. log₂ n + 1

Wzory w ostatniej kolumnie przydają się częściej, niż myślisz: pozwalają sprawdzić program bez uruchamiania go, a w części 8 — policzyć, czy zdąży się wykonać. Zatrzymajmy się przy nich na chwilę.

Ile liczb jest od a do b?

Ile liczb całkowitych jest od 3 do 7? Odejmowanie daje 7 − 3 = 4, ale liczb jest pięć: 3, 4, 5, 6, 7. Odejmowanie liczy „odstępy” między liczbami, a liczb jest zawsze o jedną więcej niż odstępów — tak samo jak słupków w płocie jest o jeden więcej niż przęseł. Dlatego od a do b jest b − a + 1 liczb.

Ze skokiem co k jest podobnie: od a do b mieści się (b − a) / k pełnych skoków (dzielenie całkowite!), a liczb jest o jedną więcej. Sprawdźmy na przykładzie: od 1 do 20 co 4.

ile_obrotow.cpp
int a = 1, b = 20, k = 4;
int ile = 0;
for (int i = a; i <= b; i += k) {
    cout << i << " ";
    ile++;
}
cout << "\nobrotow: " << ile;
cout << ", ze wzoru: " << (b - a) / k + 1 << "\n";
▶ Wyjście
1 5 9 13 17 obrotow: 5, ze wzoru: 5

(20 − 1) / 4 = 19 / 4 = 4 (dzielenie całkowite) — tyle jest pełnych skoków. Plus pierwszy obrót dla i = 1: razem 5. Następna wartość, 21, nie spełnia warunku i <= 20.

Wzór działa tylko wtedy, gdy a ≤ b. Gdy a > b, warunek jest fałszywy od razu i pętla wykona się zero razy — taki zakres nazywamy pustym.

Licznik żyje tylko w pętli

Zmienna utworzona w nawiasie for — int i = 1 — istnieje tylko w tej pętli. Za klamrą zamykającą pętlę już jej nie ma. To wygodne (licznik nie zaśmieca reszty programu, a w następnej pętli możesz znowu napisać int i), ale bywa zaskakujące:

zasieg_blad.cpp
for (int i = 1; i <= 5; i++) {
    cout << i << " ";
}
cout << i;    // błąd: i już nie istnieje
▶ Kompilator
error: 'i' was not declared in this scope
zasieg_dobrze.cpp
int i;                 // licznik przed pętlą
for (i = 1; i * i <= 50; i++) {
    // nic nie robimy — tylko szukamy
}
cout << "pierwszy kwadrat ponad 50: " << i * i << "\n";
▶ Wyjście
pierwszy kwadrat ponad 50: 64

Komunikat kompilatora brzmi: 'i' was not declared in this scope — „i nie zostało zadeklarowane w tym zasięgu”. Jeśli wartość licznika jest potrzebna po pętli, utwórz zmienną przed pętlą, a w nawiasie tylko nadaj jej wartość startową (i = 1, bez int). Tak jak w prawym przykładzie, gdzie po pętli i wynosi 8 — pierwsza liczba, której kwadrat przekroczył 50.

Dwa liczniki w jednym nawiasie

W części startowej i w części zmiany możesz zmieścić więcej niż jedną instrukcję — oddzielasz je przecinkami. Przydaje się, gdy dwa liczniki idą razem, na przykład jeden w górę, a drugi w dół:

dwa_liczniki.cpp
for (int i = 1, j = 10; i < j; i++, j -= 2) {
    cout << i << " " << j << "\n";
}
▶ Wyjście
1 10 2 8 3 6

Kolejne pary (i, j): (1, 10), (2, 8), (3, 6), (4, 4). Przy ostatniej warunek 4 < 4 jest fałszywy. Uwaga: przecinki stoją tylko w starcie i w zmianie. Warunek jest jeden — jeśli chcesz sprawdzać dwie rzeczy, łączysz je przez && albo ||.

Nie zmieniaj licznika w ciele

Kompilator pozwala zmieniać licznik również w ciele pętli — ale wtedy nagłówek przestaje mówić prawdę.         gdzieMaks = i;

07 — Wszystkie możliwości

Sprawdź wszystkie możliwości

Wiele zagadek, które na lekcji matematyki rozwiązuje się sprytnym rachunkiem, komputer rozwiązuje… siłą. Skoro potrafi sprawdzić miliony przypadków w ułamku sekundy, można po prostu wypróbować każdą możliwą odpowiedź i zostawić te, które pasują. Ta metoda nazywa się przeszukiwaniem zupełnym (po angielsku brute force, „brutalna siła”) i jest pierwszym pomysłem, od którego warto zacząć prawie każde zadanie.

Przepis zawsze jest ten sam: 1) ustal, czego szukasz i jakie wartości może to mieć, 2) przejdź po wszystkich tych wartościach pętlą (albo kilkoma pętlami), 3) dla każdej sprawdź warunek z treści.

Druga wartość wynika z pierwszej

Długopis kosztuje 2 zł, zeszyt 3 zł. Na ile sposobów możesz wydać dokładnie 12 zł? Przeszukiwanie po liczbie długopisów i liczbie zeszytów to dwie pętle. Ale gdy wiadomo, ile długopisów kupiłeś, na zeszyty zostaje konkretna kwota — i albo dzieli się ona przez cenę zeszytu, albo nie:

Bez powtórzeń: a ≤ b ≤ c

Ile jest trójkątów o bokach całkowitych i obwodzie 12? Trójkąt o bokach 3, 4, 5 to ten sam trójkąt co 5, 3, 4 — nie chcemy go liczyć sześć razy. Rozwiązanie: szukamy tylko boków ułożonych rosnąco, a ≤ b ≤ c. Pętla po b startuje od a, a trzeci bok wynika z obwodu. int p = 12, ile = 0;
for (int a = 1; a <= p; a++) {
    for (int b = a; a + b + b <= p; b++) {   // c >= b
        int c = p - a - b;
        if (a + b > c) {
            cout << a << " " << b << " " << c << "\n";
            ile++;
        }
    }
}
cout << "trojkatow: " << ile << "\n";

08 — Szybkość pętli

Jak szybka jest pętla — czy program zdąży?

Każde zadanie w sprawdzarce ma limit czasu, zwykle 1 sekundę na test. Na olimpiadzie jest tak samo. Program, który liczy poprawnie, ale za wolno, dostaje zero punktów za dany test — sprawdzarka po prostu przerywa go po upływie limitu. Jedna pętla zamiast dwóch

Ostatni, najważniejszy trik. Ile jest par liczb a < b z przedziału od 1 do n, których suma wynosi s? Przeszukiwanie wszystkich par to n · (n − 1) / 2 obrotów — dla n = 10⁷ to 5 · 10¹³, kilka dni liczenia. Ale gdy znamy a, to b nie jest dowolne: musi być równe s − a. 09 — Baza zadań

Baza zadań: pętla for w praktyce

Znasz już wszystko, co potrzebne: budowę pętli for, zakresy i liczbę obrotów, wczytywanie danych, break i continue, napisy i for (char c : s), pętle zagnieżdżone, przeszukiwanie wszystkich możliwości i szacowanie szybkości. Czas na zadania, które łączą kilka z tych rzeczy naraz. Są ułożone od najłatwiejszego do najtrudniejszego: najpierw rozgrzewka z jedną pętlą, potem zadania średnie — serie, rysunki z warunkiem, liczenie liter, hetman i zegar — a na końcu trudne, z trójkami pitagorejskimi, hipotezą Goldbacha, kalendarzem i wielkim finałem.

Przy każdym zadaniu widać, jakich zagadnień używa — także tych z poprzednich lekcji, jak setw, setprecision, long long czy pętla while. Jeśli coś brzmi obco, wróć do odpowiedniej części — mapa lekcji jest na górze strony.

Jak rozwiązywać zadania z pętlą for 1) Ustal, po czym idzie pętla: po liczbach od a do b, po n danych, po znakach napisu, po wierszach rysunku? To wyznacza nagłówek. 2) Zapisz pierwszą i ostatnią wartość licznika — i sprawdź, czy nie ma błędu o jeden. 3) Przy rysunkach zrób tabelkę: numer wiersza → ile znaków jakiego rodzaju. 4) Przy przeszukiwaniu zastanów się, które wartości trzeba przeszukać, a które da się wyliczyć. 5) Oszacuj liczbę obrotów dla największych danych: do ok. 10⁸ — zdąży. 6) Przetestuj skrajności: n = 1, puste zakresy, największe liczby.

10 — Częste błędy

Częste błędy i dobre praktyki

;
Średniki w nawiasie, nie za nim
W nawiasie dokładnie dwa średniki: for (start; warunek; zmiana). Średnik za nawiasem — for (…); — tworzy pustą pętlę, a klamry wykonują się raz.
🔁
Kolejność: ciało, potem zmiana
Zmiana stoi w nawiasie przed ciałem, ale wykonuje się po nim. Start — tylko raz, warunek — przed każdym obrotem.
1️⃣
Błąd o jeden
i = 0; i < n i i = 1; i <= n to n obrotów. Od a do b jest b − a + 1 liczb. Sprawdź pierwszą i ostatnią wartość licznika.
📦
Licznik żyje w pętli
int i z nawiasu znika za pętlą. Jeśli wartość jest potrzebna później, utwórz zmienną przed pętlą: int i; for (i = 1; …).
✋
Nie zmieniaj licznika w ciele
Cała logika licznika w nagłówku. Dodatkowe i++ w ciele sprawia, że nagłówek kłamie, a pętla robi co innego, niż się wydaje.
🔀
Różne liczniki w różnych pętlach
W pętli w pętli używaj innych nazw: i i j albo w i k. Ten sam licznik w obu pętlach to przepis na chaos.
🔤
< przy napisach
Indeksy napisu to 0 … s.length() - 1, więc warunek to i < s.length(). Pętla wstecz — z licznikiem typu int.
&
for (char &c : s)
Bez & pętla „dla każdego” dostaje kopie znaków i zmiany przepadają. Z & zmieniasz oryginalny napis.
⏭️
continue w for jest bezpieczne
W for po continue zmiana z nawiasu wykona się normalnie — w odróżnieniu od while, gdzie i++ na końcu ciała zostałoby pominięte.
🧮
Nie przeszukuj tego, co da się wyliczyć
Jeśli trzecia wartość wynika z dwóch pierwszych (c = p − a − b, b = s − a), nie twórz dla niej pętli. Jedna pętla mniej to często tysiące razy szybciej.
⏱️
Policz obroty
Około 10⁸ prostych obrotów na sekundę. Pętla w pętli dla n = 10⁶ to 10¹² — nie zdąży. Dzielniki i liczby pierwsze — do pierwiastka.
📏
long long w nagłówku
Gdy licznik dochodzi do miliarda albo w warunku jest d * d dla dużych n, licznik musi być long long — inaczej przepełnienie zepsuje warunek.
