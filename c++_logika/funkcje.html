Funkcje — nazwany kawałek kodu

Do tej pory cały program siedział w main. Gdy ten sam fragment był potrzebny w trzech miejscach, przepisywałeś go trzy razy — a potem trzy razy poprawiałeś. Funkcja to kawałek kodu z własną nazwą: piszesz go raz, a uruchamiasz jedną linijką, ile razy chcesz. Może dostać dane do pracy, oddać wynik, odpowiedzieć „tak” albo „nie”, a nawet zmienić zmienne, które jej podasz. W tej lekcji poznasz funkcje od zera, bardzo powoli: od pierwszego void kreska(), przez parametry, return i referencje, aż po dzielenie dużego zadania olimpijskiego na małe, czytelne kawałki. 01 — Pierwsza funkcja

Pierwsza funkcja — nazwany kawałek kodu

Zacznijmy od czegoś bardzo prostego. Kino drukuje bilety, a na każdym bilecie między kolejnymi informacjami stoi kreska z myślników. Napiszmy to tak, jak umiemy do tej pory.

Ten sam kawałek w kilku miejscach

bez_funkcji.cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    cout << "----------\n";
    cout << "Bilet do kina\n";
    cout << "----------\n";
    cout << "Rzad 5, miejsce 12\n";
    cout << "----------\n";
    return 0;
}
▶ Wyjście
---------- Bilet do kina ---------- Rzad 5, miejsce 12 ----------

Program działa, ale linijka z kreską powtarza się trzy razy. Na razie to nic strasznego. Wyobraź sobie jednak, że kierownik kina mówi: „kreski mają być ze znaków =, a nie z myślników”. Musisz znaleźć i poprawić każde miejsce — a w większym programie łatwo któreś przegapić.

Do tego program trudniej się czyta: patrzysz na serię cout i musisz się domyślić, które linijki to „kreska”, a które to treść biletu.

Rozwiązanie: nadajmy kresce nazwę. Napiszemy ją raz, w jednym miejscu, a potem w programie będziemy tylko mówić „narysuj kreskę”.

To samo z funkcją

z_funkcja.cpp
#include <bits/stdc++.h>
using namespace std;

void kreska() {
    cout << "----------\n";
}

int main() {
    kreska();
    cout << "Bilet do kina\n";
    kreska();
    cout << "Rzad 5, miejsce 12\n";
    kreska();
    return 0;
}
▶ Wyjście
---------- Bilet do kina ---------- Rzad 5, miejsce 12 ----------

Nad main pojawiło się coś nowego:

void kreska() { cout << "----------\n"; }

To jest definicja funkcji: przepis o nazwie kreska, który mówi, co robić. Sam przepis jeszcze niczego nie wypisuje — tak jak przepis na ciasto w książce kucharskiej nie piecze ciasta.

W main trzy razy stoi kreska();. To jest wywołanie funkcji: „wykonaj teraz przepis o nazwie kreska”. Każde wywołanie wypisuje jedną kreskę.

Wynik jest dokładnie taki sam jak wcześniej. Różnica? Kreska jest zapisana w jednym miejscu. Gdy kierownik zażyczy sobie znaków =, zmieniasz jedną linijkę w funkcji — i wszystkie trzy kreski się zmieniają.

Zapamiętaj dwa słowa, bo będą wracać przez całą lekcję. Definicja to napisanie funkcji (nagłówek i ciało w klamrach) — robisz to raz. Wywołanie to użycie funkcji (nazwa z nawiasami) — robisz to tyle razy, ile potrzebujesz.

Co się dzieje przy wywołaniu — krok po kroku

Najważniejsza rzecz w tej części: program nie czyta pliku po prostu od góry do dołu. Zaczyna od main, a gdy trafi na wywołanie, skacze do funkcji, wykonuje jej ciało i wraca dokładnie tam, gdzie przerwał. main też jest funkcją

        

            
Spójrz jeszcze raz na int main() { … return 0; }. Wygląda jak nasza funkcja, prawda? Bo to jest funkcja — ma nazwę, nawiasy i ciało. Różni się tylko tym, że wywołuje ją system, gdy uruchamiasz program, a nie Ty. Słowo int przed nazwą i return 0; na końcu znaczą, że main oddaje systemowi liczbę 0 — umówiony sygnał „wszystko poszło dobrze”. Co to znaczy „oddać liczbę”, zobaczysz dokładnie w części 3.

            Zapamiętaj
            Funkcja to nazwany kawałek kodu. void nazwa() { … } — definicja: piszesz ją raz, nad main. nazwa(); — wywołanie: program skacze do funkcji, wykonuje całe ciało i wraca do linijki za wywołaniem. Funkcja bez wywołania nic nie robi. Funkcja może wywoływać inne funkcje (stojące wyżej), może być wywoływana w pętli i może sama wczytywać dane. Program zawsze startuje od main.

Parametry — funkcja dostaje dane

        

            
Nasza kreska() ma jedną wadę: zawsze rysuje dokładnie tę samą kreskę. A co, jeśli raz potrzebujesz kreski z 3 znaków, a raz z 20? Pisać dwadzieścia funkcji kreska3, kreska4…? Oczywiście nie. Funkcji trzeba po prostu powiedzieć, jak długa ma być kreska. Służą do tego parametry.

            Funkcja w warunku z && może się nie wykonać
            Warunek a(x) && b(x) liczy się od lewej. Jeśli a(x) odda fałsz, cały warunek już jest fałszywy — i C++ w ogóle nie wywołuje b(x). Przy || jest odwrotnie: gdy lewa strona jest prawdziwa, prawa się nie wykonuje. Zwykle to zaleta (szybciej, a przy if (i < n && t[i] == x) — bezpieczniej), ale jeśli funkcja coś wypisuje albo zmienia, zaskoczy Cię to. Sprawdź quiz poniżej.
        


        

            Zapamiętaj
            bool czyX(…) { return warunek; } — funkcja-pytanie; używaj jej w if, while, z !, &&, ||. return w pętli kończy całą funkcję — stawiaj go przy znalezieniu, a odpowiedź „nie znalazłem” dawaj po pętli. Każda droga przez funkcję, która coś oddaje, musi skończyć się return — ostrzeżenie control reaches end of non-void function traktuj jak błąd. W void wychodzisz wcześniej przez return;.

        05 — Zasięg zmiennych
        
Zasięg — zmienne lokalne i globalne

        

            
Gdy funkcji robi się więcej, pojawia się pytanie: czyje są zmienne? Czy funkcja widzi zmienną z main? Co się stanie, gdy dwie funkcje mają zmienną o tej samej nazwie? Dlaczego licznik w funkcji ciągle się zeruje? Odpowiedź na wszystkie te pytania to jedno słowo: zasięg — miejsce w programie, w którym zmienna istnieje i jest widoczna.

Zmienna utworzona w środku funkcji (także parametr) to zmienna lokalna: istnieje tylko w tej funkcji i tylko w czasie jej wywołania. Z zewnątrz jej nie widać.

                    
To bardzo wygodne: pisząc funkcję, nie musisz sprawdzać, czy ktoś gdzieś indziej nie użył już nazwy i, s czy wynik.

Zmienne lokalne mieszkają w małym obszarze pamięci zwanym stosem — tym samym, na którym leżą ramki wywołań z naszych śladów. Stos ma zwykle tylko kilka megabajtów: na Linuksie (i w sprawdzarce) około 8 MB, na Windowsie często tylko 1 MB.

Przeciążanie, wartości domyślne i rozbijanie zadania na funkcje

        

            
Znasz już wszystko, co najważniejsze. W tej części kilka narzędzi, które sprawiają, że funkcje są wygodniejsze: kilka funkcji o tej samej nazwie, parametry, które można pominąć, i funkcje napisane pod main. W C++ kilka funkcji może mieć tę samą nazwę, jeśli różnią się parametrami — ich liczbą albo typami. To się nazywa przeciążanie.

                    
Przy każdym wywołaniu kompilator patrzy na argumenty i sam wybiera pasującą wersję: jeden int — kwadrat, dwa int-y — prostokąt, double — koło.

                    
Znasz to z biblioteki: abs działa dla int, long long i double, a max dla wszystkich typów — to właśnie przeciążanie.

C++ nie obiecuje, w jakiej kolejności policzy argumenty jednego wywołania. Nasz kompilator (GCC) policzył najpierw drugi argument — to on wczytał 10 — a dopiero potem pierwszy, który dostał 3. Wyszło 3 − 10.

            Jak dzielić program na funkcje
            1) Opisz rozwiązanie słowami w kilku krokach — każdy krok to kandydat na funkcję. 2) Gdy ten sam kawałek kodu pojawia się drugi raz, zrób z niego funkcję. 3) Funkcja powinna robić jedną rzecz i mieścić się na ekranie (do ~20 linijek). 4) Nazwa mówi, co funkcja robi: czasowniki dla działań (wczytaj, rysuj), czy… dla pytań, rzeczowniki dla obliczeń (suma, pole). 5) Funkcja, która liczy, oddaje wynik przez return; wypisywanie zostaw na koniec. 6) Każdą funkcję sprawdź osobno na małym przykładzie, zanim złożysz całość.

        09 — Baza zadań
        
Baza zadań: funkcje w praktyce

        

            
Znasz już cały warsztat: funkcje void i funkcje oddające wynik, parametry, funkcje-pytania z wczesnym return, zmienne lokalne i globalne, referencje i const &, funkcje z vectorem, napisem i parą, komparatory, przeciążanie, wartości domyślne i dzielenie zadania na kawałki. Czas na zadania, w których funkcje naprawdę się opłacają — bo ten sam kawałek przydaje się wiele razy albo bez podziału rozwiązanie byłoby nie do ogarnięcia.

            
Zadania są ułożone od najłatwiejszego do najtrudniejszego: najpierw rozgrzewka z jedną, dwiema funkcjami, potem kilka funkcji, które ze sobą współpracują, a na końcu duże zadania z wielkim finałem. W treści każdego zadania jest podpowiedź, jakie funkcje napisać. Jeśli coś brzmi obco, wróć do odpowiedniej części — mapa lekcji jest na górze strony. A tu masz najważniejsze schematy w jednym miejscu:

            Jak rozwiązywać zadania z funkcjami
            1) Przeczytaj, jakie funkcje proponuje treść, i zapisz ich nagłówki: nazwa, parametry, typ zwracany. 2) Napisz main jak plan — z wywołaniami funkcji, których jeszcze nie ma. 3) Pisz funkcje po jednej i sprawdzaj każdą osobno na małym przykładzie (np. tymczasowym cout w main). 4) Przy każdym parametrze zdecyduj: kopia, & czy const &. 5) Sprawdź, czy każda droga przez funkcję kończy się return i czy typ zwracany pomieści wynik (long long!). 6) Duże tablice — globalnie; globalne liczniki — zerowane w każdym teście. 7) Gdy kolejność wczytywania ma znaczenie, wczytuj do zmiennych przed wywołaniem.

        10 — Częste błędy
        
Częste błędy i dobre praktyki

        

            

                
⬆️

                
Funkcja nad main

                
Kompilator czyta plik od góry. Wywołanie funkcji, której jeszcze nie widział, kończy się błędem was not declared in this scope. Przenieś funkcję wyżej albo napisz nad main jej deklarację int f(int x);.

            

            

                
( )

                
Nawiasy przy wywołaniu

                
kreska; bez nawiasów niczego nie wywołuje — program się skompiluje, ale funkcja się nie wykona. Nawiasy są obowiązkowe, nawet puste: kreska();. Wyjątek: komparator podajesz do sort bez nawiasów.

            

            

                
❗

                
Każda droga z return

                
Jeśli funkcja ma coś oddać, każda ścieżka przez nią musi kończyć się return. Ostrzeżenie control reaches end of non-void function traktuj jak błąd — taki program potrafi wypisywać bzdury albo zapętlić się.

            

            

                
🎯

                
Liczysz — oddawaj

                
Funkcja, która coś liczy, niech oddaje wynik przez return zamiast go wypisywać. Wynik da się wtedy dodać, porównać, zapisać i wstawić do innej funkcji. Wypisywanie zostaw dla main.

            

            

                
🔢

                
Typ zwracany decyduje

                
Wynik jest zamieniany na typ zwracany: 2.5 w funkcji int staje się 2. A w funkcji double dzielenie (a + b) / 2 wciąż jest całkowite — pisz 2.0. Duże wyniki: long long.

            

            

                
📋

                
Parametr to kopia

                
Bez & funkcja dostaje kopię — zmiana parametru nie zmienia zmiennej w main. Wynik podwoj(a); bez przypisania przepada; pisz a = podwoj(a); albo użyj referencji.

            

            

                
🔗

                
& zmienia oryginał

                
int &x to druga nazwa zmiennej z wywołania — zmiany są widoczne na zewnątrz. Do takiego parametru podajesz zmienną, nie liczbę. Przy dwóch referencjach do tej samej zmiennej (f(x, x)) obie zmieniają to samo.

            

            

                
🐢

                
Duże dane przez const &

                
vector, string i map przekazane bez & są kopiowane przy każdym wywołaniu. W pętli to potrafi zamienić 30 ms w kilka sekund. Tylko czytasz — const vector<int> &v; zmieniasz — vector<int> &v.

            

            

                
🌍

                
Globalne — z głową

                
Zmienne globalne startują od zera i żyją przez cały program, więc przy wielu testach pamiętają poprzedni test — zeruj je na początku każdego. Unikaj globalnych nazw z biblioteki (y1, count) i lokalnych nazw takich samych jak globalne.

            

            

                
🧱

                
Duże tablice globalnie

                
Zmienne lokalne leżą na stosie, który ma kilka megabajtów (na Windowsie często 1 MB). Tablica z milionami elementów w main wywraca program. Deklaruj ją nad main albo użyj vector.

            

            

                
🔀

                
Kolejność argumentów

                
Argumenty trafiają do parametrów po kolei — zamienione miejscami int i char potrafią się skompilować i dać bzdury. A kolejność liczenia argumentów nie jest ustalona: f(wczytaj(), wczytaj()) może wczytać od tyłu.

            

            

                
✂️

                
Małe funkcje, dobre nazwy

                
Funkcja robi jedną rzecz i mieści się na ekranie. Nazwa mówi, co robi: wczytaj, czyPierwsza, sumaCyfr. Powtarzasz kod drugi raz? Zrób z niego funkcję. Każdą sprawdź osobno, zanim złożysz całość.

            

            

                
⚖️

                
Komparator ściśle

                
Komparator odpowiada na pytanie „czy a stoi przed b?”. Dla równych elementów musi oddać false — używaj < i >, nigdy <= czy >= (to potrafi wywrócić sort). Remisy rozstrzygaj drugim kluczem.
