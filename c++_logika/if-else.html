01 — Pierwszy if

if — zrób to tylko wtedy, gdy…

Wszystkie programy, które do tej pory napisałeś, działały jak przepis kucharski: linijka po linijce, od góry do dołu, zawsze tak samo. Bez względu na to, jakie dane dostały, wykonywały dokładnie te same instrukcje. Prawdziwe programy muszą jednak reagować na dane: bankomat wypłaci pieniądze tylko wtedy, gdy masz ich dość na koncie, a gra pokaże „Koniec gry” dopiero wtedy, gdy stracisz wszystkie życia.

Do podejmowania takich decyzji służy instrukcja if (po angielsku „jeżeli”). W zwykłym języku mówisz tak bez przerwy: „jeżeli pada deszcz, weź parasol”. W C++ zapisujesz to prawie tak samo:

schemat_if.cpp
if (warunek) {
    // te instrukcje wykonają się tylko wtedy,
    // gdy warunek jest prawdziwy (true)
}
❓

warunek w nawiasie

Po słowie if, w okrągłych nawiasach, piszesz to, co sprawdzasz, np. wiek < 18. Znasz to z lekcji o typie bool: porównanie daje true albo false.

🔲

klamry { }

Między klamrami stoi kod, który wykona się tylko wtedy, gdy warunek jest prawdziwy. Gdy jest fałszywy, program przeskakuje całe klamry, jakby ich nie było.

➡️

wcięcie

Linijki w klamrach przesuwamy o 4 spacje w prawo. Kompilatorowi to obojętne, ale Ty od razu widzisz, co jest w środku if, a co już poza nim.

Pułapka 1: średnik po if

Ten program ma błąd, którego bardzo trudno się dopatrzyć. Zmienna x to 3, więc napis nie powinien się pokazać — a jednak się pokazuje:

srednik.cpp
int x = 3;
if (x > 10); {
    cout << "x jest duze\n";
}
cout << "koniec\n";
▶ Wyjście
x jest duze koniec

Winny jest średnik po nawiasie. Średnik kończy instrukcję, więc if (x > 10); znaczy: „jeżeli x jest większe od 10, nie rób nic”. Klamry, które stoją dalej, nie należą już do if — to zwykły blok kodu, który wykonuje się zawsze.

Zapamiętaj: po nawiasie z warunkiem od razu otwierasz klamrę, bez średnika.

Pułapka 2: if bez klamer

Klamry wolno pominąć, gdy w środku jest dokładnie jedna instrukcja: if (x < 0) x = -x;. Ale wtedy do if należy tylko ta jedna, najbliższa instrukcja — nawet jeśli wcięcie sugeruje coś innego:

bez_klamer.cpp
int x = 5;
if (x > 10)
    cout << "x jest duze\n";
    cout << "naprawde duze!\n";
cout << "koniec\n";
▶ Wyjście
naprawde duze! koniec

Do if należy tylko pierwszy cout. Drugi, mimo wcięcia, stoi już poza nim i wykonuje się zawsze. Kompilator patrzy na klamry i średniki, a nie na spacje.

Rada na początek: zawsze pisz klamry, nawet przy jednej instrukcji. Kosztuje to dwa znaki, a oszczędza godzin szukania błędów.

02 — if … else

else — co zrobić w przeciwnym razie

Sam if mówi: „zrób to, jeżeli…”. Często jednak potrzebny jest też plan B: „jeżeli pada, weź parasol, a w przeciwnym razie weź okulary przeciwsłoneczne”. Do tego służy słowo else (po angielsku „w przeciwnym razie”). Stawiasz je zaraz za klamrą zamykającą if i dajesz mu własne klamry:

schemat_if_else.cpp
if (warunek) {
    // wykona się, gdy warunek jest prawdziwy
} else {
    // wykona się, gdy warunek jest fałszywy
}

Teraz program zawsze wykona dokładnie jedną z dwóch części: albo tę po if, albo tę po else. Nigdy obu naraz i nigdy żadnej. Najprostszy przykład to sprawdzenie, czy liczba jest parzysta:

parzystosc.cpp
#include <iostream>
using namespace std;

int main() {
    int n;
    cin >> n;
    if (n % 2 == 0) {
        cout << "PARZYSTA\n";
    } else {
        cout << "NIEPARZYSTA\n";
    }
    return 0;
}

Pamiętasz % z lekcji o typach? n % 2 to reszta z dzielenia przez 2: dla liczb parzystych wynosi 0, a dla nieparzystych nie. Warunek n % 2 == 0 zobaczysz jeszcze setki razy.

Uwaga na liczby ujemne W C++ reszta z dzielenia liczby ujemnej też jest ujemna: -7 % 2 to -1, a nie 1. Dlatego nieparzystość sprawdzaj przez n % 2 != 0 (albo po prostu else po n % 2 == 0), a nie przez n % 2 == 1 — ten drugi warunek dla −7 jest fałszywy!

Z czego zbudować warunek

Warunek to wszystko, co daje odpowiedź true albo false. Najczęściej jest to porównanie. Sześć operatorów porównania znasz już z lekcji o typie bool — oto one jeszcze raz, tym razem w roli warunków w if:

Baza zadań: decyzje w praktyce

Znasz już wszystkie narzędzia do podejmowania decyzji: if, else, else if, łączenie warunków, zagnieżdżanie, typowe schematy oraz switch i ?:. Czas sprawdzić je na zadaniach, które łączą kilka z nich naraz. Zadania są ułożone od najłatwiejszego do najtrudniejszego: najpierw rozgrzewka, potem zadania średnie, a na końcu trudne — z szachownicą, trójkątami, kalendarzem i wielkim finałem, w którym przydaje się wszystko naraz.

Jak rozwiązywać zadania z warunkami 1) Przeczytaj treść i wypisz sobie wszystkie przypadki: co ma się stać, gdy… 2) Dla każdego przypadku ustal warunek i zdecyduj, czy przypadki się wykluczają (łańcuch else if), czy są niezależne (osobne if-y). 3) Zastanów się nad granicami: co dla liczby równej progowi, dla zera, dla liczb ujemnych? 4) Uruchom program na przykładzie i na kilku własnych danych — zwłaszcza na granicach. 5) Wyślij. 10 — Częste błędy

Częste błędy i dobre praktyki

🟰
==, a nie =
W warunku porównujesz przez ==. if (x = 5) to przypisanie: zawsze „prawda” i po cichu psuje zmienną.
🚫
Bez średnika po if
if (x > 10); kończy instrukcję if — klamry za nim wykonują się zawsze. Po nawiasie od razu otwierasz klamrę.
🔲
Zawsze klamry
Bez klamer do if należy tylko jedna instrukcja, a else łączy się z najbliższym if. Klamry kosztują dwa znaki i oszczędzają godzin szukania błędów.
↕️
Kolejność w else if
Wygrywa pierwszy prawdziwy warunek. Przy >= zaczynaj od największego progu, przy < — od najmniejszego. Najpierw sprawdzaj przypadki szczególne (np. FizzBuzz przed Fizz).
📏
a <= x <= b nie działa
Przedział zapisujesz dwoma porównaniami: x >= a && x <= b. Poza przedziałem: x < a || x > b.
✂️
Nie skracaj porównań
c == 'a' || 'e' jest zawsze prawdą. Każde porównanie piszesz w całości: c == 'a' || c == 'e'.
( )
Nawiasy przy && i ||
Gdy w jednym warunku mieszasz && i ||, dodaj nawiasy: (a || b) && c to coś innego niż a || (b && c).
➖
Ujemne liczby i %
-7 % 2 to -1. Parzystość sprawdzaj przez n % 2 == 0 lub n % 2 != 0, nigdy przez n % 2 == 1.
📦
Zmienna przed if
Zmienna utworzona w klamrach znika za nimi. Jeśli potrzebujesz wyniku po if, utwórz zmienną przed nim, a w gałęziach tylko zmieniaj jej wartość.
🧱
Testuj granice
Sprawdź program dla liczby równej progowi i o jeden mniejszej, dla zera i dla liczb ujemnych. Tam kryje się większość błędów > zamiast >=.
🛡️
Najpierw zabezpieczenie
b != 0 && a % b == 0 — dzięki skróconemu obliczaniu dzielenie przez zero nigdy się nie wykona. Odwrotna kolejność wysypie program.
🔤
TAK to nie Tak
Odpowiedzi przepisuj z treści zadania co do litery. Sprawdzarka odróżnia wielkie litery od małych, a 'a' (znak) od "a" (napis) odróżnia nawet kompilator.
