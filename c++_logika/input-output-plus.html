Jak sprawdzarka podaje dane i czyta wynik

W tej lekcji szczegóły formatu są najważniejsze, więc zacznijmy od tego, co dokładnie robi sprawdzarka.

Dane trafiają do programu jako jeden ciąg znaków — taśma. Twój program nie wie, że dane „przyszły w trzech wierszach”: widzi znaki, wśród których stoją znaki końca wiersza. W sprawdzarce na samym końcu danych nie ma dodatkowego entera, a przy pisaniu na klawiaturze — zwykle jest. Dobry program działa w obu przypadkach; w części 1 zobaczysz, jak to zapewnić.

Wynik sprawdzarka porównuje z oczekiwanym znak po znaku, ale wcześniej wybacza dwie drobnostki: usuwa spacje z końca każdego wiersza i puste wiersze z końca całego wyniku. Wszystko inne musi się zgadzać: spacje w środku i na początku wiersza, przecinki, wielkość liter, kolejność wierszy. Dlatego 1 2 3␣ przejdzie, a 1, 2, 3, — już nie.

Jak działa sprawdzarka Każde ćwiczenie otwiera się w sprawdzarce w nowej karcie. Wklejasz cały program, klikasz Wyślij, a sprawdzarka uruchamia go na kilku testach i porównuje wynik z oczekiwanym. Każdy test ma limit czasu (zwykle 1 sekundę). W części 8 dane są duże, a rozwiązanie „pętla w pętli” nie zdąży — tam liczy się już nie tylko format, ale i szybkość.

Zwróć uwagę na prawy dolny program: liczby stoją w trzech wierszach, a wynik jest ten sam. cin >> przeskakuje spacje i entery tak samo, więc przy czytaniu liczb układ w wierszach nie ma znaczenia — to znasz z lekcji Input / Output.

cin >> x to pytanie: „udało się?”

Wyrażenie cin >> x robi dwie rzeczy. Najpierw próbuje wczytać liczbę do x. Potem zwraca sam strumień cin — a strumień postawiony w warunku (w if albo w while) odpowiada na pytanie: czy wszystkie dotychczasowe wczytania się udały? Dlatego można napisać tak:

int x;
if (cin >> x) cout << "Wczytano " << x << "\n";
else cout << "Nie ma liczby\n";

Wczytanie nie udaje się w dwóch sytuacjach:

1. Taśma się skończyła. cin >> przeskoczył białe znaki i nie znalazł już nic do czytania. Tak jest w wejściu 2 — i tak kończy się każda pętla while (cin >> x): po ostatniej liczbie przychodzi jeszcze jeden obrót, w którym wczytanie się nie udaje, i warunek staje się fałszywy.

2. Na taśmie stoi coś, co nie pasuje do typu. W wejściu 3 stoi słowo „kot”, a x jest liczbą. Tę sytuację omówimy za chwilę dokładniej, bo ma ważny skutek uboczny.

W czwartym obrocie wczytanie się nie uda — strumień dostanie flagi eof (koniec danych) i fail (nieudane wczytanie), a x zostanie bez zmian.

Wartość kończąca: najpierw wczytaj, potem sprawdź

Warunek cin >> x && x != 0 czyta się od lewej: najpierw wczytaj liczbę, a dopiero potem sprawdź, czy to nie zero. Operator && sprawdza prawą stronę tylko wtedy, gdy lewa jest prawdziwa — więc gdy danych zabraknie, nikt nie porówna śmieci z zerem.

Liczby 100 i 200 stoją za zerem. Program ich nie czyta i nie musi: po wyjściu z pętli po prostu wypisuje wynik. Nieprzeczytane dane na taśmie nikomu nie przeszkadzają — sprawdzarka patrzy tylko na to, co program wypisał.

zero_policzone.cpp
int x = -1, ile = 0;

▶ Wyjście

A tak wygląda klasyczny błąd: warunek sprawdza x, zanim w ogóle cokolwiek wczytamy (dlatego trzeba było wymyślić start x = -1), a wczytanie stoi w środku pętli. Gdy przychodzi zero, licznik zdąży się jeszcze zwiększyć — i program mówi, że liczb było 4, a były 3.

Ten sam kłopot ma każda pętla, w której najpierw sprawdzamy, potem czytamy. Rozwiązanie jest zawsze to samo: wczytanie przenieś do warunku, tak jak w programie wyżej.

Gdy koniec oznacza para liczb, warunek końca to obie liczby naraz: x == 0 && y == 0. W pętli potrzebujemy zaprzeczenia — „dopóki to nie jest para 0 0” — czyli !(x == 0 && y == 0). Częsty błąd to x != 0 && y != 0: zatrzyma pętlę już na punkcie (0, 5), który przecież jest zwykłym punktem na osi.

Gdy koniec oznacza słowo, porównujemy całe napisy przez !=. Słowo KONIECZNIE to inne słowo niż KONIEC, więc nie kończy danych — porównanie napisów sprawdza każdą literę, a nie tylko początek.

W warunku może stać kilka wczytań naraz: cin >> imie >> punkty. Warunek jest prawdziwy tylko wtedy, gdy udały się wszystkie — czyli gdy przeczytaliśmy cały rekord. Tak czyta się dane „wiersz za wierszem, do końca”, gdy każdy wiersz ma stałą liczbę kawałków.

Pętla nie wie nic o wierszach — po prostu czyta imię, potem liczbę, potem imię… Gdyby dane były porozrzucane inaczej (kilka rekordów w jednym wierszu), program działałby tak samo.

Gdy na taśmie stoi coś innego niż liczba

litera_zamiast_liczby.cpp
int a = 7, b = 7, c = 7;
cin >> a;
cin >> b;   // na taśmie stoi litera
cin >> c;
cout << a << " " << b << " " << c << "\n";
if (cin.fail()) cout << "strumien zepsuty\n";

▶ Wyjście

Pierwsze wczytanie się udaje: a = 12. Drugie trafia na literę a ze słowa „abc”. To nie cyfra, więc wczytanie się nie udaje — i dzieją się trzy rzeczy:

1. b dostaje wartość 0 (tak działa C++ od wersji z 2011 roku).

2. Strumień przechodzi w stan fail — sprawdzisz to przez cin.fail().

3. Litera zostaje na taśmie. A ponieważ strumień jest „zepsuty”, każde następne cin >> nic nie robi — dlatego c zostało równe 7, choć na taśmie czeka liczba 5.

while (cin >> x) suma += x;
cin.clear();          // naprawiamy strumień

cin >> slowo;         // litera wciąż czeka na taśmie

Strumień da się „naprawić”: cin.clear() kasuje flagi błędu. Taśma się przy tym nie zmienia — słowo, o które potknęła się pętla, wciąż czeka i możemy je wczytać do string.

To się przydaje, gdy dane składają się z liczb, a po nich stoi słowo — i nie wiemy, ile jest liczb. Pętla while (cin >> x) zatrzyma się dokładnie na pierwszym kawałku, który nie jest liczbą.

Prześledź to w ramce: najpierw cin >> a, potem nieudane cin >> b, potem cin.clear(), słowo i liczba. Spróbuj też własnych danych — na przykład liczby 3000000000, która nie mieści się w int: wczytanie też się nie uda, a zmienna dostanie największą wartość int, czyli 2147483647.

Pułapka: while (!cin.eof())

W internecie często można spotkać taki sposób czytania do końca danych: „dopóki nie koniec pliku — czytaj”. Wygląda rozsądnie, ale ma podstępny błąd.

eof_zle.cpp
int x, ile = 0;
long long suma = 0;
while (!cin.eof()) {
    cin >> x;
    ile++;
    suma += x;
}
cout << ile << " " << suma << "\n";

1 2 3
▶ Wyjście 1
4 9
▶ Wejście 2 — bez entera na końcu
1 2 3

Flaga eof zapala się dopiero wtedy, gdy program spróbuje czytać za końcem danych. Po wczytaniu trójki z wejścia 1 na taśmie zostaje jeszcze enter:

1␣2␣3↵koniec

Flaga eof jeszcze się nie zapaliła, więc pętla robi czwarty obrót. cin >> x przeskakuje enter, nie znajduje liczby i się nie udaje — ale x zostaje równe 3 i trójka zostaje policzona drugi raz. Na klawiaturze i w plikach dane prawie zawsze kończą się enterem, więc ten błąd wychodzi bardzo często.

Rada jest prosta: wczytanie zawsze w warunku pętli — while (cin >> x). Wtedy obrót wykonuje się tylko po udanym wczytaniu, niezależnie od enterów na końcu.

Zapamiętaj Trzy formaty: liczba n na początku (for), wartość kończąca (while (cin >> x && x != 0)) i do końca danych (while (cin >> x)). cin >> x w warunku znaczy „czy się udało?”. Nie udaje się na końcu danych (eof i fail, zmienna bez zmian) i na znaku, który nie pasuje do typu (fail, liczba dostaje 0, znak zostaje na taśmie). Zepsuty strumień nic nie czyta, dopóki nie wywołasz cin.clear(). Wczytanie stawiaj w warunku, nie w środku pętli — i nigdy while (!cin.eof()).

Wielka tablica i tysiące testów

Pod treścią zadań z wieloma testami często stoi ograniczenie w rodzaju: t ≤ 10⁴, n ≤ 10⁵, suma n we wszystkich testach ≤ 10⁵. To ostatnie zdanie jest bardzo ważne: mówi, że testów może być dużo, ale wszystkie razem mają niewiele liczb. Program, który w każdym teście robi tyle pracy, ile test ma liczb, zdąży bez problemu. Program, który w każdym teście robi coś dużego „na zapas”, nie zdąży.

Typowy przykład: liczniki w globalnej tablicy int ile[1000001]. Wyzerowanie jej przed każdym testem to milion operacji razy 10⁴ testów — 10¹⁰ operacji, około stu sekund. Zamiast tego wyzeruj po teście tylko te pola, które test zmienił:

#include <bits/stdc++.h>

int main() {

03 — Wypisywanie

Wypisywanie z głową — separatory, kolumny i tabele

Wynik programu to też dane — tylko że czyta je sprawdzarka, a ona jest bardzo dokładna. Przypomnijmy z wprowadzenia: na końcu każdego wiersza spacje są wybaczane, puste wiersze na końcu wyniku też. Cała reszta musi się zgadzać co do znaku. Spójrz na dwa wyniki, w których spacje zaznaczyliśmy kropkami:

1·2·3·
Spacja na końcu wiersza — sprawdzarka ją usunie przed porównaniem. Ten wynik przejdzie, jeśli oczekiwano 1 2 3.
1,·2,·3,
Przecinek na końcu to zwykły znak. Jeśli oczekiwano 1, 2, 3 — ten wynik jest zły.

Dlatego przy spacjach można sobie pozwolić na trochę niedbałości, ale przy każdym innym separatorze — nie. W tej części nauczysz się wypisywać listy, wiersze po k elementów, równe kolumny i tabele tak, żeby zgadzał się każdy znak.

Separator między elementami — trzy sposoby

// sposób 2: pierwszy osobno, reszta z separatorem

// sposób 3: po elemencie separator albo koniec wiersza

Sposób 2 jest krótki, ale wysypie się na pustym vectorze — v[0] nie istnieje.

Znak po znaku — cin.get, peek i plansze

Do tej pory czytaliśmy taśmę „kawałkami”: liczba, słowo, liczba. Czasem jednak trzeba zejść niżej i czytać ją znak po znaku — gdy liczy się każda spacja, gdy liczba jest sklejona z literą, gdy plansza nie ma odstępów albo gdy dopiero pierwszy znak mówi, co stoi dalej. Do tego służą trzy narzędzia: cin >> c, cin.get(c) i cin.peek().

Rozbieramy wiersz — stringstream i liczby w tekście

Zadanie: każdy wiersz to punkty jednego ucznia z kartkówek — ale każdy pisał inną liczbę kartkówek. Wypisz sumę dla każdego ucznia.

Samo cin >> x tu nie wystarczy: przeskakuje entery tak samo jak spacje, więc nie odróżni, gdzie kończą się liczby jednego ucznia, a zaczynają drugiego. Potrzebujemy dwóch kroków: najpierw wczytać cały wiersz przez getline, a potem rozebrać go na kawałki. Do rozbierania służy stringstream.

Pusty wiersz daje pusty strumień — pętla nie obróci się ani razu i suma zostanie 0. Bardzo ważne: stringstream tworzymy w środku pętli, nowy dla każdego wiersza. (To dokładnie ta sama zasada co przy wielu testach w części 2.)

Wystarczy sztuczka z lekcji Input / Output: separator (dwukropek, minus, nawias, przecinek) wczytujemy do zmiennej char, której potem nie używamy — jej zadaniem jest tylko „zjeść” znak. Teraz robimy to w pętli while, do końca danych.

Minus przed liczbą nie przeszkadza: w (3,-4) zmienna b zjada przecinek, a cin >> y czyta całe −4 razem ze znakiem. Kłopot byłby tylko wtedy, gdyby separatorem był sam minus, a liczby mogły być ujemne — wtedy trzeba myśleć.

Rozcinanie po wybranym znaku: getline(ss, pole, ',')

pola.cpp
string s;
getline(cin, s);
stringstream ss(s);
string pole;
int nr = 0;
while (getline(ss, pole, ',')) {
    nr++;
    cout << nr << ": [" << pole << "]\n";
}
▶ Wejście
Jan,Kowalski,,15,Nowy Sacz
▶ Wyjście
1: [Jan] 2: [Kowalski] 3: [] 4: [15] 5: [Nowy Sacz]

getline działa na każdym strumieniu — także na stringstream. Z trzecim argumentem czyta do wybranego znaku i go zjada, więc while (getline(ss, pole, ',')) tnie wiersz na kawałki między przecinkami. Spacje zostają w polach („Nowy Sacz”), a dwa przecinki obok siebie dają puste pole.

Pole z liczbą zamienisz na liczbę przez stoi(pole) albo stoll(pole) — znasz je z lekcji o napisach.

Jedna pułapka: przecinek na samym końcu wiersza nie daje pustego ostatniego pola. Po nim nie ma już żadnego znaku, więc getline nic nie czyta i pętla się kończy. Jeśli puste ostatnie pole ma znaczenie, trzeba je doliczyć osobno.

Wiersz „12+7-3+100” to liczba, a potem pary „znak, liczba”. Pierwsze ss >> wynik czyta 12 i zatrzymuje się na plusie (plus nie jest cyfrą). Potem pętla czyta pary: ss >> op bierze znak, ss >> x — liczbę.

A co z minusem? Przecież ss >> x umie czytać liczby ujemne… Ale minus zostaje zjedzony wcześniej, przez ss >> op, więc do x trafia już sama liczba. Kolejność wczytań robi tu całą robotę.

Polskie kwoty pisze się z przecinkiem: 12,50. Dla C++ przecinek nie jest częścią liczby, więc cin >> double przeczytałby tylko 12. Do tego ktoś pisał niedbale: „12,5” to też dwanaście złotych i pięćdziesiąt groszy, a „3,05” — trzy złote i pięć groszy.

Gdy zapis liczby jest nietypowy, czytaj ją jako napis i rozbierz sam: find znajduje przecinek, substr wycina części, stoll zamienia je na liczby. Całość liczymy w groszach — liczby całkowite są dokładne, a double nie zawsze.

Pola oddzielone znakiem: getline(ss, pole, ',') (puste pole w środku tak, na końcu — nie). Liczby sklejone z tekstem: x = x * 10 + (c - '0') i doliczenie ostatniej po pętli. Nietypowy zapis liczby: czytaj jako napis, rozbieraj find i substr.

Polecenia różnych typów — każde z innymi danymi

W wielu zadaniach wejście to lista poleceń: „dodaj”, „usuń”, „pokaż”, „ile”. Każde polecenie ma inne dane: jedno ma liczbę, drugie dwie, trzecie żadnej, czwarte — cały tekst do końca wiersza. Program czyta najpierw nazwę polecenia, a dopiero ona mówi mu, co wczytać dalej.

Najpierw nazwa polecenia, potem jego dane

Ostatnie else obsługuje wszystkie cztery kierunki naraz, bo wszystkie mają po jednej liczbie. Gdyby polecenia miały różne dane, każde dostałoby własną gałąź.

Jak pisać program z poleceniami 1) Wypisz z treści wszystkie polecenia i dla każdego: jakie ma dane, co zmienia i co wypisuje. 2) Wybierz strukturę, która to trzyma (zmienna, vector, zbiór, multiset). 3) Napisz pętlę po poleceniach w formacie z treści. 4) W każdej gałęzi wczytaj dokładnie dane tego polecenia. 5) Wypisuj tylko tam, gdzie każe treść — i sprawdź, co ma się stać w przypadkach brzegowych: pusty zbiór, element, którego nie ma, numer spoza zakresu.
Zapamiętaj Najpierw wczytaj polecenie (słowo do string, znak do char, numer do int), potem w gałęzi tego polecenia — dokładnie jego dane. Za dużo wczytanych danych psuje strumień, za mało — przesuwa następne polecenia. Tekst do końca wiersza: getline(cin >> ws, t). Liczba poleceń: q na początku, słowo kończące albo koniec danych.

08 — Duże dane

Duże dane — bufor, sync_with_stdio, generatory i pliki

Przy dziesięciu liczbach nie ma znaczenia, jak je czytasz. Przy milionie — ma ogromne. Na olimpiadzie dane mają często po kilka megabajtów i zdarza się, że program z dobrym algorytmem nie mieści się w limicie czasu tylko dlatego, że samo wczytywanie i wypisywanie trwa za długo. Zobaczmy, ile to kosztuje — zmierzyliśmy to na tym samym serwerze, na którym działa sprawdzarka:

co robi programczas
wczytuje 10⁶ liczb przez cin (domyślne ustawienia)ok. 255 ms
wczytuje 10⁶ liczb przez cin po sync_with_stdio(false)ok. 46 ms
wczytuje 10⁶ liczb przez scanfok. 85 ms
wypisuje 10⁶ wierszy przez cout z endlok. 480 ms

Różnice są pięcio- i dziesięciokrotne — a przy limicie jednej sekundy pół sekundy na samo wypisanie to bardzo dużo. Na Twoim komputerze liczby będą inne (w konsoli Windowsa endl bywa jeszcze dużo wolniejszy), ale proporcje zostaną podobne. Za chwilę zobaczysz, skąd te różnice się biorą i jak je usunąć dwiema linijkami.

Bufor — dlaczego endl jest wolny

cout nie wysyła na ekran każdego znaku osobno. Zbiera znaki w buforze — kawałku pamięci programu — i dopiero gdy bufor się zapełni (albo program się kończy), wysyła wszystko naraz. To jak ciężarówka, która odjeżdża, dopiero gdy jest pełna: jeden kurs z tysiącem paczek jest dużo tańszy niż tysiąc kursów z jedną paczką, bo każda wysyłka to rozmowa programu z systemem operacyjnym.

A endl? To enter i rozkaz „wyślij teraz” (opróżnij bufor). Program z endl po każdym wierszu wysyła ciężarówkę z jedną paczką — milion razy. Program z "\n" dokłada enter do bufora i jedzie dalej. Na ekranie widać dokładnie to samo; różnica jest tylko w czasie. Sprawdź to w ramce: najpierw z endl, potem przełącz na "\n" i porównaj liczbę wysyłek.

        09 — Baza zadań
        
Baza zadań: wejście i wyjście w praktyce

        

            
Znasz już cały warsztat: trzy formaty danych i stan strumienia, wiele testów w jednym wejściu, separatory, kolumny i tabele, czytanie znak po znaku z cin.get i peek, getline od środka, rozbieranie wiersza strumieniem stringstream, polecenia z różną liczbą danych, a do tego bufor, sync_with_stdio, generatory i sumy kontrolne. Czas na zadania, które łączą kilka z tych rzeczy naraz — wiele z nich to formaty wzięte prosto z życia: rachunki, kalendarze, tabele ligowe, dzienniki serwera, pliki CSV i Markdown. Zadania są ułożone od najłatwiejszego do najtrudniejszego: najpierw rozgrzewka, potem zadania średnie, a na końcu trudne — z wielkim finałem.

            
Przy każdym zadaniu widać, jakich zagadnień używa — jeśli coś brzmi obco, wróć do odpowiedniej części, mapa lekcji jest na górze strony. A tu masz najważniejsze schematy w jednym miejscu:

        


        
Ściąga: gotowe schematy

        

            

                
Ile jest danych?

                
cin >> n; for (… n razy) cin >> x;
while (cin >> x && x != 0)
while (cin >> a >> b && !(a == 0 && b == 0))
while (cin >> s && s != "KONIEC")
while (cin >> x)          // do końca

                
Wczytanie zawsze w warunku. Nigdy while (!cin.eof()).

            

            

                
Stan strumienia

                
if (cin >> x)    // udało się?
cin.fail()       // nieudane wczytanie
cin.eof()        // czytał za końcem
cin.clear();     // napraw i czytaj dalej

                
Litera zamiast liczby: liczba = 0, znak zostaje na taśmie, strumień zepsuty.

            

            

                
Wiele testów

                
int t; cin >> t;
for (int k = 1; k <= t; k++) {

    cout << "Case #" << k << ": " …
}

                
Globalne liczniki czyść tylko tam, gdzie test ich użył.

            

            

                
Separatory i kolumny

                
if (i > 0) cout << ", ";
if ((i + 1) % k == 0) cout << "\n";
w = to_string(x).size();
cout << setw(w) << x;     // prawo
cout << left << setw(w);  // lewo
string(k, '-')

                
Najpierw policz szerokości, potem wypisuj.

            

            

                
Znak po znaku

                
cin >> c;          // przeskakuje białe
cin.get(c);        // bierze wszystko
while (cin.get(c)) // cały tekst
cin >> ws; cin.peek()  // zajrzyj

Plansza bez spacji: cin >> wiersz albo cin >> t[i][j].

            

            

                
Całe wiersze

                
while (getline(cin, s))
cin >> n; cin.ignore();
getline(cin >> ws, s);
getline(cin, s, ';');

                
ws zjada też spacje na początku wiersza i puste wiersze — czasem to źle.

            

            

                
Rozbieranie wiersza

                
stringstream ss(s);
while (ss >> x)            // liczby
while (getline(ss, p, ',')) // pola
ss >> a >> op >> b
x = x * 10 + (c - '0');

                
Nowy stringstream dla każdego wiersza.

            

            

                
Duże dane

                
ios_base::sync_with_stdio(false);
cin.tie(nullptr);
cout << x << "\n";   // nie endl
// nie mieszaj z printf/scanf

                
Przetwarzaj w locie. Za dużo wyniku? Suma kontrolna.

            

        


        

            Jak rozwiązywać zadania z trudnym formatem
            1) Przeczytaj sekcje „Wejście” i „Wyjście” dwa razy — zanim zaczniesz myśleć o algorytmie. 2) Zapisz format na kartce jako taśmę: gdzie są liczby, gdzie słowa, gdzie całe wiersze, co kończy dane. 3) Wybierz narzędzie: cin >> do kawałków bez spacji, getline do wierszy, stringstream do wnętrza wiersza, cin.get do pojedynczych znaków. 4) Najpierw napisz samo wczytywanie i wypisz to, co wczytałeś — dopiero gdy się zgadza, dopisz obliczenia. 5) Sprawdź przykład z treści znak po znaku: spacje, przecinki, puste wiersze. 6) Pomyśl o największym teście: long long, szybkie wejście, wynik bez endl.

        10 — Częste błędy
        
Częste błędy i dobre praktyki

        

            

                
🔁

                
Wczytanie w warunku

                
while (cin >> x) — a nie while (!cin.eof()) ani „najpierw sprawdź, potem czytaj”. Inaczej ostatnia liczba albo znak końca zostanie policzony o jeden raz za dużo.

            

            

                
🧯

                
Zepsuty strumień milczy

                
Po nieudanym wczytaniu każde kolejne cin >> nic nie robi i nie zgłasza błędu. Jeśli zmienne mają dziwne wartości — sprawdź, czy nie czytasz liczby tam, gdzie stoi słowo. Naprawa: cin.clear().

            

            

                
🧺

                
Wszystko z testu — w teście

                
Sumy, liczniki, rekordy, vectory i zbiory twórz w środku pętli po testach. Zmienna sprzed pętli pamięta poprzedni test — a pierwszy test przechodzi, więc błąd trudno zauważyć.

            

            

                
📥

                
Doczytaj cały test

                
Znalazłeś odpowiedź w połowie testu? Nie przerywaj wczytywania. Nieprzeczytane liczby zostaną wzięte za początek następnego testu i wszystko dalej się rozjedzie.

            

            

                
🧹

                
Czyść tylko to, czego użyłeś

                
Zerowanie wielkiej tablicy przed każdym z tysięcy testów to miliardy operacji. Wyzeruj tylko pola, które test zmienił — albo użyj kontenera tworzonego w teście.

            

            

                
✂️

                
Separator między, nie po

                
Spacja na końcu wiersza jest wybaczana, ale przecinek — nie. Stawiaj separator przed każdym elementem oprócz pierwszego: if (i > 0) cout << ", ";.

            

            

                
📏

                
Szerokość z danych

                
Równa kolumna wymaga znajomości najdłuższego wpisu. Najpierw wczytaj wszystko i policz szerokości (to_string(x).size()), dopiero potem wypisuj z setw.

            

            

                
↵

                
Enter po cin >> n

                
Po cin >> n enter zostaje na taśmie i pierwszy getline zwraca pusty napis. Wyrzuć go przez cin.ignore() albo czytaj getline(cin >> ws, s) — ale ws zje też spacje na początku wiersza.

            

            

                
🔍

                
get nie przeskakuje

                
cin >> c pomija spacje i entery, cin.get(c) bierze każdy znak. Do plansz bez spacji wystarczy cin >>; do tekstu ze spacjami — get albo getline.

            

            

                
🧵

                
Wiersz to nie liczby

                
Gdy w wierszach stoi różna liczba danych, cin >> wymiesza wiersze. Wczytaj wiersz przez getline i rozbierz go stringstreamem.

            

            

                
🐢

                
endl w pętli

                
Każdy endl wysyła bufor na ekran. Przy milionie wierszy to milion wysyłek — kilka razy wolniej niż z "\n". Na zawodach kończ wiersze znakiem "\n".

            

            

                
⚡

                
Dwie linijki — i bez mieszania

                
ios_base::sync_with_stdio(false); cin.tie(nullptr); na początku main. Potem już tylko cin i cout — printf i scanf mogą wtedy wypisać się w złej kolejności.

            

            

                
📂

                
freopen tylko u siebie

                
freopen("we.txt", "r", stdin) ułatwia testowanie na komputerze. Przed wysłaniem do sprawdzarki, która podaje dane na standardowe wejście, usuń tę linijkę albo ją zakomentuj.
