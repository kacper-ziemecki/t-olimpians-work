Kolejka — kto pierwszy, ten pierwszy

W sklepie nikt nie pyta, kto jest najważniejszy: obsługuje się tego, kto przyszedł pierwszy, a nowi klienci stają na końcu. Dokładnie tak działa kolejka — queue w C++. Wkładasz na koniec, wyjmujesz z przodu i nic więcej. Brzmi skromnie, a jednak na kolejce opiera się mnóstwo programów: symulacje kas i drukarek, okna z ostatnimi pomiarami, kolejka z dwoma końcami deque, sprytne maksimum w przesuwanym oknie i najważniejsze — przeszukiwanie wszerz (BFS), które znajduje najkrótszą drogę w labiryncie. W tej lekcji poznasz to wszystko od zera, bardzo powoli, a po każdej części czekają ćwiczenia ze sprawdzarką.

01 — Pierwsza kolejka

Kto pierwszy, ten pierwszy

Zacznijmy od czegoś, co znasz z życia. Stoisz w kolejce w sklepie. Kasjerka obsługuje osobę, która stoi na samym przodzie, a każdy nowy klient staje na samym końcu. Nikt nie wchodzi w środek i nikt nie wychodzi ze środka. Ten, kto przyszedł pierwszy, pierwszy zostanie obsłużony.

Informatycy nazywają tę zasadę FIFO — od angielskiego first in, first out, czyli „pierwszy wszedł, pierwszy wychodzi”. Struktura danych, która działa według niej, to kolejka. Kolejka ma tylko dwa „miejsca pracy”: przód, skąd elementy wychodzą, i koniec, gdzie dołączają nowe.

Kolejka trzech osób. Ala przyszła pierwsza, więc stoi z przodu i to ona będzie obsłużona jako pierwsza. Celina przyszła ostatnia — stoi na końcu. Nowa osoba stanęłaby za Celiną.

Pierwsza kolejka w programie

pierwsza_kolejka.cpp
int main() {
    queue<string> q;
    q.push("Ala");
    q.push("Bartek");
    q.push("Celina");
    cout << "pierwsza: " << q.front() << "\n";
    cout << "ostatnia: " << q.back() << "\n";
    cout << "czeka: " << q.size() << "\n";
    return 0;
}
▶ Wyjście
pierwsza: Ala ostatnia: Celina czeka: 3

Kolejkę tworzy się tak samo jak vector: queue<string> q; to pusta kolejka napisów. W ostrych nawiasach piszesz typ elementów — może to być int, char, string, para, a nawet Twoja własna struktura. Kolejka mieszka w bibliotece <queue>; jeśli zaczynasz program od #include <bits/stdc++.h>, masz ją od razu.

q.push("Ala") wstawia Alę na koniec kolejki — działa jak push_back w vectorze. Po trzech wstawieniach q.front() pokazuje pierwszy element (tego, kto czeka najdłużej), q.back() — ostatni (tego, kto przyszedł przed chwilą), a q.size() mówi, ile elementów jest w kolejce. Samo pokazanie niczego nie zmienia — Ala dalej stoi na przodzie.

To wszystko. Kolejka umie mniej niż vector — i to jest jej zaleta, a nie wada. Nie da się przez pomyłkę wyjąć elementu ze środka ani wepchnąć kogoś przed innych. Każde z tych poleceń działa błyskawicznie, w jednym kroku, niezależnie od tego, czy w kolejce są trzy elementy, czy milion.

pop — pierwszy wychodzi

obsluga.cpp
int main() {
    queue<string> q;
    q.push("Ala");
    q.push("Bartek");
    q.push("Celina");
    cout << "obsluguje: " << q.front() << "\n";
    q.pop();
    cout << "obsluguje: " << q.front() << "\n";
    q.pop();
    cout << "teraz pierwsza: " << q.front() << ", czeka: " << q.size() << "\n";
    return 0;
}
▶ Wyjście
obsluguje: Ala obsluguje: Bartek teraz pierwsza: Celina, czeka: 1

q.pop() usuwa pierwszy element kolejki — Ala została obsłużona i wychodzi. Na przodzie stoi teraz Bartek, więc kolejne q.front() pokazuje już jego. Po drugim pop() zostaje sama Celina.

Zwróć uwagę na kolejność w programie: najpierw odczytujesz pierwszy element (front), a dopiero potem go usuwasz (pop). Tak wygląda obsługa kolejki w prawie każdym programie: „pokaż, kto jest pierwszy — obsłuż go — usuń go z kolejki”.

Skoro wypisanie kolejki ją opróżnia, jak wypisać kolejkę i dalej jej używać? Z lekcji o funkcjach wiesz, że parametr bez & jest kopią. Funkcja wypisz dostaje więc własną kopię kolejki i opróżnia tylko ją — kolejka w main zostaje nietknięta i ma po wszystkim 4 elementy.

        03 — Pary i struktury
        
Kto czeka i z czym — kolejka par i struktur

        

            
W prawdziwej kolejce nie stoją same imiona. Klient ma imię i godzinę przyjścia, kibic — liczbę biletów do kupienia, program — ile pracy mu jeszcze zostało. struct Klient {
    string imie;
    int przyjscie, czas;
};
int main() {
    int n;
    cin >> n;
    queue<Klient> q;
    for (int i = 0; i < n; i++) {
        Klient k;
        cin >> k.imie >> k.przyjscie >> k.czas;
        q.push(k);
    }
    int teraz = 0;
    while (!q.empty()) {
        Klient k = q.front();
        q.pop();
        int start = max(teraz, k.przyjscie);
        teraz = start + k.czas;
        cout << k.imie << ": od " << start << " do " << teraz << ", czekal " << start - k.przyjscie << "\n";
    }
    return 0;
}

        }
    }

        04 — Okno
        
Kolejka jako okno — tylko świeże elementy

        

            
Bardzo często nie interesują nas wszystkie dane, tylko te najświeższe: średnia z ostatnich siedmiu dni, liczba wejść na stronę w ostatniej minucie, wiadomości z ostatnich dziesięciu sekund. Taki fragment danych nazywamy oknem. Okno przesuwa się razem z czasem: nowe elementy do niego wchodzą, a stare wypadają. Kolejka jest do tego stworzona — nowy element dołącza na końcu, a najstarszy stoi z przodu i to on pierwszy wypada.

        05 — Deque
        
Deque — kolejka z dwoma końcami

        

            
Kolejka pozwala dokładać tylko na koniec i zdejmować tylko z przodu. Czasem to za mało: VIP wchodzi na sam początek, ostatnia osoba w kolejce traci cierpliwość i odchodzi, a sprawdzając palindrom, chcemy porównywać litery z obu stron naraz. Do takich zadań C++ ma deque (czytaj „dek”, od angielskiego double-ended queue — kolejka dwustronna). Na obu jej końcach można i dokładać, i zdejmować — zawsze w jednym kroku.

Ciekawostka: queue w C++ to tak naprawdę deque, której schowano część poleceń — w środku trzyma elementy właśnie w deque.             Zapamiętaj
            deque<typ> d; ma cztery szybkie końcówki: push_front, push_back, pop_front, pop_back, oba końce front() i back(), a do tego indeksy d[i], pętlę for i wypełnianie klamrami. Przed zdejmowaniem i podglądaniem sprawdzaj empty(), jak w kolejce. Obrót w lewo: push_back(front) + pop_front, w prawo: push_front(back) + pop_back. Wybieraj queue, gdy elementy tylko wchodzą na koniec i wychodzą z przodu, a deque — gdy potrzebujesz obu końców albo indeksów.

        06 — Maksimum w oknie
        
Maksimum w przesuwanym oknie — kolejka monotoniczna

        

            
Teraz olimpijski klasyk. Mamy ciąg liczb i okno długości k, które przesuwa się po ciągu o jedno miejsce: najpierw obejmuje liczby 1–k, potem 2–(k+1) i tak dalej. Dla każdego okna chcemy znać największą liczbę. Tak liczy się na przykład najwyższą temperaturę w każdym tygodniu albo najlepszy wynik z ostatnich k meczów. Sumę okna umiesz już liczyć z części 4 — ale z maksimum jest kłopot: gdy największa liczba wypada z okna, skąd wiedzieć, która jest następna? Rozwiążemy to krok po kroku, coraz szybciej.

int main() {
    vector<int> a = {1, 3, 1, 2, 0, 5, 4, 1};
    int k = 3;
    for (int i = k - 1; i < (int)a.size(); i++) {
        int mx = a[i];
        for (int j = i - k + 1; j <= i; j++) mx = max(mx, a[j]);
        cout << mx << " ";
    }
    cout << "\n";
    return 0;
}

Najprostszy pomysł: dla każdego okna przejść pętlą po jego k liczbach i znaleźć największą. Okno kończące się na pozycji i to liczby od i − k + 1 do i. Wynik jest dobry: okna 1 3 1, 3 1 2, 1 2 0, 2 0 5, 0 5 4 i 5 4 1 mają maksima 3, 3, 2, 5, 5, 5.

int main() {
    vector<int> a = {12, -1, -7, 8, -15, 30, 16, 28};
    int k = 3;
    queue<int> q;
    for (int i = 0; i < (int)a.size(); i++) {
        if (a[i] < 0) q.push(i);
        if (i >= k - 1) {
            while (!q.empty() && q.front() < i - k + 1) q.pop();
            if (q.empty()) cout << 0 << " ";
            else cout << a[q.front()] << " ";
        }
    }
    cout << "\n";
    return 0;
}

Okno trzymamy w multisecie: nowa liczba wchodzi przez insert, a liczba, która wypada, wychodzi przez s.erase(s.find(x)) — tylko jedna kopia, a nie wszystkie równe (pamiętasz tę pułapkę?).

Kto nigdy nie będzie maksimum?

        

            
Najważniejsza obserwacja całej części. Spójrz na okno 1 2 0 (kończy się na pozycji 4) i na liczbę 5, która za chwilę do niego wejdzie. Gdy piątka wejdzie, liczby 2 i 0 stoją w oknie przed nią. Czy któraś z nich może jeszcze kiedyś być maksimum? Nie. Wypadną z okna wcześniej niż piątka (bo są starsze), a dopóki są w oknie, jest w nim też piątka — większa od nich. Są już bez szans i można o nich zapomnieć.

            
Ogólnie: jeśli w oknie stoi liczba x, a później przychodzi liczba nie mniejsza od niej, to x nigdy już nie będzie maksimum. Zostawiamy więc tylko kandydatów — liczby, za którymi nie ma w oknie nikogo większego ani równego. Kandydaci, czytani od najstarszego do najmłodszego, są ułożeni malejąco: każdy kolejny jest mniejszy od poprzedniego. Dlatego taką deque nazywa się kolejką monotoniczną, a jej pierwszy element to maksimum okna.

int main() {
    vector<long long> v = {-2, 2, 1, -1, -5, -4};
    int n = v.size(), k = 2;
    vector<long long> dp(n);
    deque<int> d;
    dp[0] = v[0];
    d.push_back(0);
    for (int i = 1; i < n; i++) {
        if (d.front() < i - k) d.pop_front();
        dp[i] = v[i] + dp[d.front()];
        while (!d.empty() && dp[d.back()] <= dp[i]) d.pop_back();
        d.push_back(i);
    }
    for (long long x : dp) cout << x << " ";
    cout << "\n";
    return 0;
}

            Zapamiętaj
            Kolejka monotoniczna trzyma w deque indeksy kandydatów na maksimum, a ich wartości maleją od przodu. Dla nowego i: while (!d.empty() && a[d.back()] <= a[i]) d.pop_back();, potem d.push_back(i);, potem if (d.front() <= i - k) d.pop_front();, a maksimum okna to a[d.front()]. Kolejka indeksów działa też dla prostszych pytań o okno (pierwszy ujemny), a okno po tablicy dp — w programowaniu dynamicznym.

Dlaczego pierwsze dojście jest najkrótsze?

        

            
Kolejka ma w każdej chwili prostą budowę: na przodzie stoją liczby z jakiejś warstwy d, a za nimi — już tylko liczby z warstwy d + 1. Wyjmując liczbę z warstwy d, dokładamy na koniec wyłącznie liczby z warstwy d + 1, więc ten porządek się nie psuje. Dlatego liczby wychodzą z kolejki w kolejności rosnących odległości, a liczba, do której pierwszy raz docieramy, dostaje najmniejszą możliwą odległość — dłuższe drogi trafiają do niej później i zastają ją już oznaczoną.

            
To działa dlatego, że każdy ruch kosztuje tyle samo (jedno naciśnięcie). Gdyby różne przyciski kosztowały różnie, zwykły BFS by nie wystarczył — wrócimy do tego przy BFS z deque w części 8. Gdybyś zamiast kolejki użył stosu (następna lekcja), dostałbyś zupełnie inną kolejność i odległości byłyby złe.

        


        
Graf: kto zna kogo

        

            
BFS działa nie tylko na liczbach. Weźmy klasę: osoby są ponumerowane od 1 do n, a niektóre pary się znają. Taki układ to graf — osoby to jego wierzchołki, a znajomości — krawędzie. Sąsiedzi osoby to jej znajomi. Pytanie: przez ilu pośredników plotka od osoby 1 dotrze do każdej innej?

int main() {
    int n = 8;
    vector<pair<int, int>> kraw = {{1, 2}, {1, 3}, {2, 4}, {3, 4}, {3, 7}, {4, 5}, {7, 5}, {5, 6}};
    vector<vector<int>> g(n + 1);

        g[a].push_back(b);
        g[b].push_back(a);
    }
    vector<int> odl(n + 1, -1), skad(n + 1, 0);
    queue<int> q;
    odl[1] = 0;
    q.push(1);
    while (!q.empty()) {
        int v = q.front();
        q.pop();
        for (int u : g[v]) {
            if (odl[u] == -1) {
                odl[u] = odl[v] + 1;
                skad[u] = v;
                q.push(u);
            }
        }
    }
    vector<int> droga;
    for (int x = 6; x != 1; x = skad[x]) droga.push_back(x);
    droga.push_back(1);
    reverse(droga.begin(), droga.end());
    cout << "droga (" << odl[6] << " krokow):";
    for (int x : droga) cout << " " << x;
    cout << "\n";
    return 0;
}

Odległość to nie wszystko — czasem trzeba wypisać samą drogę. Wystarczy jedna dodatkowa tablica: gdy wierzchołek u pierwszy raz dostaje odległość, zapisujemy w skad[u], z którego wierzchołka do niego przyszliśmy. Żeby odtworzyć drogę do 6, idziemy po strzałkach wstecz: 6 → 5 → 4 → 2 → 1. Dostajemy drogę od końca, więc na koniec odwracamy ją przez reverse (lekcja Vector). Uwaga: z 1 do 6 prowadzą też inne drogi długości 4 (na przykład 1 3 4 5 6) — BFS wybiera jedną z nich, zależnie od kolejności sąsiadów na listach. Gdy zadanie pyta o konkretną drogę, zwykle gwarantuje, że najkrótsza jest jedna, albo mówi, którą wybrać.

int main() {
    int n = 9;
    vector<pair<int, int>> kraw = {{1, 2}, {2, 3}, {4, 5}, {6, 7}, {7, 8}, {8, 6}};
    vector<vector<int>> g(n + 1);
    for (auto [a, b] : kraw) {
        g[a].push_back(b);
        g[b].push_back(a);
    }
    vector<bool> byl(n + 1, false);
    int grup = 0;
    for (int s = 1; s <= n; s++) {
        if (byl[s]) continue;
        grup++;
        int rozmiar = 0;
        queue<int> q;
        byl[s] = true;
        q.push(s);
        while (!q.empty()) {
            int v = q.front();
            q.pop();
            rozmiar++;
            for (int u : g[v]) {
                if (!byl[u]) {
                    byl[u] = true;
                    q.push(u);
                }
            }
        }
        cout << "grupa " << grup << " od osoby " << s << ": " << rozmiar << " osob\n";
    }
    return 0;
}

int main() {
    int n, m;
    cin >> n >> m;
    vector<string> g(n);
    for (int i = 0; i < n; i++) cin >> g[i];
    vector<vector<int>> odl(n, vector<int>(m, -1));
    queue<pair<int, int>> q;
    int kw = 0, kk = 0;
    for (int w = 0; w < n; w++) {
        for (int k = 0; k < m; k++) {
            if (g[w][k] == 'S') {
                odl[w][k] = 0;
                q.push({w, k});
            }
            if (g[w][k] == 'K') {
                kw = w;
                kk = k;
            }
        }
    }
    int dw[4] = {-1, 1, 0, 0}, dk[4] = {0, 0, -1, 1};
    while (!q.empty()) {
        auto [w, k] = q.front();
        q.pop();
        for (int i = 0; i < 4; i++) {
            int nw = w + dw[i], nk = k + dk[i];
            if (nw < 0 || nw >= n || nk < 0 || nk >= m) continue;
            if (g[nw][nk] == '#') continue;
            if (odl[nw][nk] != -1) continue;
            odl[nw][nk] = odl[w][k] + 1;
            q.push({nw, nk});
        }
    }
    cout << odl[kw][kk] << "\n";
    return 0;
}

BFS kontra zalewanie z lekcji o rekurencji

        

            
W lekcji o rekurencji zalewałeś wyspy funkcją, która woła się dla czterech sąsiadów. To też przeszukiwanie, ale w głąb (DFS): idzie jak najdalej jednym korytarzem i dopiero potem się cofa. Takie zalewanie dobrze liczy pola wyspy, ale nie daje odległości — kolejność odwiedzin nie ma nic wspólnego z najkrótszą drogą. BFS odwiedza pola warstwami, więc odległości dostajemy za darmo.

            
Jest też druga różnica: głębokość. Zalewanie rekurencyjne na pełnej planszy schodzi w głąb prawie tyle razy, ile jest pól, i na planszy 500 × 500 wywraca stos. BFS nie ma rekurencji — zmierzyliśmy go na pustej planszy 2000 × 2000 (4 miliony pól): 78 ms, a w kolejce stało jednocześnie najwyżej 2000 pól. Rekurencyjne zalewanie tej samej planszy skończyło się błędem SIGSEGV. Na dużych planszach przeszukuj więc kolejką.

int main() {
    vector<string> g = {
        "..#..",
        "###.#",
        ".....",
        ".###."};
    int n = g.size(), m = g[0].size();
    vector<vector<int>> odl(n, vector<int>(m, INT_MAX));
    deque<pair<int, int>> d;
    odl[0][0] = 0;
    d.push_back({0, 0});
    int dw[4] = {-1, 1, 0, 0}, dk[4] = {0, 0, -1, 1};
    while (!d.empty()) {
        auto [w, k] = d.front();
        d.pop_front();
        for (int i = 0; i < 4; i++) {
            int nw = w + dw[i], nk = k + dk[i];
            if (nw < 0 || nw >= n || nk < 0 || nk >= m) continue;
            int koszt = (g[nw][nk] == '#');
            if (odl[w][k] + koszt < odl[nw][nk]) {
                odl[nw][nk] = odl[w][k] + koszt;
                if (koszt == 0) d.push_front({nw, nk});
                else d.push_back({nw, nk});
            }
        }
    }
    cout << "zburzonych scian: " << odl[n - 1][m - 1] << "\n";
    return 0;
}

Zwykły BFS zakłada, że każdy ruch kosztuje tyle samo. Co, jeśli przejście po wolnym polu jest darmowe, a zburzenie ściany kosztuje 1, i pytamy o najmniejszą liczbę burzeń? Ruchy mają wtedy koszt 0 albo 1 — i tu pomaga deque: pole, do którego przeszliśmy za darmo, wkładamy na przód (ma tę samą odległość co bieżące, więc powinno być rozpatrzone od razu), a pole za 1 — na koniec.

                    
Pole może tu dostać lepszą odległość później niż za pierwszym razem, dlatego zamiast „czy odwiedzone” sprawdzamy „czy znaleźliśmy krótszą drogę” (odl[w][k] + koszt < odl[nw][nk]), a na start wpisujemy INT_MAX — „nieskończoność”. To tak zwany BFS 0-1; spotkasz go w bazie zadań. Gdy koszty są dowolne, potrzebny jest algorytm Dijkstry — w lekcji o kopcu.

Ściąga: gotowe schematy

        

            

                
Kolejka

                
queue<int> q;
q.push(x);
if (!q.empty()) {
    int a = q.front();
    q.pop();
}

                
Na koniec przez push, z przodu przez front i pop. Zawsze najpierw empty().

            

            

                
Obsługa po kolei

    auto x = q.front();
    q.pop();
    // obsłuż x
}

Kopię kolejki dostaje funkcja bez &. Pętla po elementach — z rozmiarem zapisanym przed pętlą.

            

            

                
Obrót i kółko

                
for (long long i = 0; i < k % n; i++) {
    q.push(q.front());
    q.pop();
}

                
Pierwszy na koniec. Wyliczanka: k − 1 obrotów i pop tego, kto odpada.

            

            

                
Kolejka par i zegar

Kopia przed pop. Powrót na koniec ze zmienionym licznikiem.

Ostatnie k elementów albo ostatnie T sekund. Gąsienica: zdejmuj z przodu, dopóki suma za duża.

Oba końce w jednym kroku i indeksy. Obrót w prawo: push_front(back) + pop_back.

            Jak rozwiązywać zadania z kolejką
            1) Sprawdź, w jakiej kolejności elementy wychodzą. Wychodzi ten, kto przyszedł najdawniej? — queue. Z obu stron? — deque. Zawsze najświeższy? — to stos z następnej lekcji. 2) Zastanów się, co ma stać w kolejce: sama liczba, para, struktura, a może tylko numer, a dane w vectorze. 3) Przy symulacjach zapisz zegar i ustal, co dzieje się w tej samej chwili (kto pierwszy: wyjście czy przyjście?). 4) Okno: czy granica okna należy do okna? 5) Maksimum albo minimum w oknie — kolejka monotoniczna. 6) „Najmniej ruchów”, „najkrótsza droga”, „po ilu minutach” przy równych kosztach — BFS: ustal, co jest stanem, kto jest sąsiadem i jakie są granice. 7) Zanim wyślesz: pusta kolejka, jeden element, start równy celowi, cel nieosiągalny i największe dane z treści (czy nie użyłeś vectora z erase(begin())?).

🔢

                
Pętla do q.size()

                
for (int i = 0; i < q.size(); i++) q.pop(); przechodzi tylko połowę kolejki, bo rozmiar maleje w trakcie. Zapisz rozmiar przed pętlą: int ile = q.size();.

            

            

                
👀

                
Do środka nie zajrzysz

                
Kolejka nie ma q[i], pętli for (x : q) ani clear(). Wypisuje się ją, opróżniając kopię; czyści — przez q = queue<int>();. Potrzebujesz indeksów — weź deque.

            

            

                
🔁

                
Obrót w dobrej kolejności

                
q.push(q.front()); q.pop(); — najpierw kopia na koniec, potem usunięcie z przodu. Odwrotnie zgubisz element. Przy ogromnym k wykonuj tylko k % n obrotów, k w long long.

            

            

                
🧹

                
Każdy test od pustej kolejki

                
Przy kilku testach w jednym wejściu kolejka z poprzedniego testu nie może przejść na następny. Deklaruj ją wewnątrz pętli po testach albo czyść na początku każdego testu.

            

            

                
🐢

                
Nie vector z erase(begin())

                
Usuwanie pierwszego elementu vectora przesuwa wszystkie pozostałe. Zmierzyliśmy: 30 000 elementów — 1,1 s, 100 000 — 11,5 s. Kolejka robi to samo w ułamku milisekundy.

            

            

                
🔗

                
Referencja do zdjętego elementu

                
auto &x = q.front(); q.pop(); zostawia referencję do elementu, którego już nie ma. Przed pop() rób kopię: auto x = q.front(); albo auto [a, b] = q.front();.

            

            

                
🪟

                
Granica okna

                
„Ostatnie T sekund” to czasem chwile od t − T do t, a czasem od t − T + 1. Od tego zależy, czy w while (q.front() … t - T) stoi <, czy <=. Czytaj treść i sprawdź przykład.

            

            

                
📉

                
Kolejka monotoniczna na indeksach

                
W deque trzymaj indeksy, nie wartości — inaczej nie wiesz, kiedy element wypadł z okna. Przy remisach <= zostawia najpóźniejsze maksimum, a < najwcześniejsze.

            

            

                
🌊

                
BFS: oznaczaj przy wkładaniu

                
Pole dostaje odległość w chwili push, nie pop. Oznaczanie przy zdejmowaniu na pustej planszy 12 × 12 dało 2 704 155 wstawień zamiast 144. Sprawdzaj też granice przed zajrzeniem do tablicy.

            

            

                
⚖️

                
BFS tylko przy równych kosztach

                
Zwykły BFS daje najkrótsze drogi, gdy każdy ruch kosztuje tyle samo. Ruchy za 0 i 1 — BFS z deque (darmowe na przód). Dowolne koszty — algorytm Dijkstry z lekcji o kopcu.

            

        

    


    

        11 — Idź dalej
        
Co dalej?

        
Umiesz już obsługiwać kolejkę: obsługiwać polecenia, obracać, symulować kasy i procesory, trzymać okno czasowe, używać deque z dwoma końcami, liczyć maksimum w przesuwanym oknie i przeszukiwać wszerz liczby, grafy i plansze. Następna lekcja to Stos — stack, czyli struktura „ostatni wszedł, pierwszy wychodzi”, jak stos talerzy. Zobaczysz, że to, co w deque robiliśmy z tyłu (wyrzucanie słabszych kandydatów), jest właśnie stosem, i nauczysz się sprawdzać nawiasy, liczyć wyrażenia i szukać najbliższej większej liczby.
