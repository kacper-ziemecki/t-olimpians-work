Mapy — słownik klucz → wartość

Telefon pamięta numer pod imieniem, słownik — tłumaczenie pod słowem, dziennik — oceny pod nazwiskiem. Do tej pory w C++ szukałeś takich rzeczy pętlą po tablicy albo po vectorze par. Mapa robi to sama: pod dowolnym kluczem — słowem, ogromną liczbą, parą liczb — trzyma wartość i znajduje ją w mgnieniu oka. W tej lekcji poznasz map i unordered_map od zera, krok po kroku: od pierwszego m["Ola"] = 12, przez zliczanie i szukanie najbliższego klucza, aż po sztuczki, którymi rozwiązuje się zadania olimpijskie. Po każdej części czekają ćwiczenia ze sprawdzarką.

01 — Pierwsza mapa

Mapa — słownik: klucz → wartość

Zacznijmy od zadania z życia. Masz książkę telefoniczną: przy każdym imieniu zapisany jest numer. Ktoś pyta: „jaki numer ma Jan?”. Jak to zrobić w C++ tym, co już znasz?

Tak, jak umiesz dotąd: vector par i pętla

ksiazka_vector.cpp
vector<pair<string, string>> ksiazka = {{"Ola", "601-200-300"}, {"Jan", "502-111-222"}, {"Ewa", "733-000-999"}};
string kto = "Jan";
for (auto p : ksiazka)
    if (p.first == kto) cout << p.second << "\n";
▶ Wyjście
502-111-222

Każdy wpis to para: imię (first) i numer (second). Żeby znaleźć numer Jana, pętla przechodzi listę od początku i porównuje imiona.

To działa — ale policz koszt. Przy n wpisach jedno pytanie to do n porównań. Gdy wpisów jest 100 000, a pytań też 100 000, wychodzi 10¹⁰ porównań. Z lekcji o złożoności wiesz, że to dużo za wolno: sekunda wystarcza na mniej więcej 10⁸ prostych operacji.

Potrzebujemy pojemnika, który sam znajduje wpis po imieniu — szybko i bez pisania pętli. Takim pojemnikiem jest mapa.

To samo z mapą

ksiazka_mapa.cpp
map<string, string> ksiazka;
ksiazka["Ola"] = "601-200-300";
ksiazka["Jan"] = "502-111-222";
ksiazka["Ewa"] = "733-000-999";
cout << ksiazka["Jan"] << "\n";
cout << ksiazka.size() << "\n";
▶ Wyjście
502-111-222 3

Przeczytaj deklarację powoli: map<string, string> ksiazka; to mapa, w której kluczem jest string (imię), a wartością też string (numer). Pierwszy typ w nawiasach to zawsze typ klucza, drugi — typ wartości.

ksiazka["Ola"] = "601-200-300"; wygląda jak zapis do tablicy — tylko że „indeksem” jest słowo. Mapa zapamiętuje parę: klucz „Ola” i jego wartość.

ksiazka["Jan"] odczytuje wartość pod kluczem „Jan”. Żadnej pętli — mapa sama wie, gdzie szukać. size() mówi, ile jest kluczy.

Mapa mieszka w bibliotece <map>; bits/stdc++.h już ją zawiera.

Klucz jest jeden — drugi zapis nadpisuje

nadpisywanie.cpp
map<string, int> punkty;
punkty["Ola"] = 5;
punkty["Jan"] = 7;

Co się stanie, gdy zapiszemy coś pod kluczem, który już jest? Mapa nie robi drugiej Oli — klucze się nie powtarzają. Zamiast tego stara wartość (5) zostaje nadpisana nową (9).

Dlatego size() to 2, a nie 3: mamy dwa klucze, Olę i Jana. Tak samo działa zmienna: nowe przypisanie zastępuje starą wartość.

Często właśnie o to chodzi: w mapie zostaje ostatnia zapisana wartość dla każdego klucza — np. ostatni wynik zawodnika albo ostatni stan konta.

Pętla for (auto [imie, p] : wynik) przechodzi wszystkie pary mapy. W każdym obrocie imie to klucz, a p — wartość. (Nazwy w nawiasach kwadratowych wybierasz sam.)

            Jak mapa porównuje napisy
            Napisy są ułożone tak, jak porównuje je C++: znak po znaku, według kodów znaków. Cyfry są przed wielkimi literami, a wielkie litery przed małymi. Dlatego "Zosia" stoi przed "ala" (Z ma mniejszy kod niż a), a "10" przed "9" — bo porównujemy pierwsze znaki: '1' < '9'. Jeśli klucze są liczbami, trzymaj je w mapie jako liczby, nie napisy.

Czy klucz jest w mapie? count — na razie w skrócie

map<string, string> slownik = {{"kot", "cat"}, {"pies", "dog"}, {"dom", "house"}};
string s;
while (cin >> s) {
    if (slownik.count(s)) cout << slownik[s] << " ";
    else cout << "[" << s << "] ";
}
cout << "\n";

Tłumaczymy tekst słowo po słowie. Kłopot: niektórych słów nie ma w słowniku. Zanim sięgniemy po tłumaczenie, pytamy mapę, czy taki klucz w ogóle ma.

Jak szybka jest mapa?

        

            
Mapa nie przegląda wszystkich kluczy po kolei. Trzyma je ułożone w sprytnej strukturze (drzewie — zajrzymy do niego w części 5), dzięki której zapis, odczyt i sprawdzenie klucza wymagają tylko około log₂ n porównań, gdzie n to liczba kluczy:

        

        

            

                
kluczy w mapie (n)pętla po vectorze: porównań na jedno pytaniemapa: porównań na jedno pytanie

                
                    
1 000do 1 000około 10

                    
100 000do 100 000około 17

                    
1 000 000do 1 000 000około 20

                
            

        

        

            
Tak więc 100 000 pytań do książki telefonicznej ze 100 000 wpisami to dla mapy około 1,7 miliona porównań — ułamek sekundy, zamiast 10¹⁰ przy pętli po vectorze. W zapisie z lekcji o złożoności: każda operacja na mapie kosztuje O(log n).

        


        

            Zapamiętaj
            map<K, V> m; — K to typ klucza, V to typ wartości. m[k] = v zapisuje (gdy klucz już jest — nadpisuje). m[k] odczytuje. m.size() to liczba kluczy. Klucze się nie powtarzają i są zawsze posortowane: for (auto [k, v] : m) idzie po nich rosnąco (napisy — tak, jak porównuje je C++). Czy klucz jest? m.count(k) — 1 albo 0. Każda operacja kosztuje O(log n).

Zliczanie — m[x]++ i zero na start

        

            
Najczęstsze zadanie dla mapy brzmi: „policz, ile razy wystąpiło każde…” — każde słowo, każda liczba, każda litera, każdy głos.     return a.first < b.first;
});

find — strzałka na parę

        

            



    

        

        
karnety.cpp

    

    
map<int, int> wejscia = {{101, 2}, {205, 0}};
vector<int> proby = {101, 333, 205, 101, 101};
for (int nr : proby) {
    auto it = wejscia.find(nr);
    if (it == wejscia.end()) cout << nr << ": nieznany karnet\n";
    else if (it->second == 0) cout << nr << ": brak wejsc\n";
    else {
        it->second--;
        cout << nr << ": OK, zostalo " << it->second << "\n";
    }
}




▶ Wyjście

Znasz find ze zbioru: zwraca iterator — „strzałkę” wskazującą znaleziony element — albo end(), gdy elementu nie ma. W mapie jest tak samo, tylko strzałka wskazuje parę: it->first to klucz, a it->second — wartość.

                    
Przez strzałkę możesz wartość także zmieniać: it->second-- odejmuje wejście w samej mapie. Dzięki temu klucz jest szukany tylko raz — przy count i nawiasach szukamy dwa razy (najpierw sprawdzamy, potem odczytujemy).

                    
Zapis it->second to skrót od (*it).second: weź element, na który wskazuje strzałka, i jego drugą część.

        05 — Iteratory
        
Przechodzenie, iteratory i najbliższy klucz

        

            
Mapa trzyma klucze po kolei — i to jest jej druga supermoc, obok szybkiego szukania. Dzięki porządkowi możesz od razu wziąć najmniejszy albo największy klucz, przejść mapę od końca, a przede wszystkim zapytać: „jaki jest najbliższy klucz do x?”, nawet gdy samego x w mapie nie ma. Do tego potrzebujemy iteratorów — tych samych strzałek, które znasz ze zbioru.

Dlaczego zawsze po kolei? Mapa to drzewo




Mapa z kluczami 3, 8, 12, 20, 31, 47, 52 w środku komputera. Na lewo od każdego węzła są mniejsze klucze, na prawo — większe. Szukając 31, idziemy: 20 → w prawo do 47 → w lewo do 31. Trzy kroki zamiast siedmiu.

        

            
W środku mapa jest zrównoważonym drzewem: każdy węzeł trzyma jeden klucz (z wartością), w lewym poddrzewie są klucze mniejsze, a w prawym — większe. Szukanie zaczyna się w korzeniu i przy każdym porównaniu schodzi o piętro niżej, w lewo albo w prawo. Drzewo pilnuje, żeby piętra były mniej więcej równo zapełnione, więc pięter jest około log₂ n — stąd koszt O(log n) każdej operacji.

            
Przechodzenie mapy to obejście drzewa „od lewej do prawej” — dlatego klucze wychodzą posortowane. Strzałka it++ przesuwa się do następnego klucza w tym porządku. Nie musisz pamiętać, jak drzewo działa w środku (to temat na inną lekcję), ale warto wiedzieć, skąd się bierze porządek i szybkość.

map<int, int> temp = {{3, 12}, {10, 15}, {20, 9}};   // dzień → temperatura
vector<int> dni = {1, 7, 15, 30};
for (int d : dni) {
    auto it = temp.lower_bound(d);      // pierwszy pomiar w dniu >= d
    int najlepszy = -1;                 // dzień najbliższego pomiaru
    if (it != temp.end()) najlepszy = it->first;
    if (it != temp.begin()) {
        int p = prev(it)->first;        // ostatni pomiar przed dniem d
        if (najlepszy == -1 || d - p <= najlepszy - d) najlepszy = p;
    }
    cout << d << ": " << temp[najlepszy] << "\n";
}

Na ogromnej planszy stoją gońce. Ile par stoi na wspólnej przekątnej (nie przejmujemy się, czy ktoś stoi pomiędzy)? Sprawdzanie wszystkich par to O(n²).

                    
Sztuczka: na jednej przekątnej „w dół w prawo” wszystkie pola mają tę samą różnicę x − y, a na przekątnej „w dół w lewo” — tę samą sumę x + y. Zamiast pary współrzędnych liczymy więc w mapie różnice i sumy. Grupa k gońców na jednej przekątnej daje k · (k − 1) / 2 par.

                    
Tu (1, 1) i (3, 3) mają różnicę 0 — jedna para. (3, 3), (2, 4) i (5, 1) mają sumę 6 — trzy pary. Razem 4. Taki „przekształcony klucz” to częsty pomysł na olimpiadzie: przekształć warunek tak, żeby pasujące rzeczy miały równy klucz.

                

            

        


        

            Po czym poznać zadanie na mapę?

            Zdarzenia: zmiana[a]++; zmiana[b]--; (dla dni włącznie: zmiana[b + 1]--), potem przejście z bieżącą sumą — maksimum to najwięcej naraz, a t - poprzedni przy spełnionym warunku to długość. Pytania „w chwili x”: mapa stanów i prev(upper_bound(x)). Historia wielu rzeczy: map<nazwa, map<czas, wartość>>. Symulacja z pytaniami z dwóch stron: dwie mapy, każda zmiana w obu. Baza zadań: mapy w praktyce

        

            
Znasz już cały warsztat: mapę jako słownik i licznik, sprawdzanie klucza bez pułapki nawiasów, wartości złożone, iteratory i najbliższy klucz, mapę jako pamięć przeszłości, unordered_map i wybór struktury, a na koniec zdarzenia na osi i symulacje z kilkoma mapami.             1) Zapytaj: co jest kluczem, a co wartością?         10 — Częste błędy
        
Częste błędy i dobre praktyki

        

            

                
🪤

                
Pułapka nawiasów

                
m[k] dla brakującego klucza dopisuje go z wartością zerową. Sprawdzanie przez if (m[k] == 0) zaśmieca mapę: rośnie size(), a pętla po mapie widzi klucze-widma. Do sprawdzania służą count i find.

            

            

                
0️⃣

                
Zero na start — wtedy, gdy pasuje

                
Zero z nawiasów to wygoda przy liczeniu i sumowaniu: m[x]++, m[x] += v. Ale przy minimum, rekordzie czy „pierwszej pozycji” zero kłamie — pierwszy wpis dla klucza zapisz osobno, po sprawdzeniu count.

            

            

                
🔑

                
Klucza nie zmienisz

                
Klucz decyduje o miejscu w mapie, więc jest stały — zmieniać można tylko wartość. „Zmiana klucza” to dwie operacje: zapamiętaj wartość, erase stary klucz, wstaw nowy.

            

            

                
🔗

                
Bez & zmieniasz kopię

                
for (auto [k, v] : m) v++; nie zmienia mapy — pracuje na kopiach. Zmieniasz przez referencję: for (auto &[k, v] : m), auto &lista = m[k]; albo przez strzałkę it->second.

            

            

                
✂️

                
erase w pętli

                
Po m.erase(it) strzałka it jest nieważna — it++ po niej to błąd. Pisz it = m.erase(it); (erase oddaje następny element), a it++ tylko wtedy, gdy nic nie usuwasz.

            

            

                
🧭

                
end() to nie element

                
m.end() stoi za ostatnią parą — nie odczytuj z niego niczego. Przed prev(it) sprawdź, czy it != m.begin(), a przed it->second — czy it != m.end().

            

            

                
📚

                
Inna kolejność? vector i sort

                
Mapa zawsze idzie według klucza. Ranking według wartości, kolejność wpisywania, dni tygodnia — przepisz pary do vectora i posortuj lambdą albo trzymaj osobny vector z kolejnością.

            

            

                
🔤

                
Liczby jako liczby

                
W mapie z kluczem string napis "10" stoi przed "9", a "Zosia" przed "ala". Jeśli klucz jest liczbą — niech ma typ liczbowy (int, long long), a daty zapisuj jako parę (miesiąc, dzień).

            

            

                
🧺

                
Mapa w teście

                
Przy wielu testach twórz mapę w środku pętli po testach (albo wywołuj clear()). Mapa sprzed pętli pamięta liczniki z poprzedniego testu — a pierwszy test przechodzi, więc błąd trudno zauważyć.

            

            

                
⚖️

                
map, unordered_map czy tablica?

                
Potrzebujesz kolejności, najmniejszego klucza albo lower_bound — map. Tylko „jest / ile / gdzie” przy wielkich danych — unordered_map z reserve. Klucze to małe liczby (do kilku milionów) — zwykła tablica.

            

            

                
🎲

                
unordered_map nie ma porządku

                
Kolejność przechodzenia unordered_map jest przypadkowa i może się zmienić po dopisaniu klucza. Remis „wcześniejszy alfabetycznie” rozstrzygaj warunkiem w kodzie, a nie kolejnością pętli.

            

            

                
🧠

                
Mapa zamiast drugiej pętli

                
„Dla każdego elementu znajdź wcześniejszy, który…” — to zwykle mapa przeszłości: ile razy była wartość, gdzie pierwszy raz wystąpiła suma prefiksowa. Jedno przejście O(n log n) zamiast pętli w pętli O(n²).

            

            

                
🧮

                
long long w licznikach

                
Liczba par z k elementów to k · (k − 1) / 2 — przy 10⁵ to 5 · 10⁹, więcej niż mieści int. Sumy w mapach, liczby par i iloczyny trzymaj w long long.
