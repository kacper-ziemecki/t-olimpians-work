01 — Pierwsze sortowanie

sort — wszystko po kolei jedną linijką

Zaczynamy spokojnie, od tego, co już trochę znasz. W tej części dokładnie zobaczysz, co znaczy „posortować”, jak sortować vector, zwykłą tablicę i napis, w jakiej kolejności ustawiają się słowa (to potrafi zaskoczyć!), jak posortować tylko kawałek i jak sprawdzić, czy coś już jest posortowane.

Co to znaczy „posortować”?

Posortować to ustawić elementy po kolei: od najmniejszego do największego. Robisz to codziennie, nawet o tym nie myśląc — gdy ustawiasz się w szeregu według wzrostu, gdy układasz karty w ręce albo gdy szukasz swojego nazwiska na liście, która jest ułożona alfabetycznie. sort na vectorze — pierwszy pełny program

Polecenie sort dostaje dwie strzałki z lekcji o vectorze: v.begin() — strzałkę na pierwszy element, i v.end() — strzałkę za ostatnim. Sortuje wszystko od pierwszej strzałki (wliczamy) do drugiej (nie wliczamy), czyli cały vector. Mieszka w bibliotece <algorithm>, ale <bits/stdc++.h> ma ją w środku, więc nic nie dopisujesz.

pierwszy_sort.cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<int> v(n);
    for (auto &x : v) cin >> x;      // 1. wczytaj

    sort(v.begin(), v.end());        // 2. posortuj

    for (auto x : v) cout << x << " ";   // 3. wypisz
    cout << "\n";
    return 0;
}

Każdy program z sortowaniem ma te same trzy kroki: wczytaj, posortuj, wypisz (albo policz coś na posortowanych danych).

Zwróć uwagę: sort nie wypisuje niczego i nie tworzy nowego vectora. Przestawia elementy w środku tego samego vectora v. Po tej linijce v jest po prostu ułożony.

Liczby ujemne nie są problemem: −3 jest mniejsze od 1, więc stoi na początku. Dwie jedynki stanęły obok siebie.

sort na zwykłej tablicy: t i t + n

Zwykła tablica nie ma begin() ani end(), ale ma coś równie dobrego: sama nazwa tablicy t działa jak strzałka na element t[0], a t + n — jak strzałka na miejsce numer n, czyli tuż za ostatnim z n elementów. Dlatego piszesz sort(t, t + n) — dokładnie jak w lekcji o parach.

Tablica ma 5 elementów (numery 0–4). t pokazuje pudełko 0, a t + 5 — miejsce za ostatnim. sort(t, t + 5) sortuje wszystkie pięć.

cout << "\n";

Drugi przykład to częsty zwyczaj na olimpiadzie: elementy trzyma się w pudełkach od 1 do n, a pudełko 0 zostaje puste. Wtedy sortujesz od u + 1 (pudełko 1) do u + n + 1 (miejsce za pudełkiem n).

Najważniejsza zasada jest ta sama co przy vectorze: druga strzałka pokazuje miejsce, którego już nie bierzemy.

t + n, a nie t + n - 1 Częsty błąd: sort(t, t + n - 1). Wygląda logicznie („ostatni element ma numer n − 1”), ale druga strzałka nie jest wliczana — więc ostatni element zostaje poza sortowaniem i stoi tam, gdzie stał. Program działa „prawie” dobrze, co jest najgorszym rodzajem błędu. Zapamiętaj: sort(t, t + n) dla pudełek 0..n−1 i sort(t + 1, t + n + 1) dla pudełek 1..n.

Słowa po kolei: porządek słownikowy

Vector napisów sortuje się tak samo: sort(s.begin(), s.end()). Słowa ustawią się w porządku słownikowym — tak jak w słowniku albo w dzienniku. Pamiętasz z lekcji o napisach, jak C++ porównuje dwa napisy? Idzie od lewej, litera po literze, i rozstrzyga na pierwszej różnicy. Gdy jedno słowo jest początkiem drugiego, krótsze stoi wcześniej. Zobacz, co z tego wynika:

vector<string> s = {"kotek", "ala", "kot", "Zosia", "ania", "10", "9"};
sort(s.begin(), s.end());

Liczby trzymaj w int, nie w string Jeśli chcesz sortować liczby według wartości, wczytuj je do int albo long long. Napis „100” stanie przed „20”, a „-5” przed „-10”, bo napisy porównują się znak po znaku, a nie według wartości.

Litery w napisie

Napis to w środku rząd znaków — prawie jak vector. Dlatego sort(s.begin(), s.end()) ustawia po kolei litery jednego napisu. Znaki porównują się po kodach, więc spacje (kod 32) idą na sam początek, potem cyfry, wielkie litery i na końcu małe.

litery.cpp
string s = "banan";
sort(s.begin(), s.end());
cout << s << "\n";

string t = "Ala ma kota";
sort(t.begin(), t.end());
cout << "[" << t << "]\n";

Sortowanie liter ma piękne zastosowanie: anagramy. Dwa słowa są anagramami, gdy składają się z tych samych liter, tylko w innej kolejności — jak „kot” i „tok”. Po posortowaniu liter oba zamieniają się w to samo: „kot”. Wystarczy więc posortować litery obu słów i porównać wyniki przez ==.

anagramy.cpp
string a = "kajak", b = "jakak", c = "kajko";
string sa = a, sb = b, sc = c;      // kopie — oryginały zostają
sort(sa.begin(), sa.end());
sort(sb.begin(), sb.end());
sort(sc.begin(), sc.end());
cout << sa << " " << sb << " " << sc << "\n";
cout << a << " i " << b << ": " << (sa == sb) << "\n";
cout << a << " i " << c << ": " << (sa == sc) << "\n";

Tylko kawałek

sort zmienia vector — czasem potrzebna kopia

Po sort pierwotna kolejność jest stracona — vector nie pamięta, jak wyglądał wcześniej. Czasem to nie szkodzi (gdy pytają tylko o ułożone liczby), ale czasem potrzebujesz obu wersji: na przykład, żeby porównać, które elementy stały już na swoich miejscach. Wtedy robisz kopię: vector<int> w = v; i sortujesz kopię.

kopia.cpp
vector<int> v = {3, 1, 2, 4, 5};
vector<int> w = v;              // kopia
sort(w.begin(), w.end());
int naMiejscu = 0;
for (int i = 0; i < (int)v.size(); i++) {
    if (v[i] == w[i]) naMiejscu++;
}
cout << naMiejscu << "\n";

Czy to już jest posortowane?

Ciąg jest posortowany niemalejąco wtedy, gdy każde dwa sąsiednie elementy stoją dobrze: v[i] <= v[i + 1]. Wystarczy więc przejść po sąsiadach i poszukać pary, w której lewy jest większy od prawego. Jeśli takiej pary nie ma — ciąg jest posortowany. To samo robi gotowe polecenie is_sorted(v.begin(), v.end()), które zwraca true albo false.

czy_posortowane.cpp
vector<int> v = {1, 3, 3, 8, 6, 9};
int zle = -1;                     // numer pierwszej złej pary
for (int i = 0; i + 1 < (int)v.size(); i++) {
    if (v[i] > v[i + 1]) {
        zle = i;
        break;
    }
}
if (zle == -1) cout << "posortowane\n";
else cout << "zle przy numerze " << zle << ": " << v[zle] << " > " << v[zle + 1] << "\n";
cout << is_sorted(v.begin(), v.end()) << "\n";
▶ Wyjście
zle przy numerze 3: 8 > 6 0

Warunek pętli to i + 1 < v.size(), bo porównujemy v[i] z v[i + 1] — ostatnie i musi mieć jeszcze sąsiada po prawej.

Uwaga na znak: posortowane niemalejąco to v[i] <= v[i + 1], więc „źle” to v[i] > v[i + 1]. Dwa równe elementy obok siebie są w porządku.

is_sorted wypisane przez cout daje 1 (tak) albo 0 (nie) — jak każdy bool.

Inne typy działają tak samo

sort potrafi ustawić po kolei wszystko, co da się porównać znakiem <: liczby long long i double, znaki char, napisy, a nawet pary — te porównują się najpierw po first, a przy remisie po second, jak w lekcji o parach. Wrócimy do nich w części 6.

02 — Malejąco i miejsca w porządku

Malejąco, k-ty element i mediana

W rankingach zwykle chcemy odwrotnie: najlepszy wynik na górze. W tej części poznasz trzy sposoby sortowania malejąco i zobaczysz, że w posortowanym vectorze każde pytanie w stylu „kto jest k-ty?” albo „jaki wynik jest środkowy?” ma odpowiedź pod konkretnym numerem pudełka.

Sposób 1: sort, a potem reverse

Ten sposób znasz z lekcji o vectorze: najpierw ustawiasz rosnąco, a potem odwracasz kolejność poleceniem reverse. Najmniejszy element ląduje na końcu, największy — na początku.

sort_reverse.cpp
vector<int> v = {4, 9, 1, 7, 3};
sort(v.begin(), v.end());        // 1 3 4 7 9
reverse(v.begin(), v.end());     // 9 7 4 3 1
for (auto x : v) cout << x << " ";
cout << "\n";

Co się stanie, gdy dasz sort strzałki od tyłu? sort ustawi elementy rosnąco w kolejności, w jakiej je widzi, czyli od prawej do lewej. Jeśli patrząc od prawej liczby rosną, to patrząc normalnie, od lewej — maleją. Jedna linijka i gotowe: sort(v.rbegin(), v.rend()).

Sposób 3: gotowa reguła greater

sort może dostać trzeci argument: regułę, która mówi, który z dwóch elementów ma stać wcześniej. Domyślna reguła to „mniejszy przed większym”. C++ ma gotową regułę odwrotną: greater<int>() — „większy przed mniejszym”. W nawiasach ostrych piszesz typ elementów vectora. O własnych regułach będzie cała część 5.

greater.cpp
vector<int> v = {4, 9, 1, 7, 3};
sort(v.begin(), v.end(), greater<int>());
for (auto x : v) cout << x << " ";
cout << "\n";
vector<string> s = {"ola", "ewa", "zosia", "ala"};
sort(s.begin(), s.end(), greater<string>());
for (auto x : s) cout << x << " ";
cout << "\n";

Uwaga na typ: dla vector<long long> piszesz greater<long long>(), dla napisów greater<string>(). Nawiasy () na końcu są obowiązkowe.

Mediana — wartość środkowa

Mediana to liczba, która po posortowaniu stoi w samym środku: połowa liczb jest od niej mniejsza (albo równa), połowa — większa (albo równa). Dlaczego nie średnia? Bo średnią potrafi zepsuć jedna dziwna liczba. Pięć osób zarabia 2000, 2100, 2300, 2500 i 50 000 zł. Średnia to 11 780 zł — nikt tyle nie zarabia! Mediana to 2300 zł i ona naprawdę mówi, ile zarabia „typowa” osoba.

Gdy n jest nieparzyste, środek jest jeden: v[n / 2] (dzielenie całkowite). Dla n = 5 to v[2] — przed nim stoją dwa elementy i za nim dwa. Gdy n jest parzyste, środki są dwa: v[n / 2 - 1] i v[n / 2]. Wtedy medianą zwykle nazywa się ich średnią — ale zawsze czytaj, co dokładnie mówi zadanie.

Najlepsze k: suma i próg

Po posortowaniu k największych liczb stoi na końcu, w pudełkach od n − k do n − 1. Suma k najlepszych wyników to po prostu suma tego kawałka. A teraz pytanie podchwytliwe: do finału przechodzi k najlepszych zawodników, ale remisy na granicy też przechodzą. Ile osób awansuje? Próg to wynik k-tego najlepszego, czyli v[n - k], a awansują wszyscy z wynikiem co najmniej takim jak próg — może ich być więcej niż k.

prog.cpp
vector<int> v = {70, 85, 90, 85, 60, 85, 95};
int n = v.size(), k = 3;
sort(v.begin(), v.end());           // 60 70 85 85 85 90 95
long long suma = 0;
for (int i = n - k; i < n; i++) suma += v[i];
int prog = v[n - k];
int ile = 0;
for (auto x : v) {
    if (x >= prog) ile++;
}
cout << "suma " << k << " najlepszych: " << suma << "\n";
cout << "prog: " << prog << ", awansuje: " << ile << "\n";

03 — Grupy i sąsiedzi

Po sortowaniu: równe obok siebie, najbliżsi obok siebie

Sortowanie robi z danymi dwie bardzo pożyteczne rzeczy. Po pierwsze: równe wartości stają obok siebie, więc łatwo je policzyć i pogrupować. Po drugie: liczby bliskie sobie też stają obok siebie, więc najmniejszą różnicę znajdziesz, patrząc tylko na sąsiadów. W tej części wykorzystasz obie te rzeczy.

Ile jest różnych liczb?

W posortowanym ciągu nowa wartość zaczyna się dokładnie tam, gdzie v[i] != v[i - 1] — element różni się od swojego lewego sąsiada. Pierwszy element zawsze zaczyna grupę. Liczba różnych wartości to więc 1 plus liczba miejsc, w których coś się zmienia.

sort(v.begin(), v.end());          // 2 2 5 5 5 8
int roznych = 1;
for (int i = 1; i < (int)v.size(); i++) {
    if (v[i] != v[i - 1]) roznych++;
}
cout << roznych << "\n";

Grupa po grupie: wartość i ile razy

Teraz chcemy wypisać każdą wartość razem z liczbą jej wystąpień. Użyjemy schematu z dwoma numerami: i to początek grupy, a j biegnie w prawo, dopóki widzi tę samą wartość. Gdy j się zatrzyma, grupa to pudełka od i do j − 1, ma j − i elementów, a następna grupa zaczyna się w j — więc i przeskakuje na j.

vector<int> v = {5, 2, 8, 2, 5, 5};
sort(v.begin(), v.end());
int n = v.size();
int i = 0;
while (i < n) {
    int j = i;
    while (j < n && v[j] == v[i]) j++;
    cout << v[i] << " x" << j - i << "\n";
    i = j;                          // skok na początek następnej grupy
}

Najczęstsza wartość

Najczęstsza wartość to ta z najdłuższą grupą. Przechodzimy grupa po grupie i zapamiętujemy najlepszą. Jeśli kilka wartości remisuje, zwykle zadanie każe wybrać najmniejszą — a ponieważ grupy idą od najmniejszych wartości, wystarczy zmieniać zapamiętaną wartość tylko przy ściśle dłuższej grupie (znak >, nie >=).

najczestsza.cpp
vector<int> v = {4, 7, 4, 1, 7, 9, 7, 4};

Najbliżsi sąsiedzi

Przy prostej drodze stoją domy. Które dwa stoją najbliżej siebie? Naiwnie: sprawdź każdą parę domów — przy 100 000 domów to 5 miliardów par, o wiele za dużo. Sprytnie: posortuj pozycje. Dwa najbliższe domy na pewno staną wtedy obok siebie — wystarczy porównać tylko sąsiadów: v[i + 1] - v[i].

Dlaczego? Weźmy trzy domy a ≤ b ≤ c. Odległość od a do c to (b − a) + (c − b) — jest co najmniej tak duża jak każda z dwóch krótszych. Dom, który stoi „pomiędzy”, zawsze jest bliżej. Dlatego para nie-sąsiadów nigdy nie wygra z parą sąsiadów.

sasiedzi.cpp
vector<int> v = {40, 7, 22, 31, 12, 60};
sort(v.begin(), v.end());           // 7 12 22 31 40 60
int najmniej = v[1] - v[0];
int najwiecej = v[1] - v[0];
for (int i = 0; i + 1 < (int)v.size(); i++) {
    int d = v[i + 1] - v[i];
    najmniej = min(najmniej, d);
    najwiecej = max(najwiecej, d);
}
cout << "najblizej: " << najmniej << "\n";
cout << "najwieksza przerwa: " << najwiecej << "\n";

04 — Pod maską

Jak sortuje komputer? Sortowanie ręcznie

sort to gotowe narzędzie i w zadaniach będziesz go używać prawie zawsze. Mimo to warto raz zobaczyć, jak można sortować samemu. Po pierwsze — to świetny trening pętli, ifów i swap. Po drugie — zadania czasem pytają o przebieg konkretnego algorytmu: „ile zamian zrobi sortowanie bąbelkowe?”. Po trzecie — zrozumiesz, dlaczego jedne sposoby są szybkie, a inne wolne.

Poznasz cztery metody. Przy każdej jest animacja: klikaj „Krok ▸”, żeby oglądać algorytm ruch po ruchu, albo „Odtwórz”, żeby leciał sam. Pod słupkami jest opis tego, co dzieje się w danym kroku, i numery pudełek. „Nowe liczby” losuje inne dane — sprawdź, czy przewidzisz następny ruch!

Sortowanie przez wybieranie

Pomysł jest taki, jak przy ustawianiu szeregu na WF-ie. Wybierz najniższą osobę i postaw ją na pierwszym miejscu. Z pozostałych wybierz najniższą i postaw na drugim. I tak dalej. Po angielsku: selection sort.

W programie: w rundzie numer i szukamy najmniejszego elementu w kawałku od i do końca (zapamiętujemy jego numer m) i zamieniamy go z elementem v[i]. Po tej rundzie pudełko i jest gotowe i już go nie ruszamy.

Sortowanie przez wybieranie — animacja
Animacja działa po włączeniu JavaScriptu.
wybieranie.cpp
vector<int> v = {5, 2, 4, 1, 3};
int n = v.size();
for (int i = 0; i < n - 1; i++) {
    int m = i;                      // numer najmniejszego od i do końca
    for (int j = i + 1; j < n; j++) {
        if (v[j] < v[m]) m = j;
    }
    swap(v[i], v[m]);               // najmniejszy na miejsce i
    for (auto x : v) cout << x << " ";
    cout << "\n";
}

Sortowanie bąbelkowe

Tu porównujemy tylko sąsiadów. Idziemy od lewej do prawej i gdy dwaj sąsiedzi stoją w złej kolejności (lewy większy od prawego), zamieniamy ich miejscami. Po jednym takim przejściu — rundzie — największy element na pewno „wypłynie” na sam koniec, jak bąbelek powietrza w wodzie. Stąd nazwa: bubble sort. W następnej rundzie na przedostatnie miejsce wypłynie drugi największy, i tak dalej.

Sortowanie bąbelkowe — animacja
Animacja działa po włączeniu JavaScriptu.
babelkowe.cpp
vector<int> v = {5, 1, 4, 2, 8};
int n = v.size();

for (int runda = 0; runda < n - 1; runda++) {
    bool bylaZamiana = false;
    for (int j = 0; j + 1 < n - runda; j++) {

            swap(v[j], v[j + 1]);

Sortowanie przez wstawianie

Tak układasz karty w ręce: lewa część ręki jest już ułożona, bierzesz kolejną kartę i wsuwasz ją w odpowiednie miejsce, przesuwając większe karty w prawo. Po angielsku: insertion sort.

W programie: dla każdego i od 1 do n − 1 zapamiętujemy x = v[i]. Potem idziemy w lewo od j = i − 1 i dopóki v[j] > x, przesuwamy v[j] o jedno pudełko w prawo. Gdy natrafimy na element nie większy od x (albo dojdziemy do początku), x wskakuje w zwolnione miejsce j + 1.

Tę metodę znasz z lekcji o tablicach, choć może nie wiedziałeś, że to sortowanie. Gdy wartości są małe — oceny 1–6, wiek 0–120, cyfry 0–9 — w ogóle nie trzeba ich porównywać. 05 — Własna reguła

Sortowanie po swojemu: własna reguła porównania

Do tej pory sortowaliśmy „normalnie”: liczby od najmniejszej, słowa alfabetycznie. A co, jeśli zadanie każe ustawić liczby według ostatniej cyfry? Albo słowa od najkrótszego? Albo najpierw parzyste, potem nieparzyste? Wtedy dajesz sort własną regułę. To najważniejsza nowa umiejętność tej lekcji, więc pójdziemy bardzo powoli.

Reguła odpowiada na jedno pytanie

Wyobraź sobie, że sort to sędzia, który ustawia zawodników w szeregu. Sam nie wie, kto powinien stać wcześniej — za każdym razem pyta Twoją regułę o dwa elementy, a i b:

„Czy a ma stać PRZED b?”

Reguła odpowiada true (tak) albo false (nie). Sędzia zadaje to pytanie wiele razy, o różne pary, i na podstawie odpowiedzi ustawia wszystkich. Domyślna reguła sort to po prostu a < b: „a stoi przed b, gdy a jest mniejsze”. Dlatego bez reguły dostajesz kolejność rosnącą.

Jak zapisać regułę: lambda

Regułę piszemy jako trzeci argument sort, w specjalnym zapisie zwanym lambdą. Lambda to mały kawałek programu bez nazwy, napisany dokładnie w miejscu, w którym jest potrzebny. Oto reguła „większy przed mniejszym”:

lambda_wzor.cpp
sort(v.begin(), v.end(), [](int a, int b) { return a > b; });

Nawiasy kwadratowe mówią: „tu zaczyna się reguła”. Na razie zostawiamy je puste.

(int a, int b)

Dwa porównywane elementy. Ich typ to typ elementów vectora: dla vector<int> piszesz int, dla napisów string.

{ return a > b; }

Odpowiedź na pytanie „czy a przed b?”. return oddaje ją sędziemu — znasz to słowo z return 0; w main.

Sztuczka do sprawdzania reguły: weź dwie konkretne liczby, np. a = 8 i b = 2, i zapytaj, co zwróci reguła. 8 > 2 to true, więc 8 stanie przed 2. Zgadza się z tym, co chcesz?

Według ostatniej cyfry — i co z remisami?

Ostatnia cyfra liczby to x % 10 (dla liczb nieujemnych). Reguła „mniejsza ostatnia cyfra wcześniej” wygląda tak: return a % 10 < b % 10;. Ale co, jeśli dwie liczby mają tę samą ostatnią cyfrę, jak 21 i 11? Reguła odpowiada wtedy „nie” w obie strony: ani 21 nie jest przed 11, ani 11 przed 21. Dla sędziego to remis — i sort może ustawić takie liczby w dowolnej kolejności. Nie ma żadnej gwarancji, że zostaną tak, jak były na wejściu.

Dlatego dobra reguła prawie zawsze ma drugie kryterium, które rozstrzyga remisy: „gdy ostatnie cyfry są takie same, mniejsza liczba wcześniej”.

ostatnia_cyfra.cpp
vector<int> v = {23, 15, 42, 11, 30, 21, 5};
sort(v.begin(), v.end(), [](int a, int b) {
    if (a % 10 != b % 10) {
        return a % 10 < b % 10;   // różne cyfry — decyduje cyfra
    }
    return a < b;                 // remis — decyduje cała liczba
});
for (auto x : v) cout << x << " ";
cout << "\n";

[&] — reguła, która widzi zmienne z main

Teraz chcemy sortować według odległości od liczby k, którą wczytaliśmy w main: abs(a - k). Problem: lambda z pustymi nawiasami [] nie widzi zmiennych z main — kompilator zgłosi błąd, że nie zna k. Najpierw parzyste, potem nieparzyste

Chcemy dwie grupy: najpierw wszystkie parzyste rosnąco, potem wszystkie nieparzyste rosnąco. Zapisujemy w zmiennych bool, czy a i b są parzyste. Jeśli jedna jest parzysta, a druga nie — wcześniej stoi ta parzysta. Jeśli obie są tego samego rodzaju — mniejsza wcześniej.

parzyste.cpp
vector<int> v = {7, 4, -3, 10, 1, -6, 8};
sort(v.begin(), v.end(), [](int a, int b) {
    bool pa = (a % 2 == 0);
    bool pb = (b % 2 == 0);
    if (pa != pb) return pa;    // parzysta przed nieparzystą
    return a < b;
});
for (auto x : v) cout << x << " ";
cout << "\n";

Linijka return pa; wymaga chwili namysłu. Wykonuje się tylko wtedy, gdy a i b są różnego rodzaju. Jeśli a jest parzyste (pa = true), to b nie jest — odpowiadamy „tak, a przed b”. Jeśli a jest nieparzyste (pa = false), to b jest parzyste — odpowiadamy „nie”.

Warunek a % 2 == 0 działa też dla liczb ujemnych. Gdybyś napisał a % 2 == 1, liczba −3 nie zostałaby uznana za nieparzystą, bo −3 % 2 to −1.

Żelazna zasada: dla równych — false

Reguła musi spełniać jeden warunek, którego kompilator nie sprawdzi za Ciebie: gdy pytasz o dwa elementy „równe” dla tej reguły, odpowiedź musi brzmieć false. W szczególności element nigdy nie może stać „przed samym sobą”. Dlatego w regule piszesz < albo >, a nigdy <= ani >=.

06 — Kilka kryteriów

Kilka kryteriów naraz: pary, sztuczka z minusem i stable_sort

Prawdziwe rankingi rzadko mają jedno kryterium. W konkursie wygrywa ten, kto ma więcej punktów, a przy remisie — ten, kto był szybszy. W dzienniku uczniowie stoją według nazwisk, a przy tych samych nazwiskach — według imion. W tej części ułożysz dane według dwóch i trzech kryteriów naraz.

Sztuczka z minusem

Ranking zawodów: więcej punktów wyżej (malejąco), a przy remisie krótszy czas wyżej (rosnąco). Pary porównują oba pola rosnąco, więc jak zrobić jedno malejąco? Sztuczka z lekcji o parach: zamiast punktów zapisz minus punkty. Rosnąco po −punktach to to samo co malejąco po punktach: −90 < −75 < −60. Przy wypisywaniu znowu zmieniasz znak.

        mp = -punkty;

Reguła dla par

Trzy kryteria

Ranking olimpiady: więcej punktów wyżej; przy remisie mniej prób wyżej; przy remisie i w tym — alfabetycznie. Trzy pola trzymamy w parze par: pair<string, pair<int, int>>, czyli (imię, (punkty, próby)). Reguła ma teraz dwa ify i ostatni return — schodki, jak w słowniku.

stable_sort — remisy zostają w kolejności z wejścia

Pamiętasz z części 5: gdy reguła mówi „remis”, sort może ustawić takie elementy w dowolnej kolejności. Czasem jednak zadanie wymaga: „przy remisie zachowaj kolejność z wejścia”. Wtedy zamiast sort piszesz stable_sort — z tymi samymi argumentami. Stabilne sortowanie gwarantuje, że elementy równe dla reguły zostaną w takiej kolejności względem siebie, w jakiej były.

Przykład: lista uczniów w kolejności zapisów, każdy z numerem klasy. Chcemy pogrupować ich według klas, ale w każdej klasie zostawić kolejność zapisów. Reguła porównuje tylko klasy — a resztę załatwia stabilność.

});

Punkty na płaszczyźnie

Punkty (x, y) to pary, więc sort bez reguły ustawi je „od lewej”: według x, a przy tym samym x — według y. Inne częste życzenie to sortowanie według odległości od początku układu (0, 0). Odległość to pierwiastek z x² + y², ale do porównywania pierwiastek nie jest potrzebny: większa odległość to większe x² + y². Liczymy więc same kwadraty — na liczbach całkowitych, bez błędów zaokrągleń.

punkty.cpp
vector<pair<int, int>> p = {{3, 4}, {-1, 1}, {0, 2}, {-5, 0}, {1, -1}};
sort(p.begin(), p.end(), [](auto a, auto b) {
    long long da = 1LL * a.first * a.first + 1LL * a.second * a.second;
    long long db = 1LL * b.first * b.first + 1LL * b.second * b.second;
    if (da != db) return da < db;
    return a < b;                 // remis: zwykłe porównanie par
});
for (auto [x, y] : p) cout << "(" << x << "," << y << ") ";
cout << "\n";

07 — Numery i rankingi

Sortujemy numery zamiast wartości: rekordy i miejsca w rankingu

Sortowanie ma jedną wadę: po nim nie wiadomo, kto był kim. Gdy posortujesz wzrost uczniów, dostaniesz ładny rząd liczb — ale czyj jest wzrost 152? W tej części poznasz sposób, który rozwiązuje ten problem raz na zawsze: zamiast wartości sortujemy numery. Przy okazji nauczysz się układać dane z wieloma polami i liczyć miejsca w rankingu z remisami.

Problem: kto jest kim?

Uczniowie stoją w kolejce, każdy ma swój numer 0, 1, 2, 3, a w vectorze w zapisaliśmy ich wzrost. Chcemy wiedzieć, kto jest najniższy, kto drugi… — czyli numery uczniów w kolejności od najniższego. Sposób z lekcji o parach: pary (wzrost, numer) i sort. Działa, ale przy wielu polach robi się nieczytelnie. Jest lepszy sposób.

Sortujemy numery, porównujemy wartości

Robimy vector numerów nr = {0, 1, 2, …, n − 1} i sortujemy ten vector — ale z regułą, która porównuje numery według wzrostu: „numer a stoi przed numerem b, gdy uczeń a jest niższy od ucznia b”, czyli w[a] < w[b]. Reguła musi widzieć vector w, więc ma [&]. Sam vector w się nie zmienia — przestawiają się tylko numery.

Rekordy w kilku vectorach

Teraz prawdziwy pożytek. Zawodnik ma imię, punkty i czas. Zamiast pakować to w pary par, trzymamy trzy osobne vectory: imie[i], pkt[i], czas[i] — wszystkie trzy pod numerem i opisują tego samego zawodnika. Taki zestaw nazywa się rekordem. Sortujemy numery z regułą o trzech kryteriach, a wypisujemy przez imie[nr[k]].

rekordy.cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<string> imie(n);
    vector<int> pkt(n), czas(n);
    for (int i = 0; i < n; i++) cin >> imie[i] >> pkt[i] >> czas[i];

    vector<int> nr(n);
    for (int i = 0; i < n; i++) nr[i] = i;
    sort(nr.begin(), nr.end(), [&](int a, int b) {
        if (pkt[a] != pkt[b]) return pkt[a] > pkt[b];      // więcej punktów
        if (czas[a] != czas[b]) return czas[a] < czas[b];  // krótszy czas
        return imie[a] < imie[b];                          // alfabet
    });
    for (int k = 0; k < n; k++) {
        int i = nr[k];
        cout << k + 1 << ". " << imie[i] << " " << pkt[i] << " " << czas[i] << "\n";
    }
    return 0;
}

08 — Szukanie w posortowanym

Szukanie przez połowienie: lower_bound i upper_bound

W nieposortowanym vectorze, żeby sprawdzić, czy jest w nim liczba x, trzeba obejrzeć wszystkie elementy — tak działa find. W posortowanym da się to zrobić niesamowicie szybciej: w milionie liczb wystarczy zajrzeć do około 20 pudełek. W tej części poznasz pomysł połowienia i gotowe polecenia, które z niego korzystają.

Zabawa: zgadnij liczbę od 1 do 100

Wyszukiwanie binarne w vectorze

Ten sam pomysł działa w posortowanym vectorze. Pilnujemy przedziału numerów od l do r, w którym może stać x. Patrzymy na środek s = (l + r) / 2. Jeśli v[s] == x — znaleźliśmy. Jeśli v[s] < x — x może stać tylko na prawo od s (bo na lewo są jeszcze mniejsze liczby), więc l = s + 1. W przeciwnym razie r = s − 1. Gdy przedział zrobi się pusty (l > r), x nie ma. Nazwa: wyszukiwanie binarne (binarne — bo za każdym razem dzielimy na dwie części).

binarne.cpp
vector<int> v = {2, 5, 8, 12, 16, 23, 38, 56, 72, 91};
int x = 23;
int l = 0, r = v.size() - 1;
bool jest = false;
while (l <= r) {
    int s = (l + r) / 2;
    cout << "l=" << l << " r=" << r << " s=" << s << " v[s]=" << v[s] << "\n";
    if (v[s] == x) { jest = true; break; }
    if (v[s] < x) l = s + 1;       // x może być tylko na prawo
    else r = s - 1;                // x może być tylko na lewo
}
cout << (jest ? "jest" : "nie ma") << "\n";

lower_bound — pierwsze miejsce, gdzie x by pasował

binary_search mówi tylko „jest” albo „nie ma”. Często chcemy wiedzieć więcej: gdzie stoi x i ile jest liczb mniejszych od niego. Do tego służy lower_bound(v.begin(), v.end(), x). Zwraca strzałkę na pierwszy element, który jest ≥ x — czyli na pierwsze miejsce, w które dałoby się wstawić x, nie psując porządku. Jeśli wszystkie elementy są mniejsze od x, zwraca end().

Jak z każdej strzałki, numer dostajesz, odejmując v.begin(). I tu jest piękna rzecz: ten numer to jednocześnie liczba elementów mniejszych od x — bo wszystkie stoją na lewo od tego miejsca.

Najbliższa wartość

Masz cennik (posortowany) i chcesz znaleźć cenę najbliższą x. lower_bound(x) pokazuje najmniejszą cenę ≥ x — to jeden kandydat. Drugi kandydat stoi tuż przed nim: największa cena < x. Trzeba porównać obu (uważając, żeby nie wyjść poza vector).

najblizsza.cpp
vector<int> c = {10, 25, 40, 60, 95};
for (int x : {30, 34, 5, 120}) {
    int i = lower_bound(c.begin(), c.end(), x) - c.begin();
    int najlepsza;
    if (i == (int)c.size()) najlepsza = c[i - 1];      // wszystkie mniejsze
    else if (i == 0) najlepsza = c[0];                 // wszystkie większe
    else if (x - c[i - 1] <= c[i] - x) najlepsza = c[i - 1];
    else najlepsza = c[i];
    cout << x << " -> " << najlepsza << "\n";
}

09 — Sortowanie i sprytny wybór

Najpierw posortuj, potem bierz po kolei: pomysły zachłanne

Wiele zadań olimpijskich rozwiązuje się według tego samego przepisu: posortuj dane w odpowiedniej kolejności, a potem bierz po kolei to, co w danej chwili wygląda najlepiej. Taki sposób myślenia nazywa się zachłannym — jak ktoś zachłanny, bierzemy od razu najlepszy kąsek i nigdy nie wracamy do wcześniejszych decyzji. Znasz już jeden przykład z lekcji o parach: wybór jak największej liczby wykładów. W tej części poznasz kolejne.

Jak najwięcej rzeczy za budżet

Masz B złotych i listę cen prezentów. Chcesz kupić jak najwięcej prezentów (każdy co najwyżej raz). Pomysł: kupuj od najtańszych, dopóki starcza pieniędzy. Dlaczego to najlepsze? Załóżmy, że ktoś kupił jakiś drogi prezent, a pominął tańszy. Gdyby zamienił drogi na tańszy, miałby tyle samo prezentów i więcej pieniędzy. Zatem zawsze opłaca się brać najtańsze.

budzet.cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    long long budzet;
    cin >> n >> budzet;
    vector<int> c(n);
    for (auto &x : c) cin >> x;
    sort(c.begin(), c.end());               // od najtańszego
    int ile = 0;
    long long wydane = 0;
    for (auto x : c) {
        if (wydane + x > budzet) break;     // na ten już nie stać
        wydane += x;
        ile++;
    }
    cout << ile << " " << wydane << "\n";
    return 0;
}

Argument zamiany Tak sprawdzasz, czy pomysł zachłanny jest dobry: weź dowolne inne rozwiązanie i pokaż, że jeśli różni się od zachłannego, to zamiana jednego elementu na „zachłanny” niczego nie psuje. Jeśli tak — zachłanność jest optymalna. Jeśli nie umiesz tego pokazać, sprawdź pomysł na małych przykładach, rozwiązując je ręcznie.

Łódki: najcięższy z najlżejszym

Ludzie przepływają rzekę łódkami. Łódka mieści najwyżej dwie osoby o łącznej wadze najwyżej L. Ile najmniej łódek potrzeba? Pomysł: posortuj wagi i ustaw dwa wskaźniki — i na najlżejszej osobie, j na najcięższej. Najcięższy i tak musi czymś popłynąć. Jeśli zmieści się z najlżejszym — płyną razem (i++, j--). Jeśli nie — najcięższy nie zmieści się z nikim, więc płynie sam (j--). W obu przypadkach zużyliśmy jedną łódkę.

        cout << w[i] << "+" << w[j] << " ";
        i++;
    } else {
        cout << w[j] << " ";
    }
    j--;
    lodek++;
}

Mnożenie w parach: największy z największym

Masz dwie listy po n liczb (nieujemnych): a — ile sztuk każdego produktu możesz sprzedać, b — ceny, jakie dają różni kupcy. Każdy produkt sprzedajesz innemu kupcowi. Jak połączyć je w pary, żeby zarobić jak najwięcej (suma iloczynów)? Intuicja: najwięcej sztuk sprzedaj najlepiej płacącemu. Po sortowaniu obu list rosnąco łączymy a[i] z b[i] — największy z największym. A żeby wyszło najmniej, jedną listę sortujemy rosnąco, a drugą malejąco.

iloczyny.cpp
vector<long long> a = {3, 1, 2};
vector<long long> b = {10, 30, 20};
sort(a.begin(), a.end());          // 1 2 3
sort(b.begin(), b.end());          // 10 20 30
long long maks = 0, mini = 0;
int n = a.size();
for (int i = 0; i < n; i++) {
    maks += a[i] * b[i];           // największy z największym
    mini += a[i] * b[n - 1 - i];   // największy z najmniejszym
}
cout << maks << " " << mini << "\n";

Dwie posortowane listy: ciastka dla dzieci

Każde dziecko ma apetyt — minimalny rozmiar ciastka, które je zadowoli. Masz ciastka różnej wielkości; każde dziecko dostaje najwyżej jedno ciastko. Ile najwięcej dzieci zadowolisz? Sortujemy obie listy. Idziemy po ciastkach od najmniejszego: jeśli bieżące ciastko zadowala dziecko z najmniejszym apetytem spośród niezadowolonych — dajemy je; jeśli nie — to ciastko jest za małe dla wszystkich pozostałych dzieci, więc je pomijamy.

ciastka.cpp
vector<int> apetyt = {5, 2, 8, 3};

int d = 0;                              // pierwsze niezadowolone dziecko
for (auto c : ciastko) {
    if (d < (int)apetyt.size() && c >= apetyt[d]) {
        cout << "ciastko " << c << " -> dziecko z apetytem " << apetyt[d] << "\n";
        d++;
    }
}

Baza zadań: sortowanie w praktyce

Znasz już wszystko, co potrzebne: sort rosnąco i malejąco na vectorze, tablicy i napisie, k-ty element i medianę, grupy równych wartości, unique i najbliższych sąsiadów, cztery metody sortowania ręcznego, własne reguły z lambdą, kilka kryteriów naraz i stable_sort, sortowanie numerów, miejsca w rankingu i kompresję, lower_bound i upper_bound, a na koniec pomysły zachłanne. Ściąga: gotowe schematy sortowania

Rosnąco i malejąco

sort(v.begin(), v.end());

sort(v.rbegin(), v.rend());

Napisy — alfabetycznie, ale wielkie litery przed małymi, a „10” przed „9”.

Adresy w posortowanym

v[0]   v[n - 1]          // min, max
v[k - 1]   v[n - k]      // k-ty od dołu, od góry
v[n / 2]                 // mediana (n nieparzyste)
(v[n/2 - 1] + v[n/2]) / 2.0

Remis na granicy: wszyscy z wynikiem ≥ v[n - k].

Grupy i unique

i = 0;
while (i < n) { j = i;
  while (j < n && v[j] == v[i]) j++;
  // grupa v[i..j-1]
  i = j; }
v.erase(unique(v.begin(), v.end()), v.end());

Najpierw sort! Najbliżsi to zawsze sąsiedzi: v[i + 1] - v[i].

Sortowanie ręczne

wybieranie: min z [i..n-1] na miejsce i
bąbelki: swap sąsiadów, runda po rundzie
wstawianie: x wsuwa się w lewą część
zliczanie: licznik[x]++, potem wypisz

Dwie pętle ≈ n·n — dobre do kilku tysięcy. sort ≈ n·log n.

Własna reguła

sort(v.begin(), v.end(), [](int a, int b) {
    if (kl(a) != kl(b)) return kl(a) < kl(b);
    return a < b;
});

„Czy a przed b?” Dla równych — false, więc nigdy <=. Zmienne z main: [&].

pair: najpierw first, potem second
(-punkty, czas)        // minus = malejąco

stable_sort(...)       // remisy jak na wejściu

Główne kryterium na pierwsze miejsce pary albo do pierwszego ifa reguły.

    return w[a] < w[b]; });
miejsce: jak poprzedni → to samo

11 — Częste błędy

Częste błędy i dobre praktyki

📏
t + n, nie t + n - 1
Druga strzałka pokazuje miejsce, którego nie bierzemy. sort(t, t + n - 1) zostawia ostatni element nieposortowany. Dla pudełek 1..n: sort(t + 1, t + n + 1).
🔤
Napisy to nie liczby
Wielkie litery są przed małymi („Zosia” przed „ala”), a liczby zapisane jako napisy sortują się znak po znaku („100” przed „20”). Liczby wczytuj do int albo long long.
🧾
Sort zjada kolejność
Po sort nie wiadomo, gdzie co stało. Potrzebujesz oryginału — zrób kopię. Potrzebujesz numerów — sortuj pary (wartość, numer) albo vector numerów.
➗
Mediana przez 2.0
Przy parzystym n mediana to średnia dwóch środkowych: (a + b) / 2.0. Samo / 2 obetnie połówkę. Przy dużych liczbach sumuj w long long.
🧹
unique bez sort i bez erase
unique zbija tylko sąsiednie powtórzenia i nie skraca vectora. Zawsze: sort, a potem v.erase(unique(v.begin(), v.end()), v.end());.
⚖️
<= w regule
Reguła dla równych elementów musi zwracać false. return a <= b; potrafi wysypać program na dużym teście. Pisz < albo >.
🎲
Remisy bez rozstrzygnięcia
Gdy reguła mówi „remis”, sort ustawia takie elementy w dowolnej kolejności — nie w kolejności z wejścia. Dopisz kolejne kryterium (np. numer) albo użyj stable_sort.
👀
[] czy [&]?
Reguła z pustymi nawiasami nie widzi zmiennych z main — „is not captured”. Gdy w regule używasz k albo innego vectora, pisz [&].
🔎
Połowienie na nieposortowanym
binary_search, lower_bound i upper_bound na nieposortowanych danych dają bzdury bez ostrzeżenia. Najpierw sort — i to raz, a nie przy każdym pytaniu.
🚧
end() z lower_bound
Gdy wszystkie elementy są mniejsze od x, lower_bound zwraca end() — gwiazdka czyta wtedy spoza vectora. Najpierw sprawdź, czy numer jest mniejszy od n.
⏱️
Dwie pętle przy dużym n
Bąbelki, wybieranie i wstawianie robią około n·n kroków — dla n = 100 000 to 10 miliardów. Na zawodach sortuj przez sort, a pętle zostaw zadaniom o przebiegu algorytmu.
🍪
Zachłanność bez dowodu
„Bierz największe” nie zawsze działa (monety 1, 3, 4). Zanim zaufasz pomysłowi, sprawdź argument zamiany albo porównaj z rozwiązaniem sprawdzającym wszystko na małych testach.
