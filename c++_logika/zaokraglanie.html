01 — Podstawy

Cztery sposoby, cztery wyniki

„Zaokrąglij 2.7” brzmi jednoznacznie, dopóki nie zapytasz: w którą stronę? C++ oferuje cztery odpowiedzi i każda daje co innego. Wszystkie funkcje mieszkają w nagłówku <cmath>.

⬇️

floor(x)

Zawsze w dół, w stronę mniejszych liczb. floor(2.7) to 2.

⬆️

ceil(x)

Zawsze w górę. ceil(2.1) to 3 — nawet dla wartości ledwo powyżej dwójki.

🎯

round(x)

Normalnie, „po ludzku”: do najbliższej całkowitej. Połówki idą w górę: round(2.5) to 3.

✂️

(int)x

Nie zaokrągla — po prostu ucina część po przecinku. (int)2.9 to 2.

porownanie.cpp
#include <iostream>
#include <cmath>
using namespace std;

int main() {
    double x = 2.7;

    cout << floor(x) << "\n";   // 2  - w dol
    cout << ceil(x)  << "\n";   // 3  - w gore
    cout << round(x) << "\n";   // 3  - po ludzku
    cout << (int)x   << "\n";   // 2  - ucina

    return 0;
}
▶ Wyjście programu
2 3 3 2

Dla liczb dodatnich (int) zachowuje się tak samo jak floor, więc łatwo uznać, że to to samo. Dla ujemnych już nie — i tu gubi się najwięcej osób.

dodatnie.cpp
double x = 2.7;

cout << floor(x) << "\n";   // 2
cout << (int)x   << "\n";   // 2

// wyglada na to samo...
▶ Wyjście programu
2 2
ujemne.cpp
double x = -2.7;

cout << floor(x) << "\n";   // -3 (w dol!)
cout << (int)x   << "\n";   // -2 (ucinamy ogon)

// ...ale to NIE jest to samo
▶ Wyjście programu
-3 -2

Wyjaśnienie jest proste: floor zawsze idzie w stronę mniejszych liczb, a (int) zawsze w stronę zera. Dla dodatnich to ten sam kierunek, dla ujemnych — przeciwny. Jeśli w danych mogą pojawić się liczby ujemne, wybieraj świadomie.

02 — Dzielenie w górę

Najczęstszy przypadek w zadaniach

Klasyczne pytanie: „ile autobusów po 50 miejsc potrzeba dla 120 osób?”. Odpowiedź to nie 2.4, tylko 3 — bo dwudziestu osobom trzeba dać trzeci autobus. To jest właśnie dzielenie w górę i robi się je częściej, niż myślisz.

przez_ceil.cpp
#include <cmath>

int osoby = 120;
int miejsca = 50;

// uwaga: (double) przed dzieleniem!
int autobusy = ceil((double)osoby / miejsca);

cout << autobusy;
▶ Wyjście programu
3
bez_cmath.cpp
int osoby = 120;
int miejsca = 50;

// ten sam wynik, same liczby calkowite
int autobusy = (osoby + miejsca - 1) / miejsca;

cout << autobusy;
▶ Wyjście programu
3

Obie wersje dają to samo. Prawa jest bezpieczniejsza, bo nie dotyka liczb ułamkowych w ogóle — a te potrafią zdradzić przy bardzo dużych wartościach. Wzór (a + b - 1) / b warto zapamiętać jako gotowca.

Skąd on się bierze? Dzielenie na int zawsze ucina w dół. Dodanie b - 1 przed dzieleniem popycha wynik o jedną pozycję w górę zawsze wtedy, gdy coś zostaje z reszty — a gdy dzieli się równo, nic nie zmienia.

dzielenie_w_gore.cpp
#include <iostream>
using namespace std;

int main() {
    int b = 50;

    for (int a : {100, 101, 120, 150}) {
        cout << a << " osob -> "
             << a / b << " (zwykle), "
             << (a + b - 1) / b << " (w gore)\n";
    }

    return 0;
}
▶ Wyjście programu
100 osob -> 2 (zwykle), 2 (w gore) 101 osob -> 2 (zwykle), 3 (w gore) 120 osob -> 2 (zwykle), 3 (w gore) 150 osob -> 3 (zwykle), 3 (w gore)
03 — Zaokrąglanie do pokazania

setprecision to co innego

Jest różnica między zaokrągleniem wartości a pokazaniem jej z mniejszą liczbą cyfr. round zmienia liczbę na zawsze. setprecision zmienia tylko to, co widać na ekranie — w pamięci zostaje pełna wartość.

wyswietlanie.cpp
#include <iomanip>

double x = 3.14159265;

// tylko wyswietlanie - x sie nie zmienia
cout << fixed << setprecision(2);
cout << x << "\n";        // 3.14
cout << x * 100 << "\n";  // 314.16, nie 314.00
▶ Wyjście programu
3.14 314.16
zaokraglenie.cpp
#include <cmath>

double x = 3.14159265;

// naprawde zmieniamy wartosc
double y = round(x * 100) / 100.0;

cout << y << "\n";        // 3.14
cout << y * 100 << "\n";  // 314, bo y to juz 3.14
▶ Wyjście programu
3.14 314

Sztuczka z prawej strony — round(x * 100) / 100.0 — to standardowy sposób na zaokrąglenie do dwóch miejsc po przecinku. Mnożysz przez sto, zaokrąglasz do całkowitej, dzielisz z powrotem. Do trzech miejsc byłoby 1000 zamiast 100.

I ostatnia pułapka, najczęstsza ze wszystkich: dzielenie dwóch liczb całkowitych daje liczbę całkowitą, jeszcze zanim cokolwiek zaokrąglisz. 7 / 2 to 3, więc round(7 / 2) też da 3, mimo że prawidłowa odpowiedź to 4. Rzutuj przed dzieleniem, nie po.

pulapka.cpp
#include <iostream>
#include <cmath>
using namespace std;

int main() {
    int a = 7, b = 2;

    cout << round(a / b) << "\n";           // 3 - ZLE
    cout << round((double)a / b) << "\n";   // 4 - dobrze
    cout << round(a / 2.0) << "\n";         // 4 - tez dobrze

    return 0;
}
▶ Wyjście programu
3 4 4
04 — Ściąga

Wszystkie sposoby zaokrąglania obok siebie

Ostatnia kolumna pokazuje, co dokładnie wyjdzie dla liczby dodatniej i ujemnej. To właśnie tam kryją się wszystkie niespodzianki.

ZapisCo robiDla 2.7 / -2.7
floor(x) Zaokrągla w dół, w stronę mniejszych liczb. 2 / -3
ceil(x) Zaokrągla w górę. 3 / -2
round(x) Do najbliższej całkowitej, połówki w górę. 3 / -3
(int)x Ucina część ułamkową, w stronę zera. 2 / -2
a / b (na int) Dzieli i ucina w dół. 7/2 to 3
(a + b - 1) / b Dzieli w górę, bez liczb ułamkowych. (7+1)/2 to 4
round(x * 100) / 100.0 Zaokrągla wartość do dwóch miejsc po przecinku. 3.14159 to 3.14
fixed << setprecision(k) Pokazuje k miejsc po przecinku. Nie zmienia wartości w pamięci
abs(x) Wartość bez znaku minus. Osobny temat obok
(double)a / b Wymusza dzielenie z ułamkiem. Rzutuj przed dzieleniem

Porównaj wiersze pierwszy i czwarty dla liczby ujemnej: floor(-2.7) daje -3, a (int)(-2.7) daje -2. To nie jest usterka — to dwie różne reguły. Wybieraj świadomie, gdy dane mogą być ujemne.

05 — Przykładowe zadania

Sprawdź się na zadaniach

Sześć zadań od najprostszego. Każde sprawdza, czy dobrałeś właściwy rodzaj zaokrąglenia — a to zwykle różnica jednego znaku w kodzie. Najpierw spróbuj sam.

Łatwe Cztery zaokrąglenia
Wczytaj liczbę z częścią ułamkową i wypisz cztery jej wersje: w dół, w górę, zwykłe zaokrąglenie i ucięcie części ułamkowej.
Jak to ugryźć: Zadanie na rozgrzewkę — chodzi o zapamiętanie nazw. Sprawdź wynik na liczbie ujemnej, np. -2.7: dwie z czterech odpowiedzi się rozjadą.
Pokaż rozwiązanie
cztery.cpp
#include <iostream>
#include <cmath>
using namespace std;

int main() {
    double x;
    cin >> x;

    cout << "floor: " << floor(x) << "\n";
    cout << "ceil:  " << ceil(x)  << "\n";
    cout << "round: " << round(x) << "\n";
    cout << "(int): " << (int)x   << "\n";

    return 0;
}
Łatwe Ile autobusów
Wczytaj liczbę osób i liczbę miejsc w jednym autobusie. Wypisz, ile autobusów trzeba zamówić, żeby wszyscy się zmieścili.
Jak to ugryźć: Dzielenie w górę. Możesz użyć ceil z rzutowaniem na double albo bezpieczniejszego wzoru (a + b - 1) / b na samych liczbach całkowitych.
Pokaż rozwiązanie
autobusy.cpp
#include <iostream>
using namespace std;

int main() {
    int osoby, miejsca;
    cin >> osoby >> miejsca;

    int autobusy = (osoby + miejsca - 1) / miejsca;

    cout << autobusy;
    return 0;
}
Łatwe Średnia z dwoma miejscami
Wczytaj n liczb całkowitych i wypisz ich średnią z dokładnością do dwóch miejsc po przecinku.
Jak to ugryźć: Dwie pułapki naraz: dzielenie sumy przez n na samych int-ach obetnie ułamek, a bez fixed setprecision liczy cyfry znaczące, a nie miejsca po przecinku.
Pokaż rozwiązanie
srednia.cpp
#include <iostream>
#include <iomanip>
using namespace std;

int main() {
    int n;
    cin >> n;

    int suma = 0;
    for (int i = 0; i < n; i++) {
        int x;
        cin >> x;
        suma += x;
    }

    cout << fixed << setprecision(2);
    cout << (double)suma / n;

    return 0;
}
Średnie Cena z groszami
Wczytaj cenę w złotówkach (liczba z ułamkiem) i liczbę sztuk. Wypisz łączną kwotę zaokrągloną do pełnych groszy.
Jak to ugryźć: Zaokrąglenie wartości, nie tylko wyświetlania: round(kwota * 100) / 100.0. Do pokazania i tak dodaj fixed z setprecision(2), żeby grosze nie znikały.
Pokaż rozwiązanie
cena.cpp
#include <iostream>
#include <iomanip>
#include <cmath>
using namespace std;

int main() {
    double cena;
    int sztuk;
    cin >> cena >> sztuk;

    double razem = cena * sztuk;
    razem = round(razem * 100) / 100.0;

    cout << fixed << setprecision(2);
    cout << razem;

    return 0;
}
Średnie Zaokrąglij do wielokrotności
Wczytaj liczbę x i liczbę k. Wypisz najbliższą wielokrotność k, która jest większa lub równa x. Dla x = 17, k = 5 odpowiedzią jest 20.
Jak to ugryźć: Podziel w górę przez k, a potem pomnóż z powrotem przez k. Wzór ((x + k - 1) / k) * k robi oba kroki naraz.
Pokaż rozwiązanie
wielokrotnosc.cpp
#include <iostream>
using namespace std;

int main() {
    int x, k;
    cin >> x >> k;

    int wynik = ((x + k - 1) / k) * k;

    cout << wynik;
    return 0;
}
Trudne Dzielenie w dół dla ujemnych
Wczytaj dwie liczby całkowite a i b (b > 0) i wypisz wynik dzielenia a / b zaokrąglony w dół — także wtedy, gdy a jest ujemne. Dla -7 / 2 odpowiedzią jest -4, nie -3.
Jak to ugryźć: Zwykłe a / b w C++ ucina w stronę zera, więc dla ujemnych daje wynik o jeden za duży — ale tylko wtedy, gdy dzielenie nie wychodzi równo. Sprawdź oba warunki: czy a jest ujemne i czy coś zostaje z reszty.
Pokaż rozwiązanie
dzielenie_w_dol.cpp
#include <iostream>
using namespace std;

int main() {
    int a, b;
    cin >> a >> b;

    int wynik = a / b;

    // poprawka tylko dla ujemnych z reszta
    if (a % b != 0 && a < 0) {
        wynik--;
    }

    cout << wynik;
    return 0;
}
06 — Porady

Częste błędy i dobre praktyki

✂️
(int) ucina, nie zaokrągla
(int)2.9 to 2, a nie 3. Do prawdziwego zaokrąglenia służy round.
➖
Ujemne zachowują się inaczej
floor(-2.7) to -3, a (int)(-2.7) to -2. Dla dodatnich obie dają to samo — dlatego błąd wychodzi dopiero na testach z minusem.
➗
Dzielenie intów daje int
round(7 / 2) to 3, bo dzielenie wykonało się pierwsze. Rzutuj przed dzieleniem: round((double)7 / 2).
⬆️
Dzielenie w górę bez cmath
(a + b - 1) / b daje ten sam wynik co ceil((double)a / b), ale bez liczb ułamkowych. Bezpieczniejsze i szybsze.
📦
Dwa różne nagłówki
floor, ceil i round są w <cmath>, a setprecision w <iomanip>. To osobne rzeczy.
👁️
setprecision nie zmienia wartości
Zmienia tylko to, co widać na ekranie. W pamięci liczba zostaje z pełną dokładnością i dalsze obliczenia użyją tej pełnej.
