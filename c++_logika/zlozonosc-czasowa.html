01 — Podstawy

Komputer jest szybki, ale nie nieskończenie

Zwykły komputer wykonuje mniej więcej sto milionów prostych działań na sekundę. Brzmi jak dużo — i przy małych danych rzeczywiście wystarcza z ogromnym zapasem. Ale gdy dane rosną, ten zapas znika szybciej, niż się wydaje.

Spójrz na te dwa programy. Robią prawie to samo, różnią się jedną zagnieżdżoną pętlą. Pierwszy kończy się natychmiast, drugi — gdybyś go uruchomił — potrzebowałby kilkunastu minut.

szybko.cpp
int n = 100000;
long long suma = 0;

// jedna petla: 100 000 obrotow
for (int i = 0; i < n; i++) {
    suma += i;
}

cout << suma;
// gotowe w ulamku sekundy
▶ Wyjście programu
4999950000
wolno.cpp
int n = 100000;
long long suma = 0;

// petla w petli: 10 000 000 000 obrotow
for (int i = 0; i < n; i++) {
    for (int j = 0; j < n; j++) {
        suma++;
    }
}

cout << suma;
// kilkanascie MINUT
▶ Wyjście programu
(nie doczekasz)

Skąd ta różnica? Pierwszy program wykonuje n obrotów. Drugi — n razy n, czyli dziesięć miliardów. Przy stu milionach operacji na sekundę to około stu sekund... razy sto. Każde zagnieżdżenie pętli mnoży pracę, a nie ją dodaje.

I to jest cała idea tej strony: zanim zaczniesz pisać, policz na palcach, ile obrotów zrobi Twój kod. Jeśli wyjdzie więcej niż kilkaset milionów — trzeba wymyślić coś innego.

02 — Liczenie obrotów

Jak policzyć, ile razy coś się wykona

Reguły są mechaniczne i jest ich tylko kilka. Nie trzeba żadnej matematyki — wystarczy uważnie popatrzeć na pętle.

1️⃣

jedna pętla po n

Wykonuje się n razy. Dla miliona danych — milion obrotów.

✖️

pętla w pętli

Mnożymy: n × n. Dla tysiąca danych — milion obrotów.

➕

pętle obok siebie

Dodajemy, ale liczy się tylko większa. n + n to nadal „mniej więcej n”.

✂️

połowienie

Gdy w każdym obrocie dzielisz coś przez dwa, obrotów jest tylko kilkadziesiąt — nawet dla miliarda.

📞

wywołanie funkcji

Doliczasz to, co dzieje się w środku. Funkcja z pętlą wywołana w pętli to znowu mnożenie.

👀

ukryte pętle

sort, s.find() czy v.insert() też kosztują. Nie widać ich pętli, ale ona tam jest.

liczenie.cpp
#include <iostream>
using namespace std;

int main() {
    int n = 1000;
    int licznik = 0;

    // A: jedna petla -> n
    for (int i = 0; i < n; i++) licznik++;
    cout << "A: " << licznik << "\n";

    // B: petla w petli -> n * n
    licznik = 0;
    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j++)
            licznik++;
    cout << "B: " << licznik << "\n";

    // C: polowienie -> okolo 10 obrotow
    licznik = 0;
    int x = n;
    while (x > 1) { x /= 2; licznik++; }
    cout << "C: " << licznik << "\n";

    return 0;
}
▶ Wyjście programu
A: 1000 B: 1000000 C: 9

Zwróć uwagę na wynik C. Dla tysiąca danych pętla połowiąca wykonała dziewięć obrotów. Dla miliona byłoby ich dwadzieścia, dla miliarda — trzydzieści. Właśnie dlatego szukanie w posortowanych danych przez binary_search jest tak nieprawdopodobnie szybkie.

Jedna pułapka, o której łatwo zapomnieć: nie wszystkie pętle widać. Gdy w pętli po n elementach wywołujesz sort, to sortowanie ma swoją własną pętlę w środku — i całość robi się dużo wolniejsza, niż wygląda.

03 — Notacja O

Skrót, którym mówi się o szybkości

Zamiast za każdym razem pisać „ten program wykonuje mniej więcej n obrotów”, programiści używają skrótu: O(n). To po prostu nazwa dla kształtu wzrostu — nic więcej, żadnej wyższej matematyki.

W tym zapisie pomija się stałe i drobiazgi. Program robiący 3n + 100 obrotów to po prostu O(n), bo przy dużym n to właśnie n decyduje o wszystkim. Chodzi o odpowiedź na pytanie: co się stanie, gdy danych będzie dziesięć razy więcej?

nazwy.cpp
// O(1) - zawsze tyle samo pracy
int pierwszy = v[0];

// O(n) - jedno przejscie
for (int x : v) suma += x;

// O(n * n) - petla w petli
for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++)
        licznik++;

// O(log n) - polowienie
while (x > 1) x /= 2;
co_to_znaczy.cpp
// n = 1000, dane rosna 10x -> n = 10000

// O(1):      tyle samo pracy        (bez zmian)
// O(log n):  10 obrotow -> 13       (prawie bez zmian)
// O(n):      1 000 -> 10 000        (10x wiecej)
// O(n log n):10 000 -> 130 000      (13x wiecej)
// O(n * n):  1 000 000 -> 100 000 000  (100x!)

Ostatni wiersz po prawej to sedno sprawy. Przy O(n·n) dziesięciokrotny wzrost danych oznacza stukrotny wzrost czasu. Program, który dla tysiąca liczb działał ułamek sekundy, dla dziesięciu tysięcy będzie się liczył kilka sekund, a dla stu tysięcy — kilkanaście minut.

Nazwy, które spotkasz najczęściej, w kolejności od najszybszej: O(1) (stała praca), O(log n) (połowienie), O(n) (jedno przejście), O(n log n) (tyle kosztuje sortowanie), O(n·n) (pętla w pętli). To w praktyce cała lista, jakiej potrzebujesz.

04 — Ile zdąży

Zasada kciuka: co się zmieści w sekundzie

Skoro komputer robi około stu milionów działań na sekundę, można z góry powiedzieć, jaka złożoność wystarczy dla danych podanego rozmiaru. To jedyna tabelka z tej strony, którą warto zapamiętać.

szacowanie.cpp
// Rozmiar danych  ->  co jeszcze zdazy w 1 sekundzie
//
//   n <= 10           wszystko, nawet bardzo wolne
//   n <= 1 000        O(n * n)      petla w petli - OK
//   n <= 100 000      O(n log n)    sortowanie - OK
//   n <= 1 000 000    O(n)          jedno przejscie - OK
//   n <= 10 000 000   O(n)          jedno, ale bez fajerwerkow
//   n powyzej         O(log n)      albo wzor matematyczny
//
// Innymi slowy: jesli n jest duze, petla w petli odpada.

Jak z tego korzystać? Przeczytaj z treści zadania, jak duże mogą być dane, a potem sprawdź w tabelce, co jeszcze wolno. Jeśli w zadaniu stoi „liczb jest do miliona”, a Twój pomysł wymaga pętli w pętli, to nie ma sensu go pisać — lepiej od razu szukać innego.

wolne.cpp
// zadanie: czy sa dwie liczby o sumie k?
// n moze byc do 100 000

// sposob 1: kazda z kazda -> n * n
for (int i = 0; i < n; i++)
    for (int j = i + 1; j < n; j++)
        if (v[i] + v[j] == k) {
            cout << "TAK";
            return 0;
        }

// 10 000 000 000 obrotow - za wolno!
szybkie.cpp
// ten sam problem, jedno przejscie
#include <set>

set<int> widziane;

for (int i = 0; i < n; i++) {
    if (widziane.count(k - v[i])) {
        cout << "TAK";
        return 0;
    }
    widziane.insert(v[i]);
}

// 100 000 obrotow - natychmiast

Oba programy dają tę samą odpowiedź. Różnica polega wyłącznie na tym, ile pracy wykonują — i to ona decyduje o tym, czy zadanie zostanie zaliczone. Dlatego warto policzyć obroty, zanim napiszesz pierwszą linijkę.

05 — Ściąga

Wszystkie nazwy, które spotkasz

Sześć pierwszych wierszy to w praktyce cała lista, jakiej potrzebujesz. Dwa ostatnie zobaczysz rzadko i tylko przy bardzo małych danych.

NazwaCo znaczyTypowy przykład
O(1) Zawsze tyle samo pracy, niezależnie od rozmiaru danych. v[0], v.size(), dodawanie
O(log n) Liczba obrotów rośnie bardzo wolno — połowienie. binary_search, set.count
O(n) Jedno przejście przez dane. Suma tablicy, szukanie maksimum
O(n log n) Jedno przejście, ale każdy krok kosztuje trochę więcej. sort — najczęstszy przypadek
O(n · n) Pętla w pętli. Przy dużych danych odpada. Porównanie każdego z każdym
O(n · m) Dwa różne rozmiary, np. wiersze i kolumny. Przejście tabelki n×m
O(n · n · n) Trzy zagnieżdżone pętle. Tylko dla n do kilkuset
O(2 do n) Sprawdzanie wszystkich możliwości. Tylko dla n do dwudziestu

Zapamiętaj jedną granicę: przy n rzędu stu tysięcy pętla w pętli już nie przejdzie. Jeśli Twój pomysł jej wymaga, a dane są duże — to znak, że zadanie chce czegoś innego. Zwykle pomaga posortowanie danych albo użycie zbioru.

06 — Przykładowe zadania

Sprawdź się na zadaniach

Sześć zadań. W pierwszych trzech masz policzyć obroty i ocenić, czy program zdąży; w dalszych — przyspieszyć rozwiązanie, które działa poprawnie, ale za wolno. Najpierw spróbuj sam.

Łatwe Policz obroty
Napisz program, który dla podanego n wypisze, ile obrotów wykonają trzy pętle: pojedyncza po n, podwójna po n i pętla połowiąca. Uruchom go dla n równego 10, 1000 i 100000.
Jak to ugryźć: Nie musisz tych pętli wykonywać — wystarczy policzyć wzorem: n, n * n i tyle razy, ile razy da się podzielić n przez 2. Na n * n użyj long long.
Pokaż rozwiązanie
policz_obroty.cpp
#include <iostream>
using namespace std;

int main() {
    long long n;
    cin >> n;

    cout << "Pojedyncza: " << n << "\n";
    cout << "Podwojna:   " << n * n << "\n";

    int polowienie = 0;
    long long x = n;
    while (x > 1) { x /= 2; polowienie++; }
    cout << "Polowienie: " << polowienie << "\n";

    return 0;
}
Łatwe Czy liczba jest pierwsza
Napisz funkcję sprawdzającą, czy liczba jest pierwsza — ale tak, żeby działała szybko nawet dla liczb rzędu miliarda.
Jak to ugryźć: Sprawdzanie wszystkich dzielników do n to miliard obrotów — za wolno. Wystarczy dojść do pierwiastka z n, bo każdy dzielnik większy od pierwiastka ma parę mniejszą od niego. Zamiast sqrt pisz warunek i * i <= n.
Pokaż rozwiązanie
pierwsza.cpp
#include <iostream>
using namespace std;

bool czyPierwsza(long long n) {
    if (n < 2) return false;

    // do pierwiastka, nie do n!
    for (long long i = 2; i * i <= n; i++) {
        if (n % i == 0) return false;
    }

    return true;
}

int main() {
    long long n;
    cin >> n;

    cout << (czyPierwsza(n) ? "TAK" : "NIE");
    return 0;
}
Łatwe Suma bez pętli
Policz sumę wszystkich liczb od 1 do n, gdzie n może sięgać miliarda. Program ma odpowiadać natychmiast.
Jak to ugryźć: Pętla po miliardzie liczb zajmie kilkanaście sekund. Ale tę sumę można policzyć jednym wzorem ze szkoły: n * (n + 1) / 2. To różnica między O(n) a O(1). Uwaga na zakres — bierz long long.
Pokaż rozwiązanie
suma_wzorem.cpp
#include <iostream>
using namespace std;

int main() {
    long long n;
    cin >> n;

    // jedno dzialanie zamiast miliarda obrotow
    long long suma = n * (n + 1) / 2;

    cout << suma;
    return 0;
}
Średnie Dwie liczby o zadanej sumie
Wczytaj n liczb (do 100 000) i wartość k. Sprawdź, czy istnieją wśród nich dwie o sumie k. Rozwiązanie musi zdążyć.
Jak to ugryźć: Sprawdzanie każdej pary z każdą to dziesięć miliardów obrotów — odpada. Zamiast tego, idąc po liczbach, pytaj zbiór o brakującą połówkę k - x. Jedno przejście zamiast pętli w pętli.
Pokaż rozwiązanie
para_suma.cpp
#include <iostream>
#include <set>
using namespace std;

int main() {
    int n, k;
    cin >> n >> k;

    set<int> widziane;

    for (int i = 0; i < n; i++) {
        int x;
        cin >> x;

        if (widziane.count(k - x)) {
            cout << "TAK";
            return 0;
        }
        widziane.insert(x);
    }

    cout << "NIE";
    return 0;
}
Średnie Ile razy występuje każda liczba
Wczytaj n liczb z zakresu 1–1000 (samo n może sięgać miliona). Dla każdej wartości, która wystąpiła, wypisz ile razy — rosnąco po wartości.
Jak to ugryźć: Liczenie wystąpień przez przechodzenie całej tablicy dla każdej wartości byłoby pętlą w pętli. Skoro jednak wartości są małe, wystarczy tablica 1001 liczników i jedno przejście: licznik[x]++.
Pokaż rozwiązanie
zliczanie.cpp
#include <iostream>
using namespace std;

int licznik[1001] = {};       // globalnie = same zera

int main() {
    int n;
    cin >> n;

    for (int i = 0; i < n; i++) {
        int x;
        cin >> x;
        licznik[x]++;          // jedno dzialanie na liczbe
    }

    for (int v = 1; v <= 1000; v++) {
        if (licznik[v] > 0) {
            cout << v << ": " << licznik[v] << "\n";
        }
    }

    return 0;
}
Trudne Najmniejsza brakująca liczba
Wczytaj n liczb dodatnich (do miliona) i wypisz najmniejszą liczbę dodatnią, której wśród nich nie ma.
Jak to ugryźć: Sprawdzanie kolejno 1, 2, 3… i szukanie każdej w tablicy to pętla w pętli. Zamiast tego zaznacz obecność w tablicy bool (albo w zbiorze), a potem przejdź od jedynki w górę i zwróć pierwszą niezaznaczoną. Dwa osobne przejścia zamiast jednego zagnieżdżonego.
Pokaż rozwiązanie
brakujaca.cpp
#include <iostream>
using namespace std;

bool jest[1000005] = {};

int main() {
    int n;
    cin >> n;

    for (int i = 0; i < n; i++) {
        int x;
        cin >> x;
        if (x >= 1 && x <= 1000001) jest[x] = true;
    }

    for (int i = 1; ; i++) {
        if (!jest[i]) {
            cout << i;
            return 0;
        }
    }
}
07 — Porady

Częste błędy i dobre praktyki

📖
Zacznij od treści zadania
Ograniczenia (n do miliona) są w zadaniu nie bez powodu. Mówią wprost, jak szybkie musi być Twoje rozwiązanie.
✖️
Zagnieżdżone pętle mnożymy
Dwie pętle jedna w drugiej to n × n obrotów, nie n + n. To najczęstsze źródło programów, które nie zdążą.
👀
Nie wszystkie pętle widać
sort, find czy wstawianie do zbioru mają własne pętle w środku. Wywołane w pętli potrafią zaskoczyć.
💯
Sto milionów na sekundę
To zgrubna miara, ale wystarczająca. Jeśli po policzeniu obrotów wychodzi więcej niż kilkaset milionów — szukaj innego pomysłu.
💾
Pamięć to też limit
Tablica dziesięciu milionów int-ów to około 40 MB. Sto milionów już się nie zmieści, niezależnie od tego, jak szybki jest program.
🧮
Najpierw policz, potem pisz
Pięć minut liczenia obrotów na kartce oszczędza godzinę poprawiania rozwiązania, które i tak nie miało szans.
