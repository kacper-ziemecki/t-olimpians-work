Funkcja — krótkie przypomnienie

Funkcja to kawałek programu z nazwą. Piszemy go raz, a potem możemy go uruchamiać — wywoływać — ile razy chcemy.

definicja i dwa wywołania
void powitaj() {    cout << "Czesc!" << endl;} int main() {    powitaj();    powitaj();}
na ekranie
Czesc!
Czesc!
  1. Linijki 1–3 to definicja — przepis. Sama definicja niczego nie robi.
  2. Linijki 6 i 7 to wywołania — dopiero one uruchamiają przepis.
  3. Dwa wywołania → napis pojawia się dwa razy.

Funkcja z parametrem

Funkcja może dostać parametr — wartość, którą podajemy przy wywołaniu w nawiasie.

void powitaj(string imie) {    cout << "Czesc, " << imie << "!" << endl;} int main() {    powitaj("Ola");    powitaj("Bartek");}
na ekranie
Czesc, Ola!
Czesc, Bartek!
WywołanieWartość imie
powitaj("Ola")"Ola"
powitaj("Bartek")"Bartek"
Każde wywołanie dostaje własną zmienną imie z własną wartością. Za chwilę to będzie bardzo ważne — zapamiętaj to zdanie.

Co dokładnie dzieje się przy wywołaniu?

  1. Program dochodzi do linijki z wywołaniem i zatrzymuje się w tym miejscu — zapamiętuje, gdzie skończył.
  2. Przechodzi do funkcji. Parametr dostaje wartość podaną w nawiasie.
  3. Wykonuje kolejne linijki funkcji — aż do jej końca albo do return.
  4. Wraca dokładnie w to miejsce, w którym się zatrzymał, i idzie dalej od następnej linijki.
Te cztery kroki działają zawsze — dla każdej funkcji, także dla funkcji rekurencyjnych. Cała rekurencja to tylko wiele razy powtórzone te same cztery kroki.

Funkcja, która zwraca wynik

int kwadrat(int x) {    return x * x;} int main() {    int a = kwadrat(5);    cout << a + kwadrat(3);}
na ekranie
34

Funkcja typu int oddaje wynik przez return. Wywołanie zamienia się w zwróconą liczbę:

  1. kwadrat(5) zwraca 25, więc a = 25.
  2. kwadrat(3) zwraca 9.
  3. Na ekran trafia 25 + 9 = 34.
W tej części będziemy pisać głównie funkcje void, które coś wypisują. Funkcjami zwracającymi wynik zajmie się część 2.

Funkcja może wywołać inną funkcję

void c() {    cout << "C ";}void b() {    cout << "B ";    c();    cout << "b ";}void a() {    cout << "A ";    b();    cout << "a ";}int main() {    a();}

Funkcja a woła b, a b woła c. Co pojawi się na ekranie?

Zastosuj cztery kroki z poprzedniej części: przy każdym wywołaniu funkcja zatrzymuje się i czeka, aż wywołana funkcja skończy.

na ekranie
A B C b a
Małe litery b i a pojawiają się na końcu — bo b i a mogą dokończyć swoją pracę dopiero po powrocie z funkcji, którą wywołały.

Śledzimy: kto na kogo czeka?

przebieg programu
↓main woła a()
▸a wypisuje A
↓a woła b() — a czeka
▸b wypisuje B
↓b woła c() — b czeka
▸c wypisuje C
↑c kończy → wracamy do b
▸b dokańcza: wypisuje b
↑b kończy → wracamy do a
▸a dokańcza: wypisuje a
↑a kończy → wracamy do main

Wcięcie pokazuje, jak głęboko jesteśmy: im dalej w prawo, tym więcej funkcji czeka na swoją kolej.

  1. ↓ — wywołanie, schodzimy głębiej.
  2. ▸ — funkcja coś wypisuje.
  3. ↑ — funkcja się kończy, wracamy wyżej.
Funkcje kończą się w odwrotnej kolejności, niż się zaczynały: zaczęły a, b, c — skończyły c, b, a.

Zasada powrotu

Gdy funkcja się kończy, wracamy tam, skąd ją wywołano — i stamtąd idziemy dalej.
Funkcja nie zapomina
Funkcja, która kogoś wywołała, czeka. Pamięta, w której linijce skończyła, i jakie miała wartości zmiennych.
Ostatnia zaczęta — pierwsza skończona
Najpierw kończy się funkcja wywołana najpóźniej. Dopiero potem ta, która na nią czekała.

Stos wywołań — pierwsze spojrzenie

stos wywołań
c()działa — wypisuje C← wierzch
b()czeka, aż skończy się c()
a()czeka, aż skończy się b()
main()czeka, aż skończy się a()
dno stosu

Komputer zapisuje czekające funkcje jedna na drugiej — jak stos talerzy. To jest stos wywołań.

  1. Wywołanie funkcji = kładziemy nowy talerz na wierzch.
  2. Koniec funkcji = zdejmujemy talerz z wierzchu.
  3. Działa zawsze tylko funkcja z wierzchu. Reszta czeka.
Obrazek pokazuje chwilę, gdy działa c() i wypisuje literę C.

Rekurencja

Rekurencja to sytuacja, w której funkcja wywołuje samą siebie.

Brzmi jak błąd z poprzedniego slajdu — i bez zabezpieczenia rzeczywiście nim jest. Ale dobrze napisana rekurencja to jedno z najpotężniejszych narzędzi w programowaniu olimpijskim. Na czym polega „dobrze napisana”? Za chwilę.

Matrioszka
W każdej lalce jest mniejsza lalka. Ale w najmniejszej nie ma już nic — tam się kończy.
Lustro w lustrze
Dwa lustra naprzeciw siebie pokazują odbicie odbicia odbicia… To rekurencja bez końca.
Kolejka w sklepiku
Pytasz osobę przed sobą: „które jesteś?”. Ona pyta osobę przed nią… Zaraz to rozpiszemy.

Analogia: kolejka do sklepiku

pytanie idzie w dół, odpowiedź wraca w górę
↓Ty pytasz Kasię: „które jesteś w kolejce?”
↓Kasia nie wie — pyta Olka
↓Olek nie wie — pyta Zosię
■Zosia stoi pierwsza: „jestem 1.”
↑Olek: „to ja jestem 2.”
↑Kasia: „to ja jestem 3.”
↑Ty: „czyli ja jestem 4.”

Każda osoba robi to samo: jeśli nie zna odpowiedzi, zadaje to samo pytanie osobie przed sobą, czeka na odpowiedź i dodaje do niej 1.

Tylko pierwsza osoba odpowiada od razu, bez pytania — to zatrzymuje całą lawinę pytań.

To jest dokładnie rekurencja: to samo pytanie, tylko mniejsze, aż do przypadku, który znamy od ręki.

Każde wywołanie to osobna kopia funkcji

void f(int n) {    cout << "zaczynam f(" << n << ")" << endl;    if (n > 1) f(n - 1);    cout << "koncze f(" << n << ")" << endl;}

Wywołanie f(3) woła f(2). Czy f(2) „psuje” zmienną n w f(3)? Nie!

kopia 1: f(3)
własne n = 3
kopia 2: f(2)
własne n = 2
kopia 3: f(1)
własne n = 1
na ekranie
zaczynam f(3)
zaczynam f(2)
zaczynam f(1)
koncze f(1)
koncze f(2)
koncze f(3)

Kopie funkcji — najważniejsze

Każde wywołanie ma własne parametry i zmienne. Wywołania nie widzą nawzajem swoich zmiennych.

Pamiętasz zdanie z początku? „Każde wywołanie dostaje własną zmienną.” Przy rekurencji jest tak samo: gdy f(3) wywołuje f(2), to powstaje nowa kopia funkcji z nowym n. Gdy ta kopia się skończy, wracamy do f(3) — a tam n nadal wynosi 3.

Dlatego po wypisaniu „koncze f(1)” program wypisał „koncze f(2)”, a nie znowu „koncze f(1)”: każda kopia pamięta swoje n.

Warunek stopu

void odliczaj(int n) {    if (n == 0) return;    cout << n << " ";    odliczaj(n - 1);}

Dodajemy jedną linijkę: if (n == 0) return;

Gdy n dojdzie do zera, funkcja od razu kończy pracę — nie wypisuje nic i nie woła siebie dalej. To jest warunek stopu (po angielsku: base case).

na ekranie
3 2 1
Teraz wywołania idą 3 → 2 → 1 → 0, a odliczaj(0) zatrzymuje lawinę.

Budowa funkcji rekurencyjnej

void odliczaj(int n) {    if (n == 0) return;    cout << n << " ";    odliczaj(n - 1);}
1 · warunek stopu
if (n == 0) return; — najmniejszy przypadek, w którym nie trzeba wołać siebie. Piszemy go na samej górze.
2 · praca tego wywołania
cout << n << " "; — to, co robi ta jedna kopia funkcji: wypisuje swoje n.
3 · mniejszy problem
odliczaj(n - 1); — resztę pracy zlecamy kolejnej kopii, z mniejszym n. Każde wywołanie zbliża nas do warunku stopu.

Trzy pytania przed napisaniem rekurencji

  1. Kiedy kończę? Jaki jest najmniejszy przypadek, który umiem obsłużyć od ręki, bez wołania siebie? To będzie warunek stopu.

Te trzy pytania zadawaj sobie przy każdym zadaniu z rekurencji — także w kolejnych częściach kursu.

Najczęstsze błędy (1/2)

  1. Brak warunku stopu. Funkcja woła siebie bez końca, aż skończy się stos. Pisz warunek stopu jako pierwszą linijkę funkcji — zanim napiszesz cokolwiek innego.
  2. Krok w złą stronę. odliczaj(n + 1) zamiast odliczaj(n - 1): n rośnie i nigdy nie dojdzie do zera. Sprawdź, czy argument naprawdę zbliża się do warunku stopu.
  3. Warunek, który da się przeskoczyć. Przy kroku n - 2 warunek n == 0 nie zadziała dla nieparzystych n. Bezpieczniej: n <= 0.

Najczęstsze błędy (2/2)

  1. Zapomniany return. if (n == 0) cout << "koniec"; — bez return funkcja idzie dalej i woła siebie dla −1, −2, … Warunek stopu musi kończyć funkcję.

Odpowiedź 5: 1 2 1 3 1 2 1

f(n) = najpierw całe f(n - 1), potem n, potem znowu całe f(n - 1).

WywołanieWypisuje
f(1)1
f(2)f(1), 2, f(1) = 1 2 1
f(3)f(2), 3, f(2) = 1 2 1 3 1 2 1
na ekranie
1 2 1 3 1 2 1
Funkcja, która woła siebie więcej niż raz, to temat części 3 — zobaczysz tam całe drzewo wywołań.
