Co już umiemy

void odliczaj(int n) {    if (n == 0) return;    cout << n << " ";    odliczaj(n - 1);}
  1. Warunek stopu — najmniejszy przypadek, w którym funkcja nie woła siebie.
  2. Mniejszy problem — wywołanie z argumentem bliższym warunkowi stopu.
  3. Kod przed wywołaniem działa w drodze w dół, kod po — w drodze w górę.
  4. Każde wywołanie to osobna kopia funkcji na stosie, z własnymi zmiennymi.

W części 1 funkcje tylko wypisywały. Teraz napiszemy funkcje, które liczą wynik i oddają go przez return — bez ani jednej pętli.

return — przypomnienie

int podwoj(int x) {    return 2 * x;} int main() {    int a = podwoj(3);    cout << a + podwoj(10);}
na ekranie
26

return robi dwie rzeczy naraz:

  1. kończy funkcję — dalsze linijki już się nie wykonają,
  2. oddaje wynik tam, skąd funkcję wywołano.

Wywołanie podwoj(3) w programie „zamienia się” w liczbę 6, a podwoj(10) — w 20. Dlatego na ekranie jest 6 + 20 = 26.

Wywołanie w środku wyrażenia

int podwoj(int x) {    return 2 * x;} int main() {    cout << podwoj(podwoj(podwoj(1)));}
na ekranie
8

Gdy wywołanie stoi w środku innego wyrażenia, komputer musi najpierw policzyć to wywołanie, a dopiero potem resztę:

  1. podwoj(1) = 2
  2. podwoj(2) = 4
  3. podwoj(4) = 8
W rekurencji będzie dokładnie tak samo: w return n + suma(n - 1); funkcja musi poczekać na wynik suma(n - 1), zanim doda do niego n.

Problem: suma 1 + 2 + … + n

Chcemy policzyć sumę liczb od 1 do n — bez pętli. Popatrz na dwie sumy obok siebie:

51 + 2 + 3 + 4 + 5 = 15to jest suma(4) + 5!
61 + 2 + 3 + 4 + 5 + 6 = 21to jest suma(5) + 6

Każdą sumę da się zapisać przy pomocy mniejszej sumy. To jest dokładnie to, czego potrzebuje rekurencja.

Warunek stopu też coś zwraca

int suma(int n) {    if (n == 0) return 0;    return n + suma(n - 1);}

W funkcji void warunek stopu tylko kończył pracę. W funkcji int musi też oddać wynik — wynik dla najmniejszego przypadku.

  1. suma zera liczb to 0,
  2. iloczyn zera liczb (np. 0!) to 1,
  3. liczba jednocyfrowa ma 1 cyfrę.
Uwaga: Zły wynik w warunku stopu psuje wszystkie wyniki — bo każdy wynik jest z niego zbudowany.

Zaufaj rekurencji

Pisząc suma(n), załóż, że suma(n − 1) już działa i zwraca dobry wynik.

Nie trzeba w głowie schodzić do zera. Wystarczą dwie rzeczy:

  1. warunek stopu zwraca dobry wynik dla najmniejszego przypadku,
  2. krok robi dobry wynik dla n z dobrego wyniku dla n − 1.
Wtedy działa dla każdego n: suma(0) jest dobra, więc suma(1) jest dobra, więc suma(2) jest dobra, więc suma(3)… — jak domino, w którym każdy klocek przewraca następny.

05

Jak myśleć o funkcji rekurencyjnej?

1 · Co ma zwracać funkcja?
Opisz słowami, np. „suma(n) zwraca 1 + 2 + … + n”. To zdanie jest najważniejsze.
2 · Najmniejszy przypadek
Dla jakiego argumentu znam wynik od ręki? Ten wynik zwróć w warunku stopu.
3 · Załóż, że mniejsze działa
Wolno Ci użyć wyniku dla mniejszego argumentu, tak jakby ktoś już go policzył.
4 · Zbuduj wynik
Jak z wyniku dla mniejszego argumentu zrobić wynik dla n? To jest linijka z return.

Silnia

Silnia: n! = 1 · 2 · 3 · … · n, a 0! = 1. Na przykład 5! = 120.

nn!z poprzedniej
01z definicji
111 · 0!
222 · 1!
363 · 2!
4244 · 3!
51205 · 4!
long long silnia(int n) {    if (n == 0) return 1;    return n * silnia(n - 1);}
Ten sam schemat co suma, tylko zamiast + jest ·, a warunek stopu zwraca 1, a nie 0 (pomnożenie przez 0 wyzerowałoby wszystko!).

Potęga: aⁿ = a · aⁿ⁻¹

long long potega(long long a, int n) {    if (n == 0) return 1;    return a * potega(a, n - 1);}
potega(2, 5)
32
↓potega(2, 5) = 2 · potega(2, 4)
↓potega(2, 4) = 2 · potega(2, 3)
↓potega(2, 3) = 2 · potega(2, 2)
↓potega(2, 2) = 2 · potega(2, 1)
↓potega(2, 1) = 2 · potega(2, 0)
■potega(2, 0) = 1
↑= 2 · 1 = 2
↑= 2 · 2 = 4
↑= 8
↑= 16
↑= 32
Dwa parametry: a przekazujemy dalej bez zmian, maleje tylko n. (W części 6 policzymy potęgę dużo szybciej — dzieląc n na pół.)

Mnożenie bez mnożenia

a · b to a + a + … + a (b razy), czyli a · b = a + a · (b − 1).

long long razy(long long a, int b) {    if (b == 0) return 0;    return a + razy(a, b - 1);}

Ile cyfr ma liczba?

int ileCyfr(long long n) {    if (n < 10) return 1;    return 1 + ileCyfr(n / 10);}

Liczba ma o jedną cyfrę więcej niż ta sama liczba bez ostatniej cyfry (n / 10). A liczba jednocyfrowa ma 1 cyfrę.

WywołanieZwraca

ileCyfr(48)1 + ileCyfr(4) = 1 + 1 = 2
ileCyfr(4)4 < 10 → 1
Uwaga: Warunek n < 10, a nie n == 0! Z n == 0 → 0 liczba 0 miałaby zero cyfr, a ma jedną.

Funkcja rekurencyjna woła inną rekurencyjną

int sumaCyfr(long long n) {    if (n == 0) return 0;    return n % 10 + sumaCyfr(n / 10);} int pierwiastek(long long n) {    if (n < 10) return n;    return pierwiastek(sumaCyfr(n));}

Pierwiastek cyfrowy: sumuj cyfry, aż zostanie jedna cyfra. 9875 → 29 → 11 → 2.

↓pierwiastek(9875) → sumaCyfr = 29
↓pierwiastek(29) → sumaCyfr = 11
↓pierwiastek(11) → sumaCyfr = 2
■pierwiastek(2): 2 < 10 → 2
Problem nie musi maleć o 1. Wystarczy, że na pewno dojdziemy do warunku stopu — suma cyfr jest mniejsza od liczby (dla n ≥ 10).

NWD — algorytm Euklidesa

NWD(a, b) — największa liczba dzieląca i a, i b. Starożytny pomysł Euklidesa: NWD(a, b) = NWD(b, a % b), a NWD(a, 0) = a.

long long nwd(long long a, long long b) {    if (b == 0) return a;    return nwd(b, a % b);}

Pułapki (1/2)

  1. Brak return przed wywołaniem. n + suma(n - 1); bez słowa return liczy wynik i… wyrzuca go. Funkcja int bez return zwraca śmieci. Kompilator zwykle ostrzega — czytaj ostrzeżenia!
  2. Wywołanie, którego wynik się marnuje. suma(n - 1); return n; — wywołanie się wykona, ale jego wynik nigdzie nie trafia. Wynik trzeba użyć w wyrażeniu.
  3. Zły wynik w warunku stopu. Silnia z if (n == 0) return 0; zwraca zawsze 0 — bo każdy wynik to iloczyn z tym zerem.

Pułapki (2/2)

  1. Za mały typ. Suma, silnia, potęga szybko przekraczają int (ok. 2 · 10⁹). Gdy wynik może być duży — long long i w funkcji, i w parametrach.
  2. To samo wywołanie dwa razy. if (maks(i + 1) > a[i]) return maks(i + 1); liczy maks(i + 1) dwa razy, a każde z nich znowu dwa razy… Dla 30 elementów to już ponad miliard wywołań! Zapisz wynik w zmiennej: int m = maks(i + 1);.
  3. Warunek stopu tylko dla „ładnych” danych. Sprawdź najmniejsze przypadki: n = 0, n = 1, tablica z jednym elementem, słowo z jednej litery.
