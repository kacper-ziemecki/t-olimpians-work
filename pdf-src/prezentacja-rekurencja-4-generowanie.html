Pomysł: wypełniaj ciąg pozycja po pozycji

Funkcja generuj(i) zajmuje się pozycją i ciągu. Pozycje 0, …, i − 1 są już ustalone przez wcześniejsze wywołania.

Śledzimy n = 2

↓generuj(0): s[0] = 0
↓generuj(1): s[1] = 0
▸generuj(2): wypisuje 00
↓generuj(1): s[1] = 1
▸generuj(2): wypisuje 01
↓generuj(0): s[0] = 1
↓generuj(1): s[1] = 0
▸generuj(2): wypisuje 10
↓generuj(1): s[1] = 1
▸generuj(2): wypisuje 11

Zwróć uwagę: s[1] jest nadpisywane — najpierw 0, potem 1. Po powrocie do generuj(0) i wstawieniu s[0] = 1 stara wartość s[1] nie przeszkadza, bo generuj(1) i tak ją nadpisze.

Dzięki temu, że 0 próbujemy przed 1, ciągi wychodzą w kolejności alfabetycznej.

Podzbiór zbioru {1, …, n} to n decyzji: czy liczba 1 jest w podzbiorze? czy 2 jest? … Każda decyzja to 0 (nie bierz) albo 1 (bierz).

Wektor wybrane krok po kroku (n = 2)

↓nie bierz 1 → { }
▸nie bierz 2 → wypisz { }
↓push 2 → {2}, wypisz 2
↑pop → { }
↓push 1 → {1}
▸nie bierz 2 → wypisz 1
↓push 2 → {1, 2}, wypisz 1 2
↑pop → {1}
↑pop → { }

Po każdym push_back jest dokładnie jedno pop_back. Dzięki temu po powrocie z wywołania wektor wygląda tak samo jak przed nim.

Na końcu całej rekurencji wektor jest znowu pusty — wszystko, co dopisaliśmy, zostało cofnięte.

Schemat: wybierz → zejdź → cofnij

1 · wybierz
zmień stan: wybrane.push_back(x), uzyta[x] = true, s[i] = c…
2 · zejdź
wywołaj rekurencję dla następnej decyzji: generuj(i + 1)
3 · cofnij
przywróć stan sprzed wyboru: pop_back(), uzyta[x] = false
To jest serce backtrackingu (części 5). Każdą zmianę wspólnego stanu trzeba po powrocie odwrócić.
Wyjątek: gdy stan jest parametrem (np. suma s w f(i + 1, s + a[i])), każde wywołanie ma własną kopię i niczego nie trzeba cofać.

Trzy wzorce rekurencji generującej

wypisz wszystkie
Funkcja void. W liściu (gdy decyzje są podjęte) — sprawdź i wypisz. Przejdzie całe drzewo.
znajdź jedno
Funkcja bool. W liściu zwróć true, gdy pasuje. Jeśli wywołanie zwróciło true — od razu zwróć true dalej, bez sprawdzania reszty drzewa.
policz
Funkcja int / long long. Liść zwraca 1 (pasuje) albo 0. Węzeł zwraca sumę wyników swoich dzieci.

Ten podział Striver omawia w filmie L7 („Print all / Print one / Count”). Zobaczmy wszystkie trzy na jednym zadaniu: podzbiory tablicy o sumie k.

Wzorzec 2: znajdź jeden (czy w ogóle się da?)

bool da(int i, int s) {    if (i == n) return s == k;    if (da(i + 1, s + a[i])) return true;    if (da(i + 1, s)) return true;    return false;}

Gdy którakolwiek gałąź zwróci true, przekazujemy true w górę i nie zaglądamy do pozostałych gałęzi.

Permutacje — kod

int n, perm[10];bool uzyta[10]; void permutuj(int i) {    if (i == n) {        for (int j = 0; j < n; j++) cout << perm[j] << " ";        cout << endl;        return;    }    for (int x = 1; x <= n; x++) {        if (uzyta[x]) continue;        uzyta[x] = true;        perm[i] = x;        permutuj(i + 1);        uzyta[x] = false;    }}
  1. if (uzyta[x]) continue; — liczba już stoi wcześniej, pomijamy ją,
  2. wybierz: zaznacz x jako użytą i wstaw na pozycję i,
  3. zejdź: permutuj(i + 1),
  4. cofnij: uzyta[x] = false — x znowu wolna dla innych gałęzi.

Druga metoda: zamiany (swap)

void permutuj(int i) {    if (i == n) { wypisz(); return; }    for (int j = i; j < n; j++) {        swap(a[i], a[j]);        permutuj(i + 1);        swap(a[i], a[j]);    }}

Na pozycję i wstawiamy po kolei każdy element z pozycji i, …, n − 1 — zamieniając go miejscami. Po powrocie zamieniamy z powrotem (cofnięcie wyboru).

Tę metodę Striver pokazuje w filmie L13. Działa bez tablicy uzyta[], ale permutacje nie wychodzą w kolejności leksykograficznej — gdy zadanie jej wymaga, użyj pierwszej metody.

Poprawne nawiasowania

Napis z n nawiasów „(” i n nawiasów „)” jest poprawny, gdy każdy nawias ma swoją parę. Dla n = 3: ((())), (()()), (())(), ()(()), ()()().

Dopisujemy po jednym nawiasie, ale tylko taki, który ma sens:

  1. „(” — gdy otworzyliśmy mniej niż n: otw < n
  2. „)” — gdy jest co zamykać: zam < otw

Dlaczego i > od?

Na jednym poziomie (w jednej pętli) z kilku równych liczb próbujemy tylko pierwszej — wyblakłe gałęzie to pominięte powtórki.

Ale głębiej druga dwójka wolno wziąć — stąd „2 2” i „1 2 2”. Warunek i > od pilnuje, żeby pomijać tylko powtórki w tej samej pętli, a nie pierwszy element pętli.
