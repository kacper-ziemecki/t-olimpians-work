Dziel i zwyciężaj

Podziel problem na dwie połowy, rozwiąż każdą rekurencyjnie, a potem połącz wyniki.
1 · podziel
Tablicę, przedział albo liczbę dzielimy na dwie (mniej więcej) równe części.
2 · rozwiąż
Każdą część rozwiązuje wywołanie rekurencyjne. Bardzo mała część to warunek stopu.
3 · połącz
Z wyników obu części budujemy wynik dla całości. Często to najciekawszy krok.
Przykład z życia: posortować stos 1000 klasówek? Podziel na dwa stosy po 500, daj je dwóm osobom do posortowania, a potem scal dwa posortowane stosy w jeden.

Po co dzielić na pół, a nie zmniejszać o 1?

Do tej pory problem malał o jeden: n → n − 1 → n − 2 → … Rekurencja miała n poziomów.

Gdy dzielimy na pół, problem maleje dwa razy na każdym poziomie: n → n / 2 → n / 4 → … → 1.

Liczba poziomów to tyle, ile razy da się podzielić n przez 2 — czyli log₂ n. Nawet dla miliarda to tylko 30 poziomów.

Minimum i maksimum — dzielimy tablicę

pair<int, int> minmaks(int l, int r) {    if (l == r) return {a[l], a[l]};    int s = (l + r) / 2;    auto L = minmaks(l, s);    auto R = minmaks(s + 1, r);    return {min(L.first, R.first),            max(L.second, R.second)};}
  1. stop: jeden element jest swoim minimum i maksimum,
  2. podziel: środek s = (l + r) / 2 — lewa połowa l…s, prawa s + 1…r,
  3. połącz: mniejsze z dwóch minimów, większe z dwóch maksimów.
Funkcja zwraca parę (pair) — dwie liczby naraz. L.first to minimum lewej połowy, L.second — maksimum.

Potęgowanie: zwykłe jest za wolne

z części 2 — n wywołań
long long potega(long long a, long long n) {    if (n == 0) return 1;    return a * potega(a, n - 1);}
Uwaga: Dla n = 10¹⁸ to 10¹⁸ wywołań — nie skończy się do końca świata (i dużo wcześniej zabraknie stosu).

Pomysł: a¹⁰⁰ = (a⁵⁰)². Wystarczy policzyć a⁵⁰ raz i podnieść do kwadratu. A a⁵⁰ = (a²⁵)², a a²⁵ = a · (a¹²)²…

Szybkie potęgowanie modulo m

long long m; long long potega(long long a, long long n) {    if (n == 0) return 1 % m;    long long p = potega(a, n / 2);    p = p * p % m;    if (n % 2 == 1) p = p * (a % m) % m;    return p;}

Wyniki potęg są gigantyczne, więc w zadaniach liczy się je modulo m — resztę z dzielenia przez m. Bierzemy resztę po każdym mnożeniu, żeby liczby nie urosły.

Uwaga: Linijka 5: potega(a, n / 2) wywołujemy jeden raz i zapisujemy w zmiennej. Napisanie potega(a, n/2) * potega(a, n/2) zrobiłoby z powrotem n wywołań!
Gdy m ≤ 10⁹, iloczyn dwóch reszt jest mniejszy niż 10¹⁸ — mieści się w long long.

Wyszukiwanie binarne — zgadnij liczbę

Gra: myślę o liczbie od 1 do 100, a Ty zgadujesz. Na każdą próbę mówię „więcej” albo „mniej”. Najlepiej pytać o środek — każda odpowiedź wyrzuca połowę możliwości.

Wystarczy 7 pytań: 100 → 50 → 25 → 13 → 7 → 4 → 2 → 1.

Tak samo szukamy liczby x w posortowanej tablicy: patrzymy na środkowy element.

  1. środek == x — znalezione,
  2. środek > x — x może być tylko w lewej połowie,
  3. środek < x — tylko w prawej.

int szukaj(int l, int r, int x) {    if (l > r) return -1;          // pusto: nie ma    int s = (l + r) / 2;    if (a[s] == x) return s;    if (a[s] > x) return szukaj(l, s - 1, x);    return szukaj(s + 1, r, x);}

Tylko jedno wywołanie rekurencyjne — do tej połowy, w której x może być. Druga połowa jest odrzucana w całości.

Sortowanie przez scalanie (merge sort)

  1. jeden element jest już posortowany — stop,
  2. podziel tablicę na dwie połowy,
  3. posortuj każdą połowę rekurencyjnie,
  4. scal dwie posortowane połowy.
Zaufaj rekurencji: zakładamy, że wywołania dla połówek już umieją sortować. Nam zostaje tylko scalić ich wyniki — a to umiemy.

Ten algorytm pokazuje Striver w filmie „Merge Sort” z playlisty — zobacz go po tej prezentacji.

Sortowanie przez scalanie — kod

int a[100000], pom[100000]; void sortuj(int l, int r) {    if (l >= r) return;    int s = (l + r) / 2;    sortuj(l, s);    sortuj(s + 1, r);    int i = l, j = s + 1, k = l;    while (i <= s || j <= r) {        if (j > r || (i <= s && a[i] <= a[j]))            pom[k++] = a[i++];        else            pom[k++] = a[j++];    }    for (int x = l; x <= r; x++) a[x] = pom[x];}

Wywołanie z main: sortuj(0, n - 1).

  1. linijka 4: fragment z 0 lub 1 elementem jest posortowany,
  2. linijki 6–7: posortuj połówki (zaufaj rekurencji!),
  3. linijki 8–14: scal połówki do pom,
  4. linijka 15: przepisz z powrotem do a.

Ile pracy wykonuje merge sort?

Spójrz na schemat scalania „w górę”: na każdym poziomie scalamy kawałki, które razem mają n elementów. To ok. n operacji na poziom.

Poziomów jest log₂ n. Razem: n · log₂ n operacji.

Dla n = 100 000 to ok. 1,7 miliona operacji — ułamek sekundy.
nn² (sortowanie „bąbelkowe”)n · log₂ n (merge sort)

Zliczanie inwersji — kod

long long sortuj(int l, int r) {    if (l >= r) return 0;    int s = (l + r) / 2;    long long w = sortuj(l, s) + sortuj(s + 1, r);    int i = l, j = s + 1, k = l;    while (i <= s || j <= r) {        if (j > r || (i <= s && a[i] <= a[j]))            pom[k++] = a[i++];        else {            w += s - i + 1;            pom[k++] = a[j++];        }    }    for (int x = l; x <= r; x++) a[x] = pom[x];    return w;}

To merge sort z jedną dodatkową linijką (10) i wynikiem zwracanym przez return.

  1. inwersje w lewej połowie + inwersje w prawej (linijka 4),
  2. plus inwersje „pomiędzy”, liczone przy scalaniu (linijka 10).
Uwaga: Przy remisie (a[i] == a[j]) bierz z lewej — równe liczby nie tworzą inwersji. Wynik może przekroczyć int.

Quicksort — inny sposób dzielenia

Merge sort dzieli „na ślepo” na pół, a cała praca jest przy łączeniu. Quicksort robi odwrotnie: cała praca jest przy dzieleniu.

  1. wybierz element osiowy — pivot,
  2. rozdziel elementy na mniejsze, równe i większe od pivota,
  3. posortuj rekurencyjnie mniejsze i większe,
  4. połącz: mniejsze, równe, większe — i gotowe.

Quickselect: k-ty najmniejszy element

int kty(vector<int> v, int k) {    int pivot = v[v.size() / 2];    vector<int> mniejsze, wieksze;    int rowne = 0;    for (int x : v) {        if (x < pivot) mniejsze.push_back(x);        else if (x > pivot) wieksze.push_back(x);        else rowne++;    }    if (k <= mniejsze.size()) return kty(mniejsze, k);    if (k <= mniejsze.size() + rowne) return pivot;    return kty(wieksze, k - mniejsze.size() - rowne);}

Nie musimy sortować wszystkiego, żeby znaleźć k-ty najmniejszy element. Po podziale wiemy, w której części on jest — i tylko tam szukamy dalej.

Najlepszy fragment — kod

long long najlepszy(int l, int r) {    if (l == r) return a[l];    int s = (l + r) / 2;    long long w = max(najlepszy(l, s), najlepszy(s + 1, r));    long long suma = 0, lewa = LLONG_MIN, prawa = LLONG_MIN;    for (int i = s; i >= l; i--) { suma += a[i]; lewa = max(lewa, suma); }    suma = 0;    for (int i = s + 1; i <= r; i++) { suma += a[i]; prawa = max(prawa, suma); }    return max(w, lewa + prawa);}
Na każdym poziomie rekurencji pętle przechodzą łącznie przez całą tablicę, a poziomów jest log n — razem O(n log n). (Istnieje też sprytniejszy sposób O(n) — algorytm Kadane; w kompendium: „Maksymalna suma na przedziale 1D”.)

Napis Fibonacciego: k-ta litera bez budowania napisu

S(1) = a, S(2) = b, S(n) = S(n − 1) + S(n − 2): b, ba, bab, babba, babbabab, … S(80) ma ponad 10¹⁶ liter — nie da się go zbudować.

Ale k-ta litera S(n) leży albo w części S(n − 1) (gdy k ≤ długość S(n − 1)), albo w części S(n − 2) — na pozycji k − długość S(n − 1). Schodzimy tylko w jedną część!

char litera(int n, long long k) {    if (n == 1) return 'a';    if (n == 2) return 'b';    if (k <= dl[n - 1]) return litera(n - 1, k);    return litera(n - 2, k - dl[n - 1]);}
dl[n] — długości napisów, policzone wcześniej pętlą: dl[n] = dl[n − 1] + dl[n − 2]. To znowu liczby Fibonacciego!

k-ta cyfra w drugiej połowie (długości 2p) to odwrócona cyfra z pozycji k − p.

int cyfra(long long k) {    if (k == 1) return 0;    long long p = 1;    while (2 * p < k) p *= 2;    return 1 - cyfra(k - p);}
Na przykład 6. cyfra: p = 4, więc to odwrócona 2. cyfra; 2. cyfra to odwrócona 1., czyli 1 − 0 = 1; zatem 6. cyfra = 1 − 1 = 0.
