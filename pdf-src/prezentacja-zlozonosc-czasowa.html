Ten sam wynik, zupełnie inny czas

Dwa programy liczą to samo: sumę 1 + 2 + 3 + … + n.

program A — pętla
long long n, suma = 0;cin >> n;for(long long i = 1; i <= n; i++){    suma += i;}cout << suma << endl;
program B — wzór
long long n;cin >> n;cout << n * (n + 1) / 2 << endl;

Dla n = 100 oba wypisują 5050.

Ile operacji w 1 sekundę?

Komputer wykonuje około 108 prostych operacji na sekundę.

Notacja dużego O

O( … ) mówi, jak szybko rośnie liczba operacji, gdy rośnie wejście.

Z notatek: notacja dużego O pozwala obliczyć, ile operacji maksymalnie wykona nasz program, zależnie od danych wejściowych.

Jak czytać?
O(n) czytamy „o od en”. W nawiasie piszemy przybliżoną liczbę operacji, używając n — rozmiaru wejścia.
Jak nazywać?
To, co jest w nawiasie, to złożoność czasowa programu. Np. „ten program ma złożoność O(n)”.

O(n) — jedna pętla do n

z notatek
for(int i = 0; i < n; i++){   // n razy → O(n)    cout << i << endl;        // O(1)}

Z notatek: ten for-loop wykona się n razy, czyli liczba powtórzeń zależy od inputu (konkretnie od „n”) → O(n).

Wnętrze pętli to O(1). Pętla powtarza je n razy: n · O(1) = O(n).

Wykres to prosta linia: dwa razy większe n → dwa razy więcej operacji.

Reguły liczenia złożoności

  1. Pojedyncze instrukcje (przypisanie, działanie, if, cin, cout jednej liczby) → O(1).
  2. Pętla, która obraca się k razy → k · (złożoność wnętrza).
  3. Części po kolei (jedna pod drugą) → dodajemy i zostawiamy największą.
  4. Pętle w sobie → mnożymy.
  5. Pomijamy stałe (3n → n) i mniejsze składniki (n² + n → n²).
  6. Pętla, w której n jest dzielone (przez 2, 10, …) → O(log n).

Po co pisać bruta?

1. Część punktów
Testy często są podzielone na grupy: np. n ≤ 1000 za 30 pkt i n ≤ 10⁶ za resztę. Wolny brut zdobywa punkty za małe testy.
2. Sprawdzanie wzorcówki
Na małych testach brut i wzorcówka muszą dać ten sam wynik. Jeśli się różnią — szukasz błędu.
3. Zrozumienie zadania
Pisząc bruta lepiej rozumiesz zadanie i łatwiej wpadasz na szybszy pomysł.
4. Spokój
Masz już jakieś punkty, zanim zaczniesz walczyć o 100.

Najczęstsze błędy

  1. Dodawanie zamiast mnożenia. Pętle w sobie się mnoży (n · n), a dodaje tylko te po kolei.
  2. „O(1) to jedna operacja”. Nie — to stała liczba operacji, niezależna od n (może być 100).
  3. Każdy for to O(n). for(int i = 0; i < 100; i++) to O(1), a pętla z i *= 2 to O(log n).
  4. Odejmowanie jak dzielenie. n -= 2 w pętli daje O(n), a n /= 2 — O(log n).
  5. Zgubiona druga zmienna. Pętla do m to O(m), nie O(n). O(n · m) to nie to samo co O(n²).
  6. Liczenie dla małego n. Złożoność sprawdzamy dla największego n z ograniczeń.
